# QEMU 全局架构概览

> **版本**: QEMU 11.0.50  
> **分析日期**: 2026-05-08  
> **重点架构**: AArch64 (ARM64) virt 机器  
> **源码根目录**: qemu/qemu  

---

## 1. 项目概况

QEMU 是一个通用的开源机器模拟器和虚拟化器，支持两种运行模式：

| 模式 | 入口文件 | 说明 |
|------|----------|------|
| **系统模拟** (System Emulation) | `system/main.c` | 模拟完整机器（CPU + 外设 + 固件），可配合 KVM/HVF 实现硬件加速 |
| **用户态模拟** (User-mode Emulation) | `linux-user/main.c` | 仅翻译系统调用和 CPU 指令，运行异构架构的用户态程序 |

### 1.1 源码规模

| 目录 | 文件数 | 说明 |
|------|--------|------|
| `hw/` | ~1,912 | 硬件设备模拟（最大子系统） |
| `include/` | ~1,384 | 头文件 |
| `target/` | ~912 | CPU 架构特定代码（ARM、x86、RISC-V 等） |
| `tests/` | ~3,550 | 测试用例 |
| `docs/` | ~373 | 官方文档（RST 格式） |

### 1.2 ARM64 构建配置

配置文件 `configs/targets/aarch64-softmmu.mak` 定义：

```makefile
TARGET_ARCH=aarch64
TARGET_BASE_ARCH=arm
TARGET_LONG_BITS=64
TARGET_NEED_FDT=y        # ARM64 依赖设备树
TARGET_XML_FILES=...      # GDB XML（aarch64-core.xml、arm-vfp-sysregs.xml 等）
```

构建系统（`meson.build`）中 ARM64 相关加速器映射：
- `kvm_targets` 包含 `aarch64-softmmu`
- `xen_targets` 包含 `aarch64-softmmu`
- HVF（macOS）、WHPX（Windows）也支持 `aarch64-softmmu`
- EDK2 固件目标包含 `aarch64-softmmu`

## 3. 核心框架

### 3.1 QOM（QEMU Object Model）— 对象模型

QOM 是 QEMU 的面向对象基础设施，所有设备、CPU、加速器、机器类型都基于 QOM 构建。

**核心数据结构** (`include/qom/object.h:123-162, 435-495`)：

```
TypeInfo                          # 类型注册信息
  ├─ name / parent                # 类型名 / 父类型名
  ├─ instance_size / class_size   # 实例 / 类大小
  ├─ instance_init / class_init   # 构造回调
  └─ interfaces[]                 # 实现的接口列表

ObjectClass                       # 类对象（共享）
  ├─ type                         # 指向 TypeImpl
  ├─ interfaces                   # 接口链表
  └─ properties                   # 类级属性

Object                            # 实例对象
  ├─ class                        # 指向 ObjectClass
  ├─ properties                   # 实例属性
  ├─ ref / parent                 # 引用计数 / 父对象
  └─ free                         # 释放回调
```

**关键 API** (`qom/object.c`)：

| 函数 | 位置 | 说明 |
|------|------|------|
| `type_register_static()` | object.c:103-182 | 注册 TypeInfo 到全局类型表 |
| `object_new()` | object.c:690-780 | 按类型名创建对象实例 |
| `object_initialize()` | — | 就地初始化（嵌入式对象） |
| `object_property_add_child()` | object.c:1786 | 建立父子对象关系 |

**类型继承关系（ARM64 相关）**：

```
Object
  └─ DeviceState
       ├─ SysBusDevice        # 系统总线设备（UART、RTC、GIC 等）
       ├─ PCIDevice           # PCI/PCIe 设备
       └─ CPUState
            └─ ARMCPU         # ARM64 CPU
  └─ MachineState
       └─ VirtMachineState    # ARM64 virt 机器
  └─ AccelState
       ├─ KVMState            # KVM 加速器
       └─ TCGState            # TCG 翻译加速器
```

> **官方文档**: `docs/devel/qom.rst` 对 QOM 的基本概念有详细说明。  
> **佐证 commit**: `150072398f` 将兼容属性 API 限制为仅系统模拟可用，体现了 QOM 的模块化演进。

### 3.2 QAPI — 管理接口框架

QAPI 是 QEMU 的管理协议（QMP）接口自动生成框架，通过 JSON Schema 定义接口，
自动生成类型、序列化/反序列化、命令处理代码。

**Schema 入口**: `qapi/qapi-schema.json:28-78`

包含的子模块：

```
error, run-state, machine, qom, qdev,     # 核心
block-core, block, char,                    # 存储/字符设备
migration, net, ui,                         # 迁移/网络/UI
accelerator, ...                            # 加速器
```

**代码生成** (`qapi/meson.build`)：

| 生成文件 | 用途 |
|----------|------|
| `qapi-types-*.c/h` | C 类型定义 |
| `qapi-visit-*.c/h` | 序列化访问器 |
| `qapi-commands-*.c/h` | QMP 命令处理函数 |
| `qapi-events-*.c/h` | 事件发射函数 |
| `qapi-introspect.*` | 自省元数据 |

> **官方文档**: `docs/interop/qmp-spec.rst` 描述了 QMP JSON 协议格式。

## 4. 加速器架构

QEMU 通过抽象的 `AccelClass` 支持多种 CPU 虚拟化后端。

### 4.1 加速器选择

`accel/accel-common.c:18-136` 中 `accel_find()` 根据 `-accel` 参数匹配加速器类型，
`accel_init_interfaces()` 安装 CPU/操作接口。

### 4.2 KVM 加速器

| 组件 | 位置 | 说明 |
|------|------|------|
| `KVMState` | kvm-all.c:86-107 | 全局加速器状态 |
| `KVMMemoryListener` | kvm-all.c | 内存插槽管理，同步 Guest 物理内存到 KVM |
| `kvm_cpu_exec()` | kvm-all.c | vCPU 执行循环：`ioctl(KVM_RUN)` → 处理 VM Exit |
| MMIO 处理 | `case KVM_EXIT_MMIO:` | KVM Exit 到用户态，调用 `address_space_rw()` 分发到设备 |

**ARM64 KVM 特性**（近期 commit）：
- `37863fff59` — HVF vGIC 默认启用（virt-11.1+）
- `2a3c965516` — HVF vGIC 基础设施变更
- `6f8f25614d` — 嵌套虚拟化（Nested Virtualization）支持

### 4.3 TCG 加速器（动态二进制翻译）

| 组件 | 位置 | 说明 |
|------|------|------|

TCG 直接通过内存 API / MMU TLB 慢速路径最终调用 `memory_region_dispatch_read/write()`。

## 5. 内存子系统

### 5.1 核心抽象

```
AddressSpace                      # 地址空间（如 address_space_memory）
  └─ MemoryRegion (树状)          # 内存区域
       ├─ RAM 区域               # 直接映射的客户机物理内存
       ├─ MMIO 区域              # 设备寄存器（关联 MemoryRegionOps）
       ├─ Alias 区域             # 指向其他区域的别名/窗口
       └─ Container 区域         # 纯容器，组织子区域
```

**关键结构** (`include/system/memory.h:300-360, 816-867`)：

| 结构体 | 说明 |
|--------|------|
| `MemoryRegion` | 内存区域：大小、偏移、ops、opaque、子区域链表 |
| `MemoryRegionOps` | 设备回调：`.read`、`.write`、`.read_with_attrs`、`.valid`、`.impl` |
| `AddressSpace` | 地址空间：根 MemoryRegion + FlatView 缓存 |

**全局地址空间** (`include/system/address-spaces.h:25-33`)：
- `get_system_memory()` → 系统物理内存根区域
- `get_system_io()` → I/O 端口空间（x86 主要使用，ARM 极少用）

### 5.2 MMIO 分发路径

```
Guest 访问设备寄存器
  │
  ├─ [KVM 路径] VM Exit(KVM_EXIT_MMIO)
  │    └─ address_space_rw(&address_space_memory, addr, ...)
  │
  └─ [TCG 路径] MMU/TLB 慢速路径
       └─ address_space_read/write()
            │
            └─ memory_region_dispatch_read/write()  [memory.c:1444-1530]
                 ├─ 解析别名、验证访问大小
                 ├─ 调整字节序（大/小端转换）
                 └─ 调用 ops->read / ops->write
                      └─ 设备处理函数（如 pl011_read）
```

> **官方文档**: `docs/devel/memory.rst` 详细描述了 MemoryRegion/AddressSpace 模型。

## 6. 中断子系统（ARM64 GICv3）

### 6.1 中断层级

```
设备（SPI/PPI/SGI/LPI）
  │  qemu_set_irq()
  ▼
GICv3 Distributor (GICD)          [hw/intc/arm_gicv3.c]
  │  gicd_int_pending()
  │  irqbetter() 优先级比较
  ▼
GICv3 Redistributor (GICR)       [hw/intc/arm_gicv3.c]
  │  gicr_int_pending()
  │  gicv3_redist_update()
  ▼
GICv3 CPU Interface (GICC)
  │  gicv3_cpuif_update()
  ▼
ARMCPU GPIO 线
  ARM_CPU_IRQ / ARM_CPU_FIQ / ARM_CPU_VIRQ / ARM_CPU_VFIQ
```

### 6.2 ITS（Interrupt Translation Service）

`hw/intc/arm_gicv3_its.c` 实现 MSI/LPI 翻译：
- 使用 `address_space_ldq_le/stq_le` 访问 Guest 内存中的翻译表
- 通过 `dma_as` 执行 DMA 地址空间访问

**IRQ 基础设施** (`include/hw/core/irq.h:8-19, 44-97`)：
- `IRQState` — 中断线状态
- `qemu_irq` — 指向 IRQState 的指针
- `qemu_set_irq()` — 触发中断
- `qemu_allocate_irqs()` / `qemu_free_irqs()` — 分配/释放

## 7. 设备模型框架

### 7.1 核心结构

**DeviceState / DeviceClass** (`include/hw/core/qdev.h:222-405`)：

```
DeviceClass                       # 设备类（共享行为）
  ├─ realize / unrealize          # 设备实现/释放回调
  ├─ legacy_reset                 # 传统复位回调（通过 Resettable 接口实现三阶段复位）
  ├─ props[]                      # 设备属性定义
  ├─ vmsd                         # 迁移状态描述
  └─ bus_type                     # 所属总线类型

DeviceState                       # 设备实例
  ├─ parent_bus                   # 所在的总线
  ├─ realized                     # 是否已实现
  ├─ hotplugged                   # 是否热插拔
  └─ 属性值                      # 运行时属性
```

### 7.2 设备生命周期

```
type_register_static()  →  注册设备类型到 QOM
object_new()            →  分配实例，调用 instance_init
qdev_realize()          →  调用 DeviceClass.realize，连接总线
  [设备运行]
qdev_unrealize()        →  调用 DeviceClass.unrealize，清理
```

> **佐证**: `hw/core/qdev.c:265-292` 包含 `qdev_realize()` 和 `qdev_realize_and_unref()` 实现。  
> **官方文档**: `docs/system/device-emulation.rst` 描述了前端/后端/总线模型。

### 7.3 总线层级

| 总线类型 | 头文件 | 用途 |
|---------|--------|------|
| `SysBusDevice` | `include/hw/core/sysbus.h` | ARM 主总线（MMIO + IRQ） |
| `PCIDevice` | `include/hw/pci/pci.h` | PCIe 设备 |
| `VirtIODevice` | — | virtio 传输（mmio/pci） |

**SysBus 关键 API** (`hw/core/sysbus.c:83-249`)：
- `sysbus_init_mmio()` — 注册 MMIO 区域
- `sysbus_mmio_map()` — 映射 MMIO 到系统内存
- `sysbus_connect_irq()` — 连接设备 IRQ 到 GIC
