## 2. 整体架构概览

QEMU 的事件循环是一个 **多层次、可嵌套** 的架构：

```
┌─────────────────────────────────────────────────────────────┐
│                      用户空间 QEMU 进程                       │
├──────────────────────┬──────────────────────────────────────┤
│    Main Thread       │       IOThread(s)                    │
│  ┌────────────────┐  │  ┌────────────────┐                  │
│  │ GMainContext   │  │  │ AioContext     │                  │
│  │  ┌──────────┐  │  │  │  ┌──────────┐  │                  │
│  │  │AioContext│  │  │  │  │ aio_poll()│  │                  │
│  │  │(GSource) │  │  │  │  │    ↓      │  │                  │
│  │  └──────────┘  │  │  │  │ BH/Timer  │  │                  │
│  │  ┌──────────┐  │  │  │  │ FD/Event  │  │                  │
│  │  │IOHandler │  │  │  │  │ Coroutine │  │                  │
│  │  │(GSource) │  │  │  │  └──────────┘  │                  │
│  │  └──────────┘  │  │  └────────────────┘                  │
│  └────────────────┘  │                                      │
├──────────────────────┴──────────────────────────────────────┤
│  FD 监控后端: ppoll ← epoll ← io_uring (逐级升级)           │
├─────────────────────────────────────────────────────────────┤
│  内核: poll/epoll/io_uring 系统调用                          │
└─────────────────────────────────────────────────────────────┘
```

**核心设计原则**：
1. **AioContext 是事件循环的最小单元** — 每个 AioContext 管理自己的 fd handler、BH、定时器和协程
2. **主线程通过 GMainContext 桥接** — AioContext 作为 GSource 挂载到 GLib 主循环
3. **IOThread 直接调用 aio_poll()** — 绕过 GLib 获得更高性能
4. **三级 fd 监控后端** — ppoll → epoll → io_uring，根据 fd 数量和配置自动升级

## 3. AioContext 核心数据结构

`AioContext` 是事件循环的核心容器，继承自 GLib 的 `GSource`：

```c
// aio.h:201-339
struct AioContext {
    GSource source;                    // GLib GSource 基类

    /* 线程安全 */
    QemuRecMutex lock;                 // 递归互斥锁
    struct BdrvGraphRWlock *bdrv_graph; // 块层图读写锁

    /* FD Handler 管理 */
    AioHandlerList aio_handlers;       // 注册的 fd handler 链表
    AioHandlerList deleted_aio_handlers; // 待删除的 handler
    AioHandlerList poll_aio_handlers;  // 参与用户态轮询的 handler
    QemuLockCnt list_lock;             // handler 列表保护锁

    /* 通知机制 */
    uint32_t notify_me;                // 原子变量，控制 eventfd 通知
    bool notified;                     // 避免重复 eventfd 读取
    EventNotifier notifier;            // eventfd 用于跨线程唤醒

    /* Bottom Half */
    BHList bh_list;                    // 待处理 BH 链表
    QSIMPLEQ_HEAD(, BHListSlice) bh_slice_list; // 嵌套 BH 调度

    /* 协程调度 */
    QSLIST_HEAD(, Coroutine) scheduled_coroutines; // 待执行协程
    QEMUBH *co_schedule_bh;            // 协程调度 BH

    /* 线程池 */
    int thread_pool_min;
    int thread_pool_max;
    struct ThreadPoolAio *thread_pool;

    /* Linux AIO / io_uring */
#ifdef CONFIG_LINUX_AIO
    struct LinuxAioState *linux_aio;
#endif
#ifdef CONFIG_LINUX_IO_URING
    struct io_uring fdmon_io_uring;
    AioHandlerSList submit_list;
    CqeHandlerSimpleQ cqe_handler_ready_list;
#endif

    /* 定时器 */
    QEMUTimerListGroup tlg;            // 每种时钟类型一个定时器列表

    /* 自适应轮询参数 */
    int poll_disable_cnt;              // 无 io_poll 的 handler 计数
    int64_t poll_ns;                   // 当前轮询时间窗口(ns)
    int64_t poll_max_ns;               // 最大轮询时间(ns)
    int64_t poll_grow;                 // 轮询窗口增长因子
    int64_t poll_shrink;               // 轮询窗口收缩因子
    int64_t poll_weight;               // 当前区间权重

    /* AIO 引擎参数 */
    int64_t aio_max_batch;             // 批处理请求上限

    /* epoll 状态 */
    bool poll_started;                 // 是否在轮询模式
    int epollfd;                       // epoll 文件描述符
    void *epollfd_tag;                 // GSource epollfd 标签
    const FDMonOps *fdmon_ops;         // fd 监控操作表

    bool initialized;                  // 初始化完成标志
};
```

**关键设计**：`AioContext` 同时是一个 `GSource`（通过继承），因此可以直接挂载到 GLib 的 `GMainContext` 中。`fdmon_ops` 函数指针表决定实际的 fd 监控实现。

## 4. AioContext 创建与生命周期

### 4.1 创建流程

```c
// async.c:552-627
AioContext *aio_context_new(Error **errp)
{
    // 1. 作为 GSource 分配（继承 GSource 头部）
    ctx = (AioContext *) g_source_new(&aio_source_funcs, sizeof(AioContext));

    // 2. 初始化 eventfd 通知器
    event_notifier_init(&ctx->notifier, false);

    // 3. 设置 fd 监控后端（ppoll/epoll/io_uring）
    aio_context_setup(ctx, errp);

    // 4. 初始化 handler 列表锁
    qemu_lockcnt_init(&ctx->list_lock);

    // 5. 创建协程调度 BH
    ctx->co_schedule_bh = aio_bh_new(ctx, co_schedule_bh_cb, ctx);

    // 6. 注册 eventfd 到 fd handler
    aio_set_event_notifier(ctx, &ctx->notifier,
                           aio_context_notifier_cb,
                           aio_context_notifier_poll,
                           aio_context_notifier_poll_ready);

    // 7. 初始化定时器组
    timerlistgroup_init(&ctx->tlg, aio_timerlist_notify, ctx);

    // 8. 注册到全局 AioContext 列表
    register_aiocontext(ctx);
    ctx->initialized = true;
}
```

### 4.2 引用计数

AioContext 通过 `GSource` 的引用计数管理生命周期：

```c
// async.c:714-721
aio_context_ref(ctx)   → g_source_ref(&ctx->source)
aio_context_unref(ctx) → g_source_unref(&ctx->source)  // 引用归零触发 finalize
```

### 4.3 销毁流程

`aio_ctx_finalize()`（async.c:370-420）在 GSource 引用归零时调用，释放所有 BH、handler、定时器和 fdmon 资源。

## 5. 主循环架构

### 5.1 初始化

```c
// main-loop.c:160-187
int qemu_init_main_loop(Error **errp)
{
    // 1. 初始化时钟系统
    qemu_init_clocks(qemu_timer_notify_cb);

    // 2. 初始化信号处理
    qemu_signal_init(errp);

    // 3. 创建主线程的 AioContext
    qemu_aio_context = aio_context_new(errp);
    qemu_set_current_aio_context(qemu_aio_context);

    // 4. 创建通知 BH（用于唤醒主循环）
    qemu_notify_bh = qemu_bh_new(notify_event_cb, NULL);

    // 5. 将 AioContext 作为 GSource 挂载到 GLib 默认 GMainContext
    src = aio_get_g_source(qemu_aio_context);
    g_source_attach(src, NULL);  // NULL = 默认 GMainContext

    // 6. 挂载 IO handler GSource
    src = iohandler_get_g_source();
    g_source_attach(src, NULL);
}
```

### 5.2 主循环入口

```c
// runstate.c:943-951
void qemu_main_loop(void)
{
    while (!main_loop_should_exit(&status)) {
        main_loop_wait(false);  // 非阻塞模式
    }
}
```

### 5.3 main_loop_wait 详解

```c
// main-loop.c:563-604
void main_loop_wait(int nonblocking)
{
    // 1. 重置 GPollFD 数组
    g_array_set_size(gpollfds, 0);

    // 2. 通知所有监听者填充 poll 事件
    notifier_list_notify(&main_loop_poll_notifiers, &mlpoll);

    // 3. 计算超时：取 mlpoll.timeout 与定时器截止时间的最小值
    timeout_ns = qemu_soonest_timeout(timeout_ns,
                     timerlistgroup_deadline_ns(&main_loop_tlg));

    // 4. 执行 OS 级别主循环等待
    ret = os_host_main_loop_wait(timeout_ns);
    //   → g_main_context_prepare/query/check/dispatch (GLib 集成)
    //   → qemu_poll_ns() 阻塞等待

    // 5. 通知监听者 poll 结果
    notifier_list_notify(&main_loop_poll_notifiers, &mlpoll);

    // 6. 运行所有定时器
    qemu_clock_run_all_timers();
}
```

**关键点**：主线程使用 GLib 的 `GMainContext` 作为事件循环框架，而 `AioContext` 作为 `GSource` 嵌入其中。这使得主线程同时处理 GLib 事件源和 QEMU 自身的 fd/BH/timer 事件。

## 6. GMainContext 集成机制

AioContext 通过实现 GSource 的四个回调函数与 GLib 集成：

```c
// async.c:425-430
static GSourceFuncs aio_source_funcs = {
    aio_ctx_prepare,    // 准备阶段：检查是否有待处理事件
    aio_ctx_check,      // 检查阶段：poll 后检查事件就绪状态
    aio_ctx_dispatch,   // 分发阶段：处理就绪事件
    aio_ctx_finalize    // 清理阶段：释放资源
};
```

### 6.1 prepare 回调

```c
// async.c:305-325
static gboolean aio_ctx_prepare(GSource *source, gint *timeout)
{
    // 设置 notify_me 位 0，表示 GSource 正在 prepare 阶段
    qatomic_set(&ctx->notify_me, qatomic_read(&ctx->notify_me) | 1);

    // 计算超时：基于 BH 和定时器
    *timeout = aio_compute_timeout(ctx) / SCALE_MS;

    // 如果有待处理 BH 或已收到通知，返回 TRUE（立即 dispatch）
    return aio_bh_poll(ctx) || *timeout == 0;
}
```

### 6.2 check 回调

```c
// async.c:329-355
static gboolean aio_ctx_check(GSource *source)
{
    // 清除 notify_me 位 0
    qatomic_set(&ctx->notify_me, qatomic_read(&ctx->notify_me) & ~1);

    // 检查 BH、fd 就绪状态
    return aio_bh_poll(ctx) || check_fd_handlers(ctx);
}
```

### 6.3 dispatch 回调

```c
// async.c:357-367
static gboolean aio_ctx_dispatch(GSource *source, ...)
{
    aio_dispatch(ctx);  // 统一分发入口
    return true;
}
```

## 7. aio_poll 核心循环

`aio_poll()` 是 IOThread 和直接事件循环的核心，位于 `aio-posix.c:652-758`：

```
aio_poll(ctx, blocking)
│
├─ 1. 断言：必须在 home thread 中调用
│     assert(in_aio_context_home_thread(ctx))
│
├─ 2. 获取 list_lock
│     qemu_lockcnt_inc(&ctx->list_lock)
│
├─ 3. 计算超时
│     timeout = blocking ? aio_compute_timeout(ctx) : 0
│
├─ 4. 尝试用户态轮询（如果 poll_max_ns > 0）
│     try_poll_mode(ctx, &ready_list, &timeout)
│     └─ run_poll_handlers(ctx, ..., max_ns, &timeout)
│        └─ 循环调用 run_poll_handlers_once()
│           └─ 遍历 poll_aio_handlers，调用 handler->io_poll()
│
├─ 5. 设置 notify_me（如果需要阻塞）
│     qatomic_set(&ctx->notify_me, +2)
│     smp_mb()  // 与 aio_notify() 配对
│     if (ctx->notified) timeout = 0  // 避免错过通知
│
├─ 6. 关闭轮询模式，调用 fdmon_ops->wait()
│     ctx->fdmon_ops->wait(ctx, &ready_list, timeout)
│     // → fdmon_poll_wait() / fdmon_epoll_wait() / fdmon_io_uring_wait()
│
├─ 7. 清除 notify_me，接受通知
│     qatomic_store_release(&ctx->notify_me, -2)
│     aio_notify_accept(ctx)
│
├─ 8. 分发就绪事件
│     ctx->fdmon_ops->dispatch(ctx)     // io_uring CQE 处理
│     aio_bh_poll(ctx)                  // BH 处理
│     aio_dispatch_ready_handlers(ctx, &ready_list, ...)  // fd handler
│     aio_free_deleted_handlers(ctx)    // 清理已删除 handler
│
├─ 9. 自适应轮询参数更新
│     update_handler_poll_times(ctx, block_ns, dispatch_ns)
│
├─ 10. 释放 list_lock，运行定时器
│      qemu_lockcnt_dec(&ctx->list_lock)
│      timerlistgroup_run_timers(&ctx->tlg)
│
└─ return progress
```

**关键设计**：`aio_poll()` 先尝试用户态忙轮询（零系统调用开销），只在轮询无果后才退化到内核阻塞等待。

## 8. 自适应轮询机制

自适应轮询是 QEMU 低延迟 I/O 的核心优化，通过动态调整轮询窗口平衡 CPU 占用和响应延迟。

### 8.1 轮询参数

| 参数 | 字段 | 说明 |
|------|------|------|
| 当前窗口 | `poll_ns` | 当前忙轮询时间窗口（纳秒） |
| 最大窗口 | `poll_max_ns` | 轮询窗口上限 |
| 增长因子 | `poll_grow` | 轮询有效果时增长倍数 |
| 收缩因子 | `poll_shrink` | 轮询无效果时缩减除数 |
| 权重 | `poll_weight` | 平滑计算权重 |

### 8.2 轮询循环

```c
// aio-posix.c:494-545
static bool run_poll_handlers(AioContext *ctx, ..., int64_t max_ns, ...)
{
    RCU_READ_LOCK_GUARD();  // 整个轮询作为 RCU 临界区

    start_time = qemu_clock_get_ns(QEMU_CLOCK_REALTIME);
    do {
        progress = run_poll_handlers_once(ctx, ...);  // 遍历所有 poll handler
        elapsed_time = now - start_time;
        max_ns = qemu_soonest_timeout(*timeout, max_ns);

        if (ctx->fdmon_ops->need_wait(ctx)) {
            if (fdmon_supports_polling(ctx)) {
                *timeout = 0;  // 保持轮询模式
            }
            break;
        }
    } while (elapsed_time < max_ns);  // 在时间窗口内持续轮询

    // 移除空闲的 poll handler
    remove_idle_poll_handlers(ctx, ...);
}
```

### 8.3 参数自适应

```c
// aio-posix.c:608-650
static void update_handler_poll_times(AioContext *ctx, int64_t block_ns, ...)
{
    // 基于每个 handler 的实际忙等时间 vs 阻塞时间
    // 使用加权移动平均平滑调整
    // poll_grow: 如果轮询有效果，增大 poll_ns
    // poll_shrink: 如果轮询无效果，减小 poll_ns
}
```

**性能影响**：对于 virtio-blk 等高频 I/O 设备，自适应轮询可将延迟从几十微秒降至几微秒（通过避免 epoll_wait 系统调用的上下文切换）。

## 9. FD 监控后端：ppoll

ppoll 是默认后端，适用于 fd 数量较少的场景。

```c
// fdmon-poll.c:12-99
static int fdmon_poll_wait(AioContext *ctx, AioHandlerList *ready_list,
                           int64_t timeout)
{
    // 1. 构建 GPollFD 数组（线程局部存储，避免每次分配）
    QLIST_FOREACH_RCU(node, &ctx->aio_handlers, node_rcu) {
        pollfds[npfd].fd = node->pfd.fd;
        pollfds[npfd].events = node->pfd.events;
    }

    // 2. 调用 qemu_poll_ns() → ppoll() 系统调用
    ret = qemu_poll_ns(pollfds, npfd, timeout);

    // 3. 将 revents 写回 handler，加入 ready_list
    // 4. 如果 fd 过多，尝试升级到 epoll
```

## 13. Bottom Half (BH) 机制

BH 是 QEMU 的 **延迟执行机制**，类似 Linux 内核的 tasklet/softirq。

### 13.1 数据结构

```c
// async.c:63-71
struct QEMUBH {
    AioContext *ctx;
    const char *name;
    QEMUBHFunc *cb;
    void *opaque;
    QSLIST_ENTRY(QEMUBH) next;
    unsigned flags;              // BH_PENDING | BH_SCHEDULED | BH_DELETED ...
    MemReentrancyGuard *reentrancy_guard;
};
```

### 13.2 调度（线程安全）

```c
// async.c:74-108
static void aio_bh_enqueue(QEMUBH *bh, unsigned new_flags)
{
    // 1. 原子设置 BH_PENDING 标志
    old_flags = qatomic_fetch_or(&bh->flags, BH_PENDING | new_flags);

    // 2. 如果之前未 PENDING，插入 ctx->bh_list（原子操作）
    if (!(old_flags & BH_PENDING)) {
        QSLIST_INSERT_HEAD_ATOMIC(&ctx->bh_list, bh, next);
    }

    // 3. 通知 AioContext（可能唤醒正在 poll 的线程）
    aio_notify(ctx);
}

// async.c:235-238
void qemu_bh_schedule(QEMUBH *bh)
{
    aio_bh_enqueue(bh, BH_SCHEDULED);
}
```

### 13.3 处理（仅在 home thread）

```c
// async.c:181-228
int aio_bh_poll(AioContext *ctx)
{
    // 1. 原子移动整个 bh_list 到本地 slice
    QSLIST_MOVE_ATOMIC(&slice.bh_list, &ctx->bh_list);

    // 2. 遍历所有 BH，调用回调
    while ((bh = aio_bh_dequeue(&s->bh_list, &flags))) {
        if ((flags & (BH_SCHEDULED | BH_DELETED)) == BH_SCHEDULED) {
            aio_bh_call(bh);  // 执行回调
        }
        if (flags & (BH_DELETED | BH_ONESHOT)) {
            g_free(bh);       // 清理一次性 BH
        }
    }
}
```

**设计要点**：BH 的 enqueue 是线程安全的（任何线程可调度），但执行只在 home thread 中进行。使用 `QSLIST_MOVE_ATOMIC` 批量获取 BH 列表，避免逐个加锁。

### 16.2 线程主循环

```c
// iothread.c:28-65
static void *iothread_run(void *opaque)
{
    rcu_register_thread();
    g_main_context_push_thread_default(iothread->worker_context);
    qemu_set_current_aio_context(iothread->ctx);
    qemu_sem_post(&iothread->init_done_sem);

    while (iothread->running) {
        // 核心：直接调用 aio_poll（比 GLib 更快）
        aio_poll(iothread->ctx, true);

        // 可选：运行 GMainContext（用于需要 GLib 事件源的场景）
        if (iothread->running && qatomic_read(&iothread->run_gcontext)) {

    rcu_unregister_thread();
}
```

- IOThread 优先使用 `aio_poll()` 而非 `g_main_loop_run()`，因为纯块层 IOThread 不需要 GLib
- `run_gcontext` 仅在需要 GLib 事件源（如某些 chardev 后端）时启用
- 性能注释明确说明：`aio_poll()` 比 `g_main_loop_run()` 更快

## 19. 协程池与复用

协程创建开销较大（需要分配栈空间），因此使用 **两级池** 机制：

```
┌────────────────────┐      ┌────────────────────┐
│  线程局部池         │ ←──→ │  全局池              │
│  (per-thread)      │      │  (shared)           │
│  ┌──────────────┐  │      │  ┌──────────────┐   │
│  │ Batch (≤64)  │  │      │  │ Batch Pool   │   │
│  │ co→co→co→... │  │      │  │ batch→batch→  │   │
│  └──────────────┘  │      │  └──────────────┘   │
└────────────────────┘      └────────────────────┘
```

```c
// qemu-coroutine.c:177-215
static Coroutine *coroutine_pool_get(void)
{
    co = coroutine_pool_get_local();     // 先查线程本地池
    if (!co) {
        coroutine_pool_refill_local();   // 从全局池补充
        co = coroutine_pool_get_local();
    }
    return co;
}

static void coroutine_pool_put(Coroutine *co)
{
    // 放回线程本地池
    // 如果本地池满（batch > COROUTINE_POOL_BATCH_MAX_SIZE），推送到全局池
    if (batch->size >= COROUTINE_POOL_BATCH_MAX_SIZE) {
        coroutine_pool_put_global(batch);
    }
    QSLIST_INSERT_HEAD(&batch->list, co, pool_next);
}
```

### 20.2 CoMutex

```c
// qemu-coroutine-lock.c:236-330
void qemu_co_mutex_lock(CoMutex *mutex)
{
    // 快速路径：原子 CAS 尝试获取
    if (qatomic_cmpxchg(&mutex->locked, 0, 1) == 0) {
        mutex->holder = self;
        return;  // 成功获取
    }

    // 慢速路径：加入等待队列并让出
    trace_qemu_co_mutex_lock_entry(mutex, self);
    push_bql_lock_order(mutex);
    QSIMPLEQ_INSERT_TAIL(&mutex->waiters, self, co_queue_next);
    mutex->waiters_count++;
    qemu_coroutine_yield();  // 等待持有者 unlock 时唤醒
}

void qemu_co_mutex_unlock(CoMutex *mutex)
{
    // 如果有等待者，唤醒队首
    next = QSIMPLEQ_FIRST(&mutex->waiters);
    if (next) {
        QSIMPLEQ_REMOVE_HEAD(&mutex->waiters, co_queue_next);
        aio_co_wake(next);
    }
    qatomic_set(&mutex->locked, 0);
}
```

```c
    // 3. 工作线程执行 func(arg)
    // 4. 完成后通过 BH 回调通知
}

// util/thread-pool.c:286-293
int coroutine_fn thread_pool_submit_co(ThreadPoolAio *pool,
    ThreadPoolFunc *func, void *arg)
{
    // 协程封装：提交后 yield，完成时 wake
    thread_pool_submit_aio(pool, func, arg, thread_pool_co_cb, ...);
    qemu_coroutine_yield();
}

// util/thread-pool.c:278-284
static void thread_pool_co_cb(void *opaque, int ret)
{
    aio_co_wake(co);  // 唤醒等待的协程
}
```
