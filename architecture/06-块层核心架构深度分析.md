# QEMU 块层核心架构深度分析

## 1. 概述

本文深度分析 QEMU 11.0.50 块层（Block Layer）的核心架构，包括 BlockDriverState（BDS）数据结构、BlockBackend 前端接口、BlockDriver 驱动插件系统、BDS 树形拓扑、I/O 路径、协程集成和设备管理。块层是 QEMU 最复杂的子系统之一，它在虚拟设备和主机存储之间提供了灵活的多层抽象。

**关键源文件：**
- `include/block/block_int-common.h` — BlockDriver/BDS/BdrvChild 核心定义（~1300行）
- `block/block-backend.c` — BlockBackend 前端实现（~2500行）
- `block/io.c` — 核心 I/O 路径（~3600行）
- `block.c` — BDS 图管理、打开/关闭/附加（~8000行）
- `blockdev.c` — QMP/HMP 设备管理（~3700行）

## 2. 架构总览

### 2.1 分层结构

```
┌────────────────────────┐
│   虚拟设备              │  virtio-blk / IDE / SCSI / NVMe
│   (DeviceState)        │
└──────────┬─────────────┘
           │ dev_ops
┌──────────┴─────────────┐
│   BlockBackend (blk)   │  前端接口：I/O 统计、错误策略、权限
│   block-backend.c      │
└──────────┬─────────────┘
           │ blk->root (BdrvChild)
┌──────────┴─────────────┐
│   格式层 BDS            │  qcow2 / vmdk / qed / raw-format
│   (BlockDriverState)   │  数据格式解析、元数据管理
└──────────┬─────────────┘
           │ bs->file (BdrvChild)
┌──────────┴─────────────┐
│   协议层 BDS            │  file-posix / nbd / curl / ssh / iscsi
│   (BlockDriverState)   │  主机存储访问
└──────────┴─────────────┘
           │ fd / socket / ...
       ┌───┴───┐
       │ 主机   │
       │ 存储   │
       └───────┘
```

### 2.2 可选中间层

```
blk → [throttle-group] → [filter] → qcow2 → [backing: qcow2] → raw → file-posix
                                        │
                                        └─→ bs->file → raw → file-posix
```

## 4. I/O 路径

### 4.1 读 I/O 完整路径

```
1. virtio-blk 收到 Guest 请求
   │
2. blk_co_preadv()                    [block-backend.c:1375-1400]
   │  检查权限、对齐、in_flight++
   │
3. bdrv_co_preadv_part()              [io.c 内部]
   │  请求对齐、bounce buffer
   │  COR (copy-on-read) 检查
   │
4. bdrv_driver_preadv()               [io.c:974-1040]
   │  优先级: bdrv_co_preadv_part > bdrv_co_preadv > bdrv_aio_preadv > bdrv_co_readv
   │
5. drv->bdrv_co_preadv_part()         [驱动层]
   │  例: qcow2_co_preadv_part()
   │    → qcow2_get_host_offset() 查 L1/L2 表
   │    → 读底层 bs->file
   │    → 可能需要解密/解压
   │
6. 递归: bdrv_driver_preadv() 在 file 协议层
   │  例: raw_co_preadv() → pread()/io_uring
   │
7. 返回数据 → Guest
```

### 4.2 写 I/O 完整路径

```
1. blk_co_pwritev()                   [block-backend.c:1468-1474]
   │
2. bdrv_co_pwritev_part()             [io.c 内部]
   │  对齐检查、write-through 处理
   │
3. bdrv_driver_pwritev()              [io.c:1043-1127]
   │
4. drv->bdrv_co_pwritev_part()        [驱动层]
   │  例: qcow2_co_pwritev_part()
   │    → qcow2_alloc_host_offset() 分配簇
   │    → 更新 L2 表
   │    → 可能加密/压缩
   │    → 写底层 bs->file
   │
5. 协议层写入
```

### 4.3 驱动回调分发

```c
// io.c:974-1040 — bdrv_driver_preadv()
// 按优先级尝试驱动回调:
if (drv->bdrv_co_preadv_part) {        // 最优：支持 partial qiov
    return drv->bdrv_co_preadv_part(...);
}
if (drv->bdrv_co_preadv) {             // 次选：完整 qiov
    return drv->bdrv_co_preadv(...);
}
if (drv->bdrv_aio_preadv) {            // 兼容：AIO 回调
    acb = drv->bdrv_aio_preadv(...);   // 转换为协程等待
    qemu_coroutine_yield();
}
// 最后：旧式 sector 接口
drv->bdrv_co_readv(bs, sector_num, nb_sectors, qiov);
```

## 5. BDS 树管理

### 5.1 打开流程

```c
// block.c:4281-4288 — bdrv_open()
// 1. 解析选项（QDict）
// 2. 探测格式：bdrv_probe_all() (block.c:994-1012)
//    - qcow2_probe: magic == QCOW_MAGIC → 返回 100
//    - raw_probe: 始终返回 1（最低分，兜底）
// 3. 创建 BDS 节点
// 4. 调用 drv->bdrv_open()
// 5. 打开 backing 链（如果有）
```

### 5.2 典型 BDS 拓扑

```
场景1: qcow2 + backing

  BlockBackend "disk0"
       │ root
  BDS [qcow2] "node0"          ← 格式层
       ├── file → BDS [raw] → BDS [file-posix] "/data/disk.qcow2"
       └── backing → BDS [qcow2] "node1"  ← backing 格式层
                      └── file → BDS [raw] → BDS [file-posix] "/data/base.qcow2"

场景2: raw 磁盘

  BlockBackend "disk0"
       │ root
  BDS [raw-format]              ← 格式层（透传）
       └── file → BDS [file-posix] "/dev/sda"

场景3: NBD 远程磁盘

  BlockBackend "disk0"
       │ root
  BDS [raw-format]
       └── file → BDS [nbd] "nbd://server:10809/export"
```

## 6. 协程与 AioContext

### 6.1 协程 I/O 模型

```
所有块 I/O 在协程中执行:

主线程                         I/O 协程
  │                              │
  │ blk_co_preadv()              │
  │──创建协程──────────────→     │ bdrv_co_preadv_part()
  │                              │   bdrv_driver_preadv()
  │                              │     drv->bdrv_co_preadv_part()
  │                              │       qemu_coroutine_yield() ←─ 等待底层 I/O
  │ ←─ 事件循环处理其他工作 ─→   │
  │                              │ ←─ I/O 完成，恢复协程
  │ ←──协程完成，返回结果 ──     │
  │                              │
```

### 6.2 AioContext 关联


## 11. 小结

| 维度 | 实现 |
|------|------|
| **BlockBackend** | 设备前端（权限/统计/错误策略），dev→blk→root→BDS |
| **BlockDriverState** | 核心节点（drv/opaque/file/backing/children/parents） |
| **BlockDriver** | 驱动插件（open/close/preadv/pwritev/flush/block_status） |
| **BDS 树** | children/backing/file 父子关系，支持 COW、过滤器、多级嵌套 |
| **I/O 路径** | blk_co_preadv → bdrv_driver_preadv → drv 回调 → 递归到协议层 |
| **协程** | 所有 I/O 在协程中，AioContext 控制执行线程 |
| **驱动注册** | block_init() 构造函数 → bdrv_register() 全局链表 |
| **格式探测** | bdrv_probe_all() 读头→评分→选最高分驱动 |
| **设备管理** | QMP blockdev-add / -drive 命令行 / blockdev_init() |
