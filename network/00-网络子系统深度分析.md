## 1. 网络子系统总体架构

QEMU 网络子系统采用 **前端-后端分离** 的分层架构：

```
┌─────────────────────────────────────────────────┐
│                    Guest OS                      │
│         virtio-net / e1000 / rtl8139 ...        │
├─────────────────────────────────────────────────┤
│              设备模型层 (hw/net/)                 │
│    virtio-net.c / e1000.c / rtl8139.c ...       │
├─────────────────────────────────────────────────┤
│         ┌── NetFilterState 过滤器链 ──┐          │
│         │  filter-mirror / filter-dump │          │
│         └─────────────────────────────┘          │
├─────────────────────────────────────────────────┤
│          网络核心层 (net/net.c)                   │
│   NetClientState ←peer→ NetClientState           │
│   NetQueue 队列    qemu_send_packet()            │
├─────────────────────────────────────────────────┤
│              网络后端层 (net/*.c)                  │
│   TAP / SLIRP / Socket / vhost-net / ...        │
├─────────────────────────────────────────────────┤
│               Host OS / Hardware                 │
└─────────────────────────────────────────────────┘
```

核心设计原则：
- 每个网络连接由**一对 NetClientState** 组成，通过 `peer` 指针互联
- **前端**（NIC 设备）和**后端**（TAP/SLIRP 等）各持有一个 NetClientState
- 发送方调用 `qemu_send_packet()` → 经过滤器链 → 到达 peer 的 `receive()` 回调
- 全局 `net_clients` 链表管理所有 NetClientState 实例

## 2. 核心数据结构

网络子系统的核心数据结构定义在 `include/net/net.h` 中：

```
NetClientInfo (驱动操作表)        NICState (网卡封装)
    ↓ info指针                      ↓ 持有ncs数组
NetClientState ←──peer──→ NetClientState
    ↑                           ↑
 (前端/设备侧)              (后端/主机侧)
    │                           │
    ├─ incoming_queue (NetQueue)  ├─ incoming_queue
    ├─ filters (过滤器链)         └─ ...
    └─ ...
```

## 3. NetClientInfo — 驱动操作表

```c
// include/net/net.h:86-113

    HasVnetHdr *has_vnet_hdr;      // vnet 头支持
    HasVnetHdrLen *has_vnet_hdr_len;
    SetOffload *set_offload;       // 设置卸载特性
    SetVnetHdrLen *set_vnet_hdr_len;
    SetVnetLE *set_vnet_le;        // 设置小端
    SetVnetBE *set_vnet_be;        // 设置大端

} NetClientInfo;
```

这是一个**虚函数表**（vtable），每种网络后端都定义自己的 NetClientInfo 实例。最核心的回调是：
- `receive` / `receive_iov` — 接收数据包
- `can_receive` — 流控检查
- `cleanup` — 资源清理

## 4. NetClientState — 网络客户端状态

```c
// include/net/net.h:115-134
struct NetClientState {
    NetClientInfo *info;           // 驱动操作表指针
    int link_down;                 // 链路是否断开
    QTAILQ_ENTRY(NetClientState) next;  // 全局链表节点
    NetClientState *peer;          // 对等端指针（前端↔后端）
    NetQueue *incoming_queue;      // 入站队列
    char *model;                   // 设备模型名（如 "virtio-net-pci"）
    char *name;                    // 实例名（如 "net0"）
    char info_str[256];            // 描述字符串
    unsigned receive_disabled : 1; // 接收禁用标志（流控）
    NetClientDestructor *destructor;
    unsigned int queue_index;      // 多队列索引
    unsigned rxfilter_notify_enabled:1;
    int vring_enable;              // vring 启用状态
    int vnet_hdr_len;              // vnet 头长度
    bool is_netdev;                // 是否为 -netdev 创建
    bool do_not_pad;               // 不填充到最小以太帧长度
    bool is_datapath;              // 是否为数据面
    QTAILQ_HEAD(, NetFilterState) filters;  // 过滤器链
};
```

关键字段说明：
- **`peer`** — 这是网络子系统最核心的连接机制。前端的 peer 指向后端，后端的 peer 指向前端
- **`incoming_queue`** — 每个 NetClientState 都有自己的入站 NetQueue，用于缓冲待处理的数据包
- **`receive_disabled`** — 当对端 `receive()` 返回 0 时设置，表示对端暂时无法接收
- **`filters`** — 挂载在此客户端上的过滤器链表

## 5. NICState — 网卡封装

```c
// include/net/net.h:138-144
typedef struct NICState {
    NetClientState *ncs;           // NetClientState 数组（多队列时有多个）
    NICConf *conf;                 // NIC 配置（MAC 地址等）
    MemReentrancyGuard *reentrancy_guard;  // 重入保护
    void *opaque;                  // 设备私有数据（指向 VirtIONet 等）
    bool peer_deleted;             // peer 是否已删除
} NICState;
```

NICState 是设备侧的封装层，一个 NIC 可以拥有多个 NetClientState（多队列场景）。设备模型通过 `qemu_get_nic_opaque(nc)` 获取设备私有数据。

## 6. 网络客户端初始化流程

### 6.1 总体流程

```
命令行: -netdev tap,id=net0 -device virtio-net-pci,netdev=net0

    ↓ 解析 -netdev
net_init_clients()
    → net_client_init1()                    // net/net.c:1320-1377
        → net_client_init_fun[TAP]()        // 分发到 net_init_tap()
            → qemu_new_net_client()         // net/net.c:293-307
                → qemu_net_client_setup()   // net/net.c:264-291
                    → QTAILQ_INSERT_TAIL(&net_clients, nc)  // 加入全局链表

    ↓ 解析 -device（设备实例化时）
virtio_net_device_realize()
    → qemu_new_nic()                        // net/net.c:325-352
        → qemu_net_client_setup()           // 创建前端 NetClientState
            → nc->peer = peer               // 与后端建立 peer 连接
```

### 6.2 qemu_net_client_setup — 客户端初始化核心

```c
// net/net.c:264-291
static void qemu_net_client_setup(NetClientState *nc,
                                  NetClientInfo *info, ...)
{
    nc->info = info;                           // 绑定驱动操作表
    nc->model = g_strdup(model);
    nc->name = assign_name(nc, name);
    nc->incoming_queue = qemu_new_net_queue(...);  // 创建入站队列
    nc->destructor = destructor;
    QTAILQ_INIT(&nc->filters);
    QTAILQ_INSERT_TAIL(&net_clients, nc, next);    // 加入全局链表

    // 建立 peer 连接
    if (peer) {
        nc->peer = peer;
        peer->peer = nc;                       // 双向连接
    }
}
```

### 6.3 qemu_new_nic — NIC 创建

```c
// net/net.c:325-352
NICState *qemu_new_nic(NetClientInfo *info, NICConf *conf,
                       const char *model, const char *name,
                       MemReentrancyGuard *reentrancy_guard,
                       void *opaque)
{
    // 分配 NICState + queue_pairs 个 NetClientState
    NICState *nic = g_malloc0(info->size + sizeof(NICState));
    nic->ncs = (void *)nic + info->size;
    nic->conf = conf;
    nic->opaque = opaque;
    nic->reentrancy_guard = reentrancy_guard;

    for (i = 0; i < queues; i++) {
        qemu_net_client_setup(&nic->ncs[i], info, ...);
    }
    return nic;
}
```

## 8. Peer 对等连接机制

Peer 是 QEMU 网络的核心连接模型。每个网络连接由两个 NetClientState 通过 `peer` 字段双向链接：

```
NetClientState (前端/NIC)          NetClientState (后端/TAP)
┌──────────────────┐              ┌──────────────────┐
│ info = virtio_info│              │ info = tap_info   │
│ peer ─────────────┼──────────→  │ peer ─────────────┼──→ (指回前端)
│ incoming_queue    │              │ incoming_queue    │
│ filters[]         │              │ filters[]         │
└──────────────────┘              └──────────────────┘
```

连接建立时机：
- `qemu_net_client_setup()` 中（`net/net.c:280-284`）：`nc->peer = peer; peer->peer = nc;`

断开处理：
- `qemu_free_net_client()` 中（`net/net.c:402-404`）：`peer->peer = NULL`

## 9. 数据包发送路径（TX）

Guest → Host 方向的完整数据包发送路径：

```
设备模型 (如 virtio-net)
    │
    ▼
qemu_sendv_packet_async()              // net/net.c:884-917
    │
    ▼
qemu_send_packet_async_with_flags()    // net/net.c:729-762
    │
    ├── filter_receive_iov(TX方向)      // net/net.c:747-755
    │       遍历 nc->filters 正向
    │       调用 qemu_netfilter_receive()
    │
    ▼
qemu_net_queue_send_iov()              // net/queue.c:221-244
    │
    ├── (队列为空且可发送) → 直接分发
    │       qemu_net_queue_deliver_iov()
    │
    └── (队列非空或不可发送) → 入队缓冲
            qemu_net_queue_append_iov()
```

### 9.1 qemu_send_packet_async — 发送入口

```c
// net/net.c:764-770
ssize_t qemu_send_packet_async(NetClientState *sender,
                               const uint8_t *buf, int size,
                               NetPacketSent *sent_cb)
{
    return qemu_send_packet_async_with_flags(sender, QEMU_NET_PACKET_FLAG_NONE,
                                             buf, size, sent_cb);
}
```

### 9.2 qemu_deliver_packet_iov — 最终分发

```c
// net/net.c:829-882
static ssize_t qemu_deliver_packet_iov(NetClientState *sender,
                                       unsigned flags,
                                       const struct iovec *iov,
                                       int iovcnt, void *opaque)
{
    NetClientState *nc = opaque;  // 目标（peer）

    // 链路检查
    if (nc->link_down) return iov_size(iov, iovcnt);
    if (nc->receive_disabled) return 0;

    // 重入保护
    if (nc->info->type == NET_CLIENT_DRIVER_NIC)
        reentrancy_guard->engaged_in_io = true;

    // 处理 RAW 标志：补充 vnet_hdr
    if ((flags & QEMU_NET_PACKET_FLAG_RAW) && nc->vnet_hdr_len) {
        // 在 iov 前插入空的 vnet_hdr
    }

    // 调用目标的 receive 回调
    if (nc->info->receive_iov)
        ret = nc->info->receive_iov(nc, iov, iovcnt);
    else
        ret = nc_sendv_compat(nc, iov, iovcnt, flags);

    if (ret == 0) nc->receive_disabled = 1;  // 流控
    return ret;
}
```

## 11. NetQueue — 网络队列层

NetQueue 是异步数据包缓冲机制，当接收方暂时无法处理时缓存数据包。

```c
// net/queue.c:43-61
struct NetPacket {
    QTAILQ_ENTRY(NetPacket) entry;
    NetClientState *sender;
    unsigned flags;
    int size;
    NetPacketSent *sent_cb;
    uint8_t data[];
};

struct NetQueue {
    void *opaque;
    uint32_t nq_maxlen;
    uint32_t nq_count;
    NetQueueDeliverFunc *deliver;
    QTAILQ_HEAD(, NetPacket) packets;    // 缓冲的数据包链表
    unsigned delivering : 1;
};
```

### 11.1 队列刷新

```c
// net/queue.c:262-293
void qemu_net_queue_flush(NetQueue *queue)
{
    // 遍历所有缓冲的数据包，尝试重新分发
    while (!QTAILQ_EMPTY(&queue->packets)) {
        packet = QTAILQ_FIRST(&queue->packets);
        ret = qemu_net_queue_deliver(queue, ...);
        if (ret == 0) break;  // 对端仍然无法接收，停止刷新
        QTAILQ_REMOVE(&queue->packets, packet, entry);
    }
}
```

当接收方重新就绪时（如 virtio-net 处理完上一批数据包），调用 `qemu_flush_queued_packets()` 触发队列刷新。

## 12. 网络过滤器框架

### 12.1 NetFilterState

```c
// include/net/filter.h:51-63
struct NetFilterState {
    Object parent_obj;
    char *netdev_id;               // 关联的 netdev 名称
    NetClientState *netdev;        // 关联的 NetClientState
    NetFilterDirection direction;  // TX / RX / ALL
    bool on;                       // 是否启用
    char *position;                // 位置
    bool insert_before_flag;
    QTAILQ_ENTRY(NetFilterState) next;  // 挂在 nc->filters 链表
};
```

### 12.2 过滤器拦截机制

```c
// net/net.c:647-677
static ssize_t filter_receive_iov(NetClientState *nc,
                                  NetFilterDirection direction,
                                  NetClientState *sender,
                                  unsigned flags,
                                  const struct iovec *iov, int iovcnt,
                                  NetPacketSent *sent_cb)
{
    NetFilterState *nf;
    // TX 方向：正向遍历过滤器链
    if (direction == NET_FILTER_DIRECTION_TX) {
        QTAILQ_FOREACH(nf, &nc->filters, next) {
            ret = qemu_netfilter_receive(nf, ...);
            if (ret) return ret;  // 被过滤器拦截
        }
    // RX 方向：反向遍历过滤器链
    } else {
        QTAILQ_FOREACH_REVERSE(nf, &nc->filters, next) {
            ret = qemu_netfilter_receive(nf, ...);
            if (ret) return ret;
        }
    }
    return 0;  // 未拦截，继续正常流程
}
```

设计要点：
- TX 方向正向遍历，RX 方向**反向**遍历，确保过滤器顺序对称
- 过滤器可以通过 `qemu_netfilter_pass_to_next()` 将包传递给下一个过滤器
- 常用过滤器：`filter-mirror`（镜像）、`filter-redirector`（重定向）、`filter-dump`（抓包）

## 13. TAP 后端实现

TAP 是最常用的高性能网络后端，通过 Linux TAP 设备将 Guest 数据包桥接到 Host 网络。

### 13.1 TAPState 结构

```c
// net/tap.c:70-86
typedef struct TAPState {
    NetClientState nc;             // 继承 NetClientState
    int fd;                        // TAP 设备文件描述符
    char down_script[1024];        // 关闭脚本
    char down_script_arg[128];     // 关闭脚本参数
    uint8_t buf[NET_BUFSIZE];      // 接收缓冲区
    bool read_poll;                // 是否监听读事件
    bool write_poll;               // 是否监听写事件
    bool using_vnet_hdr;           // 是否使用 vnet 头
    bool has_ufo;                  // UFO 支持
```

```c
static void tap_send(void *opaque)
{
    TAPState *s = opaque;
    // 循环从 TAP fd 读取数据包
    do {
        uint8_t *buf = s->buf;
        size = tap_read_packet(s->fd, ...);   // net/tap.c:182-186
        if (size <= 0) break;

        // 跳过 vnet_hdr（如果有）
        if (s->host_vnet_hdr_len && !s->using_vnet_hdr) {
            buf  += s->host_vnet_hdr_len;
            size -= s->host_vnet_hdr_len;
        }

        // 发往 peer（设备侧）
        size = qemu_send_packet_async(&s->nc, buf, size, tap_send_completed);
        if (size == 0) tap_read_poll(s, false);  // 流控暂停读取
    } while (size > 0);
}
```

## 22. virtio-net TX 路径

Guest 发送数据包的完整路径：

```
Guest 写入 TX virtqueue
    │
    ▼
virtio_net_handle_tx_bh()              // hw/net/virtio-net.c:2851-2875
    │ 或 virtio_net_handle_tx_timer()  // hw/net/virtio-net.c:2822-2849
    │
    ▼
virtio_net_flush_tx()                  // hw/net/virtio-net.c:2718-2818
    │
    │ 循环处理 virtqueue 中的元素：
    │   1. virtqueue_pop() 获取元素
    │   2. 提取 virtio_net_hdr
    │   3. qemu_sendv_packet_async()  发送到 peer
    │
    ▼
qemu_deliver_packet_iov()             // → 后端 receive()
    │
    ▼
tap_receive_iov() / slirp_receive()   // 写入 Host 网络
```

### 22.1 virtio_net_flush_tx — TX 核心

```c
// hw/net/virtio-net.c:2718-2818
static int32_t virtio_net_flush_tx(VirtIONetQueue *q)
{
    VirtIONet *n = q->n;
    int32_t num_packets = 0;

    for (;;) {
        // 1. 从 TX virtqueue 取出元素
        elem = virtqueue_pop(q->tx_vq, sizeof(VirtQueueElement));
        if (!elem) break;

        // 2. 提取 virtio_net_hdr（如果有）
        out_num = elem->out_num;
        out_sg = elem->out_sg;
        if (n->has_vnet_hdr) {
            // 跳过 hdr 或处理 offload 信息
        }

        // 3. 发送数据包
        ret = qemu_sendv_packet_async(qemu_get_subqueue(n->nic, queue_index),
                                      out_sg, out_num,
                                      virtio_net_tx_complete);

        // 4. 如果异步发送（返回0），记录 async_tx 等待完成
        if (ret == 0) {
            q->async_tx.elem = elem;
            return -EBUSY;
        }

        // 5. 完成处理
        virtqueue_push(q->tx_vq, elem, 0);
        num_packets++;

        // 6. burst 限制
        if (++num_packets >= n->tx_burst) break;
    }

    virtio_notify(vdev, q->tx_vq);  // 通知 Guest
    return num_packets;
}
```

### 22.2 TX 触发模式

virtio-net 支持两种 TX 触发方式：

- **BH 模式**（默认）— `virtio_net_handle_tx_bh()` 调度 bottom-half，在主循环中处理
- **Timer 模式** — `virtio_net_handle_tx_timer()` 启动定时器，延迟合并发送

```c
// hw/net/virtio-net.c:2851-2875 — BH 模式
static void virtio_net_handle_tx_bh(VirtIODevice *vdev, VirtQueue *vq)
{
    VirtIONetQueue *q = &n->vqs[vq2q(virtio_get_queue_index(vq))];
    if (unlikely(q->tx_waiting)) return;
    q->tx_waiting = 1;
    qemu_bh_schedule(q->tx_bh);
}

// hw/net/virtio-net.c:2822-2849 — Timer 模式
static void virtio_net_handle_tx_timer(VirtIODevice *vdev, VirtQueue *vq)
{
    q->tx_waiting = 1;
    timer_mod(q->tx_timer, qemu_clock_get_ns(QEMU_CLOCK_VIRTUAL) +
              n->tx_timeout);  // 延迟发送
}
```

### 23.1 virtio_net_receive_rcu — RX 核心

```c
// hw/net/virtio-net.c:1904-2054
static ssize_t virtio_net_receive_rcu(NetClientState *nc,
                                      const uint8_t *buf, size_t size)
{
    VirtIONet *n = qemu_get_nic_opaque(nc);

    // 1. 计算 virtio_net_hdr 大小
    // 2. 检查可用 RX buffer
    if (!virtio_net_has_buffers(q, offset + size)) return 0;

    // 3. MAC 过滤
    if (!virtio_net_filter(n, buf, size)) return size;  // 静默丢弃

    // 4. RSS 队列选择
    if (n->rss_data.enabled && n->rss_data.enabled_software_rss) {
        // 计算哈希，选择目标队列
    }

    // 5. 填充 RX virtqueue
    while (offset < size) {
        elem = virtqueue_pop(q->rx_vq, sizeof(VirtQueueElement));
        // 将数据包分片写入多个 buffer（mergeable 模式）
        len = iov_from_buf(elem->in_sg, elem->in_num, ...);
        virtqueue_fill(q->rx_vq, elem, total, i++);
    }

    // 6. 设置 mergeable header 的 num_buffers
    virtio_net_hdr_mrg_rxbuf.num_buffers = i;

    // 7. flush 并通知 Guest
    virtqueue_flush(q->rx_vq, i);
    virtio_notify(vdev, q->rx_vq);

    return size;
}
```

## 24. Offloading 卸载特性

### 24.1 virtio_net_hdr_v1 — 卸载头

```c
// include/standard-headers/linux/virtio_net.h:152-192
struct virtio_net_hdr_v1 {
    uint8_t flags;
    // VIRTIO_NET_HDR_F_NEEDS_CSUM  (1) — 需要计算校验和
    // VIRTIO_NET_HDR_F_DATA_VALID  (2) — 校验和已验证
    // VIRTIO_NET_HDR_F_RSC_INFO    (4) — RSC 信息
    // VIRTIO_NET_HDR_F_UDP_TUNNEL_CSUM (8) — UDP 隧道校验和

    uint8_t gso_type;
    // VIRTIO_NET_HDR_GSO_NONE    (0)
    // VIRTIO_NET_HDR_GSO_TCPV4   (1) — TSO IPv4
    // VIRTIO_NET_HDR_GSO_UDP     (3) — UFO
    // VIRTIO_NET_HDR_GSO_TCPV6   (4) — TSO IPv6
    // VIRTIO_NET_HDR_GSO_UDP_L4  (5) — USO

    __virtio16 hdr_len;    // 以太网 + IP + TCP/UDP 头长度
    __virtio16 gso_size;   // 每帧追加到 hdr_len 的字节数

    union {
        struct { __virtio16 csum_start; __virtio16 csum_offset; };  // 校验和
        struct { uint16_t segments; uint16_t dup_acks; } rsc;        // RSC
    };

    __virtio16 num_buffers;  // 合并 RX 缓冲数
};
```

### 24.2 卸载工作流

**TX 方向（Guest → Host）：**
1. Guest 设置 `virtio_net_hdr.flags = NEEDS_CSUM`，`gso_type = GSO_TCPV4`
2. Guest 将未分段的大包写入 TX virtqueue
3. QEMU 读取 hdr，将卸载信息传递给后端
4. TAP 后端通过 `TUNSETOFFLOAD` 让内核处理 TSO/校验和

**RX 方向（Host → Guest）：**
1. Host 内核或后端收到大包（可能已 GRO 合并）
2. TAP 后端设置 `virtio_net_hdr.flags/gso_type`
3. QEMU 将 hdr + 数据写入 RX virtqueue
4. Guest 驱动根据 hdr 信息处理校验和验证/分段

## 28. 完整数据包流转追踪

### 28.1 Guest → Host（TX 完整路径）

```
1. Guest 应用发送数据
    ↓
2. Guest virtio-net 驱动将数据 + virtio_net_hdr 写入 TX virtqueue
    ↓
3. Guest 写入 kick doorbell → QEMU 收到通知
    ↓
4. virtio_net_handle_tx_bh()                  // hw/net/virtio-net.c:2851
    ↓
5. virtio_net_flush_tx()                       // hw/net/virtio-net.c:2718
    │ a. virtqueue_pop() 取出元素
    │ b. 提取 out_sg (scatter-gather)
    │ c. 处理 virtio_net_hdr
    ↓
6. qemu_sendv_packet_async(&nic->nc, ...)      // net/net.c:884
    ↓
7. filter_receive_iov(TX方向, nc->filters)     // net/net.c:747
    ↓
8. qemu_net_queue_send_iov()                   // net/queue.c:221
    ↓
9. qemu_deliver_packet_iov(sender, peer)       // net/net.c:829
    │ a. 检查 link_down / receive_disabled
    │ b. 重入保护
    ↓
10. peer->info->receive_iov()                  // 即 tap_receive_iov()
    ↓
11. tap_receive_iov()                          // net/tap.c:152
    │ writev(tap_fd, iov, iovcnt)
    ↓
12. Linux 内核处理 TAP 写入 → Host 网络栈
```

### 28.2 Host → Guest（RX 完整路径）

```
1. Host 网络栈将数据包写入 TAP 设备
    ↓
2. TAP fd 可读 → QEMU 事件循环触发
    ↓
3. tap_send()                                  // net/tap.c:195
    │ a. read(tap_fd, buf, ...)
    │ b. 跳过 vnet_hdr（如果需要）
    ↓
4. qemu_send_packet_async(&tap_nc, buf, size)  // net/net.c:764
    ↓

    ↓

    ↓
7. qemu_deliver_packet_iov(tap_nc, nic_nc)     // net/net.c:829
    ↓
```
