## 第一部分：块层架构

### 1. 架构总览

QEMU 块层是一个分层的、基于协程的 I/O 栈，将设备层的块 I/O 请求通过多级处理最终转化为宿主机的文件/设备操作。

```
┌─────────────────────────────────────────────────────┐
│          设备层 (virtio-blk, IDE, SCSI, NVMe)        │
└────────────────────┬────────────────────────────────┘
                     │ blk_aio_preadv() / blk_aio_pwritev()
                     ▼
┌─────────────────────────────────────────────────────┐
│               BlockBackend (BB)                      │
│  • 设备↔块层接口    • 权限管理    • I/O 限流入口      │
└────────────────────┬────────────────────────────────┘
                     │ bdrv_co_preadv() / bdrv_co_pwritev()
                     ▼
┌─────────────────────────────────────────────────────┐
│           BDS 图 (BlockDriverState Graph)             │
│                                                      │
│  ┌──────────┐    ┌──────────┐    ┌──────────────┐   │
│  │ throttle │───►│  qcow2   │───►│  file-posix  │   │
│  │ (过滤器) │    │ (格式层) │    │  (协议层)    │   │
│  └──────────┘    │    │      │    └──────────────┘   │
│                  │    │backing│                       │
│                  │    ▼      │                       │
│                  │ ┌────────┐│                       │
│                  │ │ base   ││                       │
│                  │ │ image  ││                       │
│                  │ └────────┘│                       │
│                  └──────────┘                        │
└────────────────────┬────────────────────────────────┘
                     │ preadv() / pwritev() / io_uring
                     ▼
┌─────────────────────────────────────────────────────┐
│                  宿主机内核                           │
│           VFS → 文件系统 → 块设备 → 磁盘              │
└─────────────────────────────────────────────────────┘
```

**三大核心数据结构**：

| 结构 | 角色 | 定义位置 |
|------|------|---------|
| BlockBackend | 设备层接口，1:1 对应一个虚拟磁盘 | block-backend.c:43-95 |
| BlockDriverState | 块层节点，构成 DAG 图 | block_int-common.h:1104-1292 |
| BdrvChild | 连接 BDS 节点的边（父→子） | block_int-common.h:1049-1084 |

### 2. BlockBackend

BlockBackend（BB）是设备层与块层之间的唯一接口。

#### 结构定义（block-backend.c:43-95）

```c
struct BlockBackend {
    char *name;                    // 块设备名（如 "hd0"）
    int refcnt;

    /* BDS 图连接 */
    BdrvChild *root;               // 指向 BDS 图顶层的 BdrvChild
    AioContext *ctx;               // 所属 AioContext

    /* 设备绑定 */
    void *dev;                     // 绑定的设备（如 VirtIOBlock）
    const BlockDevOps *dev_ops;    // 设备回调
    void *dev_opaque;

    /* 权限 */
    uint64_t perm;                 // 自身权限
    uint64_t shared_perm;          // 共享权限

    /* 统计 */
    BlockAcctStats stats;          // I/O 记账
    BlockBackendPublic public;     // 公开结构（含 throttle）

    /* I/O 状态 */
    unsigned int in_flight;        // 正在飞行的请求数
    bool disable_request_queuing;  // 请求排队禁用标志
    CoQueue queued_requests;       // 排队的协程请求

    /* 错误处理 */
    BlockdevOnError on_read_error;
    BlockdevOnError on_write_error;
};
```

#### 关键 API

| 函数 | 作用 | 位置 |
|------|------|------|
| `blk_new()` | 创建 BlockBackend | block-backend.c:355-381 |
| `blk_insert_bs()` | 连接 BDS 到 BB | block-backend.c:900-932 |
| `blk_remove_bs()` | 断开 BDS | block-backend.c:859-895 |
| `blk_attach_dev()` | 绑定设备 | block-backend.c:987-1021 |
| `blk_set_dev_ops()` | 设置设备回调 | block-backend.c:1090-1101 |
| `blk_aio_preadv()` | 异步读 | block-backend.c:1706-1714 |
| `blk_aio_pwritev()` | 异步写 | block-backend.c:1716-1724 |

### 3. BlockDriverState (BDS)

BDS 是块层的核心节点，每个 BDS 代表一个块处理阶段（过滤器、格式层或协议层）。

#### 结构定义（block_int-common.h:1104-1292）

```c
struct BlockDriverState {
    /* 驱动 */
    BlockDriver *drv;              // 块驱动（qcow2/raw/file 等）
    void *opaque;                  // 驱动私有数据（如 BDRVQcow2State）

    /* 文件标识 */
    char *filename;                // 文件路径
    char *backing_file;            // 后备文件路径
    char *backing_format;          // 后备文件格式
    char *exact_filename;          // 精确路径（无协议前缀）
    QDict *full_open_options;      // 完整打开选项

    /* BDS 图连接 */
    QLIST_HEAD(, BdrvChild) children;   // 子节点列表
    BdrvChild *backing;            // 后备文件子节点（缓存指针）
    BdrvChild *file;               // 数据文件子节点（缓存指针）
    QLIST_HEAD(, BdrvChild) parents;    // 父节点列表

    /* 节点标识 */
    char node_name[32];            // 节点名（用于 blockdev-add 引用）
    QTAILQ_ENTRY(BlockDriverState) node_list; // 全局节点链表

    /* 引用计数与继承 */
    int refcnt;
    BlockDriverState *inherits_from; // 继承关系

    /* I/O 状态 */
    unsigned int in_flight;        // 飞行中请求数
    unsigned int serialising_in_flight;
    bool copy_on_read;             // 读时复制使能

    /* 权限 */
    uint64_t open_flags;           // 打开标志（BDRV_O_*）
    QLIST_HEAD(, BdrvOpBlocker) op_blockers[BLOCK_OP_TYPE_MAX];

    /* 限制 */
    BlockLimits bl;                // 块大小/对齐限制

    /* Dirty Bitmap */
    QLIST_HEAD(, BdrvDirtyBitmap) dirty_bitmaps;

    /* 缓存 */
    BdrvBlockStatusCache *block_status_cache; // 块状态缓存
};
```

### 4. BdrvChild 与 BDS 图

#### BdrvChild 结构（block_int-common.h:1049-1084）

```c
struct BdrvChild {
    BlockDriverState *bs;          // 指向子 BDS
    char *name;                    // 边的名称（"file", "backing" 等）

    const BdrvChildClass *klass;   // 子节点行为类
    const BdrvChildRole *role;     // 角色（数据/元数据/COW）

    void *opaque;                  // 父节点私有数据

    /* 权限 */
    uint64_t perm;                 // 授予的权限
    uint64_t shared_perm;          // 共享权限

    /* 图链接 */
    QLIST_ENTRY(BdrvChild) next;        // 同父下一个子节点
    QLIST_ENTRY(BdrvChild) next_parent; // 同子下一个父节点
};
```

#### 典型 BDS 图

```
BlockBackend "hd0"
  │
  └── root (BdrvChild)
        │
        ▼
  ┌─────────────────────┐
  │ throttle-group       │  ← 过滤器 BDS（可选）
  │ drv = "throttle"     │
  └──────┬──────────────┘
         │ file (BdrvChild)
         ▼
  ┌─────────────────────┐
  │ qcow2                │  ← 格式 BDS
  │ drv = "qcow2"        │
  │ opaque = BDRVQcow2State│
  ├──────┬──────────────┤
  │      │ file          │
  │      ▼              │
  │ ┌───────────────┐   │
  │ │ file-posix    │   │  ← 协议 BDS（数据文件）
  │ │ filename =    │   │
  │ │ "disk.qcow2"  │   │
  │ └───────────────┘   │
  │      │ backing       │
  │      ▼              │
  │ ┌───────────────┐   │
  │ │ qcow2 (base)  │   │  ← 后备文件格式 BDS
  │ │ backing_file = │  │
  │ │ "base.qcow2"  │   │
  │ │   │ file      │   │
  │ │   ▼           │   │
  │ │ file-posix    │   │  ← 后备文件协议 BDS
  │ └───────────────┘   │
  └─────────────────────┘
```

**后备链**：当 qcow2 读取到未分配的簇时，请求沿 `backing` 链向下传递，直到找到分配的数据或到达链底（返回零）。

### 5. BlockDriver 接口

BlockDriver 是块驱动的虚函数表（block_int-common.h:94-800）。

#### 核心回调

```c
struct BlockDriver {
    const char *format_name;       // 格式名（"qcow2", "raw"）
    const char *protocol_name;     // 协议名（"file", "nbd"）— 协议驱动特有

    /* 生命周期 */
    int (*bdrv_open)(BDS *bs, QDict *options, int flags, Error **errp);
    void (*bdrv_close)(BDS *bs);

    /* I/O 回调（协程） */
    int (*bdrv_co_preadv_part)(BDS *bs, ...);      // 优先：带偏移的读
    int (*bdrv_co_preadv)(BDS *bs, ...);            // 备选：完整读
    int (*bdrv_co_pwritev_part)(BDS *bs, ...);      // 优先：带偏移的写
    int (*bdrv_co_pwritev)(BDS *bs, ...);           // 备选：完整写
    int (*bdrv_co_flush_to_disk)(BDS *bs);          // flush 到磁盘
    int (*bdrv_co_pdiscard)(BDS *bs, ...);          // discard

    /* 元数据 */
    bool is_format;                // 是否为格式驱动
    bool supports_backing;         // 是否支持后备文件
    int64_t (*bdrv_co_getlength)(BDS *bs);
    int (*bdrv_co_block_status)(BDS *bs, ...);      // 块状态查询

    /* 创建 */
    int (*bdrv_co_create)(BlockdevCreateOptions *, Error **);
    int (*bdrv_co_create_opts)(BlockDriver *, const char *, QemuOpts *, Error **);
};
```

#### 驱动分类

| 类别 | 示例 | 特征 |
|------|------|------|
| 格式驱动 | qcow2, raw, vmdk, vdi | `is_format=true`，处理镜像格式 |
| 协议驱动 | file, nbd, iscsi, nvme | 有 `protocol_name`，处理实际 I/O |
| 过滤驱动 | throttle, copy-on-read, mirror | 拦截/转发 I/O |

#### I/O 回调选择优先级（block/io.c:992-1040）

```
1. bdrv_co_preadv_part  （首选：支持偏移子请求）
2. bdrv_co_preadv       （次选：完整请求）
3. bdrv_aio_preadv      （遗留：异步回调式）
4. bdrv_read            （最旧：扇区级）
```

## 第二部分：I/O 路径

### 6. 读 I/O 完整路径

从设备发起到数据返回的完整读路径：

```
virtio_blk_handle_request()  ← 设备层
  │
  └── blk_aio_preadv(blk, offset, qiov, flags, cb, opaque)
        │                                [block-backend.c:1706-1714]
        │
        ├── 1. 创建 AIOCB + 启动协程
        │     └── blk_aio_prwv()         [block-backend.c:1579-1610]
        │           ├── acb = blk_aio_get(...)
        │           ├── co = qemu_coroutine_create(blk_aio_read_entry)
        │           └── aio_co_enter(blk->ctx, co)
        │
        └── 2. 协程执行
              └── blk_aio_read_entry()   [block-backend.c:1612-1620]
                    │
                    └── blk_co_do_preadv_part() [block-backend.c:1330-1361]
                          │
                          ├── 等待 drain 完成
                          ├── 检查设备可用性
                          ├── 增加 in_flight 计数
                          │
                          ├── 3. Throttle 拦截（如果启用）
                          │     └── throttle_group_co_io_limits_intercept()
                          │                          [block-backend.c:1352-1356]
                          │
                          └── 4. 进入 BDS 图
                                └── bdrv_co_preadv(blk->root, offset, bytes, qiov, flags)
                                      │            [block/io.c:1768-1825]
                                      │
                                      ├── 请求跟踪 + 对齐处理
                                      │
                                      └── 5. 驱动分发
                                            └── bdrv_driver_preadv()
                                                  │    [block/io.c:992-1040]
                                                  │
                                                  ├── qcow2 路径:
                                                  │   └── qcow2_co_preadv_part()
                                                  │         ├── L1/L2 查表
                                                  │         ├── 已分配 → 读 data file
                                                  │         ├── 未分配 → 递归读 backing
                                                  │         └── 压缩 → 解压
                                                  │
                                                  └── file-posix 路径:
                                                      └── raw_co_preadv()
                                                            ├── io_uring 提交
                                                            ├── 或 Linux AIO
                                                            └── 或 线程池 preadv()
```

### 7. 写 I/O 完整路径

```
virtio_blk_handle_request()  ← 设备层
  │
  └── blk_aio_pwritev(blk, offset, qiov, flags, cb, opaque)
        │                                [block-backend.c:1716-1724]
        │
        └── blk_co_do_pwritev_part()     [block-backend.c:1405-1454]
              │
              ├── 1. Drain + 可用性检查
              │
              ├── 2. Throttle 拦截
              │     └── throttle_group_co_io_limits_intercept()
              │                                  [block-backend.c:1426-1430]
              │
              ├── 3. 写缓存策略
              │     └── 如果 write-cache 禁用 → 添加 BDRV_REQ_FUA 标志
              │                                  [block-backend.c:1432-1434]
              │
              └── 4. 进入 BDS 图
                    └── bdrv_co_pwritev_part()    [block/io.c:2236-2295]
                          │
                          ├── 请求验证 + 跟踪
                          │
                          ├── 对齐不足时 → Read-Modify-Write (RMW)
                          │     └── 读取对齐边界数据，合并新数据，再写入
                          │
                          └── 5. 驱动分发
                                └── bdrv_driver_pwritev()
                                      │    [block/io.c:1043-1126]
                                      │
                                      ├── FUA 处理:
                                      │   ├── 驱动支持 FUA → 直接传递
                                      │   └── 不支持 → 写完后 flush
                                      │         └── bdrv_co_flush()
                                      │                    [io.c:1118-1120]
                                      │
                                      ├── qcow2 路径:
                                      │   └── qcow2_co_pwritev_part()
                                      │         ├── 簇已分配 → 直接覆写
                                      │         ├── 簇未分配 → COW:
                                      │         │   ├── 分配新簇
                                      │         │   ├── 读取旧数据
                                      │         │   ├── 合并新数据
                                      │         │   ├── 写入新簇
                                      │         │   └── 更新 L2 表
                                      │         └── 引用计数更新
                                      │
                                      └── file-posix 路径:
                                          └── raw_co_pwritev()
                                                └── pwritev() / io_uring
```

### 8. Flush 路径

```
blk_aio_flush() → blk_co_flush() → bdrv_co_flush()
  │
  ├── 遍历 BDS 图，每层调用 drv->bdrv_co_flush_to_disk()
  │
  ├── qcow2: 刷新 L2/refcount 缓存 → 调用 file 层 flush
  │
  └── file-posix: fdatasync() 或 fsync()
```

### 9. Discard/写零路径

```
blk_aio_pdiscard() → bdrv_co_pdiscard()
  │
  ├── qcow2: 释放簇引用 → 标记 L2 条目为未分配
  │
  └── file-posix: fallocate(FALLOC_FL_PUNCH_HOLE)

blk_aio_pwrite_zeroes() → bdrv_co_pwrite_zeroes()
  │
  ├── qcow2: 标记 L2 条目为零簇（不实际写数据）
  │
  └── file-posix: fallocate(FALLOC_FL_ZERO_RANGE)
```

## 第三部分：协程与异步 I/O

### 10. 协程基础设施

QEMU 块层使用协程实现非阻塞 I/O，避免了回调地狱。

#### 协程 API（coroutine.h:23-170）

```c
/* 创建协程 */
Coroutine *qemu_coroutine_create(CoroutineEntry *entry, void *opaque);

/* 进入协程（从非协程上下文） */
void qemu_aio_coroutine_enter(AioContext *ctx, Coroutine *co);

/* 让出（从协程内部） */
void qemu_coroutine_yield(void);

/* 同步原语 */
CoMutex    — 协程互斥锁（让出而非阻塞）
CoQueue    — 协程等待队列
```

#### 协程生命周期

```
主线程/IOThread                     协程
     │                                │
     ├── qemu_coroutine_create()      │ (创建，未执行)
     │                                │
     ├── aio_co_enter(ctx, co) ──────►│ (进入执行)
     │                                │
     │   ◄── qemu_coroutine_yield() ──│ (让出，返回调用者)
     │                                │
     │   ... 等待 I/O 完成 ...        │
     │                                │
     ├── aio_co_enter(ctx, co) ──────►│ (恢复执行)
     │                                │
     │   ◄── 协程函数返回 ─────────────│ (协程结束，回收到池)
```

#### 协程池（qemu-coroutine.c:28-47, 217-233）

协程使用对象池复用，避免频繁创建/销毁的开销。`qemu_coroutine_create()` 优先从池中取出空闲协程，池空时才创建新的。

### 11. blk_aio_* 到协程桥接

设备层调用的 `blk_aio_*` 是异步回调式 API，内部通过协程实现：

```
blk_aio_preadv(blk, offset, qiov, flags, cb, opaque)
  │
  └── blk_aio_prwv()              [block-backend.c:1579-1610]
        │
        ├── 1. 分配 AIOCB
        │     └── acb = blk_aio_get(&blk_aio_em_aiocb_info, ...)
        │
        ├── 2. 创建协程
        │     └── co = qemu_coroutine_create(blk_aio_read_entry, acb)
        │
        ├── 3. 进入协程
        │     └── aio_co_enter(blk->ctx, co)
        │           └── 协程执行 blk_co_do_preadv_part()
        │                 └── ... 可能在 I/O 等待时 yield ...
        │
        └── 4. 完成回调
              └── blk_aio_complete()   [block-backend.c:1563-1570]
                    ├── acb->common.cb(acb->common.opaque, ret)
                    │     └── 回调设备层（如 virtio_blk_rw_complete）
                    └── blk->in_flight--
```

**关键设计**：协程可能在单次 `aio_co_enter()` 中完成（快速路径），也可能多次 yield/resume（如等待 io_uring 完成）。`has_returned` 标志防止过早释放 AIOCB。

### 13. 线程池 AIO

当文件系统不支持异步 I/O（如 NFS 上的 O_DIRECT）时，file-posix 使用线程池模拟异步。

#### 线程池架构（thread-pool.c:27-498）

```
AioContext
  │
  └── ThreadPool
        │
        ├── 工作线程 1 ──► preadv() (阻塞)
        ├── 工作线程 2 ──► pwritev() (阻塞)
        ├── 工作线程 3 ──► fsync() (阻塞)
        └── ...
        │
        └── 完成通知 ──► completion BH ──► 唤醒协程
```

**工作流**（thread-pool.c:82-293）：

```

  │

  │     └── 工作线程取出并执行 func(arg)    [82-136]

  │

```

### 15. qcow2 格式驱动

qcow2 是 QEMU 最重要的磁盘镜像格式，支持 COW、快照、压缩和加密。

### 16. qcow2 读路径

`qcow2_co_preadv_part()`（qcow2.c:2472-2533）：

```

  │
  ├── while (bytes > 0):
  │     │
  │     ├── 1. 簇查找
  │     │     └── qcow2_get_host_offset()    [qcow2-cluster.c:395-638]
  │     │           ├── L1 索引 = offset >> (cluster_bits + l2_bits)

  │     │
  │     │     ┌── NORMAL (已分配):
  │     │     │     └── 从 data_file 读取 host_offset 处的数据

  │     │     │
  │     │     ├── UNALLOCATED (未分配):
  │     │     │     ├── 有 backing → 递归读 backing 文件
  │     │     │     │     └── bdrv_co_preadv_part(bs->backing, offset, ...)
```

### 17. qcow2 写路径与 COW

#### 写入已分配簇

```
qcow2_co_pwritev_part() — 簇已分配:
  │
  ├── qcow2_get_host_offset() → NORMAL，已有 host_offset
  │
  └── bdrv_co_pwritev_part(s->data_file, host_offset, ...)
        └── 直接覆写（无需 COW）
```

#### 写入未分配簇（COW 流程）

```
qcow2_co_pwritev_part() — 簇未分配:
  │
  ├── 1. 分配新簇
  │     └── qcow2_alloc_cluster_offset()
  │           ├── 搜索空闲簇（从 free_cluster_index 开始）
  │           ├── 更新引用计数 (+1)
  │           └── 返回 host_offset
  │
  ├── 2. COW 旧数据（如果写入不覆盖整个簇）
  │     └── do_perform_cow_read()     [qcow2-cluster.c:495-520]
  │           ├── 从 backing 文件读取未被覆盖的部分
  │           └── 存入临时缓冲区
  │
  ├── 3. 合并新数据与 COW 数据
  │
  ├── 4. 写入新簇
  │     └── bdrv_co_pwritev_part(s->data_file, host_offset, ...)
  │
  ├── 5. 更新 L2 表
  │     ├── L2 表中对应条目 = new_host_offset | QCOW_OFLAG_COPIED
  │     └── l2_allocate() 如果 L2 表本身也需要分配
  │           └── [qcow2-cluster.c:273-380]
  │                 ├── 分配新 L2 表簇
  │                 ├── 复制旧 L2 表内容（如果存在）
  │                 ├── 更新 L1 表指向新 L2
  │                 └── 设置 QCOW_OFLAG_COPIED
  │
  └── 6. 更新引用计数
        └── 旧簇引用 -1（如果有），新簇引用已在步骤 1 设置
```

**QCOW_OFLAG_COPIED**：表示该簇/L2 表的引用计数为 1（独占），可以直接覆写。没有此标志表示被快照共享，必须先 COW。

### 18. qcow2 引用计数

引用计数跟踪每个簇被多少个快照/活跃镜像引用。

#### 二级查找结构

```
Refcount Table (在 header 中指定)
  ├── [0] → Refcount Block 0 的偏移
  ├── [1] → Refcount Block 1 的偏移
  └── ...

Refcount Block (每个覆盖一组簇)
  ├── [0] = 簇 N 的引用计数
  ├── [1] = 簇 N+1 的引用计数
  └── ...
```

#### 关键操作（qcow2-refcount.c）

| 操作 | 函数 | 位置 |
|------|------|------|
| 初始化 | `qcow2_refcount_init()` | 101-136 |
| 更新引用计数 | `update_refcount()` | 811-1151 |
| 分配簇 | 搜索 refcount=0 的簇 | qcow2-cluster.c |
| 释放簇 | 设置 refcount=0 | update_refcount() |

**引用计数与 COW 的关系**：
- refcount = 1 → QCOW_OFLAG_COPIED 置位 → 可直接覆写
- refcount > 1 → 被多个快照共享 → 写时必须 COW
- refcount = 0 → 空闲簇，可分配

### 19. qcow2 快照

快照通过复制 L1 表实现，不复制数据（COW 语义）。

#### 创建快照

```
1. 复制当前 L1 表 → 保存到快照表
2. 所有被引用的簇 refcount +1
3. 活跃 L1 表继续使用
4. 后续写入触发 COW（因为 refcount > 1）
```

#### 快照管理（qcow2-snapshot.c:45-271）

| 函数 | 作用 |
|------|------|
| `qcow2_do_read_snapshots()` | 读取快照表 |
| `qcow2_write_snapshots()` | 写入快照表 |
| `qcow2_free_snapshots()` | 释放快照资源 |

### 23. Throttle 限流机制

#### 架构

#### 限流算法（throttle-groups.c:357-389）

```
throttle_group_co_io_limits_intercept(tgm, bytes, is_write)
  │

  │
  ├── 2. 选择下一个 token（轮询）
  │     └── throttle_group_pick_next_peer()  [181-255]
  │
```

`blockdev_init()`（blockdev.c:479-652）处理 `-drive` 参数：

```
-drive file=disk.qcow2,id=hd0,format=qcow2,if=none,cache=writeback
  │
  ├── 解析参数:
  │     ├── file → 文件路径
  │     ├── format → 格式驱动名
  │     ├── cache → 缓存模式
  │     └── if → 接口类型（none/virtio/ide/scsi）
  │
  ├── blk_new_open(filename, options, flags)
  │     └── bdrv_open() → 构建 BDS 图
  │           ├── 打开协议层: file-posix BDS
  │           ├── 打开格式层: qcow2 BDS (bs->file = file-posix)
  │           └── 如果有 backing → 递归打开
  │
  └── 返回 BlockBackend
```

#### -blockdev（现代方式）

`-blockdev` 允许显式构建 BDS 图节点：

```bash
# 显式构建 BDS 图
-blockdev driver=file,node-name=file0,filename=disk.qcow2
-blockdev driver=qcow2,node-name=fmt0,file=file0
-device virtio-blk-pci,drive=fmt0
```

#### 缓存模式

| 模式 | O_DIRECT | O_DSYNC | 说明 |
|------|----------|---------|------|
| `writeback` | 否 | 否 | 默认，页缓存+延迟写回 |
| `writethrough` | 否 | 是 | 页缓存+同步写 |
| `none` | 是 | 否 | 绕过页缓存（推荐生产） |
| `directsync` | 是 | 是 | 绕过缓存+同步写 |
| `unsafe` | 否 | 否 | 忽略 flush（仅测试用） |

#### 格式探测 vs 显式指定

```
format= 未指定:
  └── bdrv_open() → bdrv_probe() 尝试各格式驱动的 magic 检测
        └── 安全警告：生产环境应始终显式指定 format=

format=qcow2:
  └── 直接使用 qcow2 驱动打开，跳过探测
```

### A. 完整 I/O 生命周期示例

**场景**：virtio-blk 设备读取 qcow2 镜像中的一个 4KB 扇区

```
1. Guest 驱动写 QueueNotify
2. KVM ioeventfd 触发 → QEMU IOThread 唤醒
3. virtio_blk_handle_output() → virtqueue_pop()
4. 解析 virtio_blk_outhdr: type=IN, sector=1024
5. blk_aio_preadv(blk, 512KB, qiov, 0, cb, opaque)
6. blk_aio_prwv() → 创建协程 → aio_co_enter()
7. blk_co_do_preadv_part():
     a. throttle 检查 → 未超限，通过
     b. bdrv_co_preadv(root, 512KB, 4KB, qiov, 0)
8. bdrv_co_preadv_part() → bdrv_driver_preadv()
9. qcow2_co_preadv_part():
     a. L1[0] → L2 表偏移
     b. L2[8] → host_offset = 1MB | QCOW_OFLAG_COPIED
     c. 类型 = NORMAL → 读 data_file
     d. bdrv_co_preadv_part(data_file, 1MB, 4KB, qiov, 0)
10. raw_co_preadv() → raw_co_prw()
11. io_uring: luring_co_submit(fd, 1MB, qiov, READ)
     a. io_uring_prep_readv() + io_uring_submit()
     b. 协程 yield
12. 内核完成 I/O → CQE 就绪
13. luring_process_completions() → 唤醒协程
14. 数据在 qiov 中就绪 → 返回到 qcow2 → 返回到 BB
15. blk_aio_complete() → virtio_blk_rw_complete()
16. virtqueue_push() + virtio_notify()
17. Guest 收到中断 → 读取数据完成
```
