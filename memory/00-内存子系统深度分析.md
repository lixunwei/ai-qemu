## 1. 概述

QEMU 内存子系统是连接 Guest 虚拟机与宿主机物理资源的核心桥梁。它管理：

- **Guest 物理地址空间** — 将 Guest 看到的地址映射到 RAM、MMIO 设备、ROM
- **MMIO 分发** — 将 Guest 对设备寄存器的读写转发到对应设备的处理函数
- **内存拓扑** — 支持复杂的内存区域嵌套、别名、优先级覆盖
- **IOMMU** — 为设备 DMA 提供地址翻译

核心设计理念：**树状内存区域 → 扁平化视图 → 快速分发**

```
MemoryRegion 树（可嵌套、可重叠）
        │  generate_memory_topology()
        ▼
FlatView（扁平化、无重叠的区间数组）
        │  address_space_translate()
        ▼
快速查找 → memory_region_dispatch_read/write()
```

## 2. MemoryRegion — 核心抽象

### 2.1 结构体定义

`include/system/memory.h:820-867` — MemoryRegion 是 QOM Object 的子类：

```c
struct MemoryRegion {
    Object parent_obj;                    // QOM 父类

    /* 类型标志 */
    bool romd_mode;                       // ROM 设备模式
    bool ram;                             // 是 RAM 区域
    bool subpage;                         // 子页面
    bool readonly;                        // 只读
    bool nonvolatile;                     // 非易失
    bool rom_device;                      // ROM 设备
    bool flush_coalesced_mmio;            // 刷新合并 MMIO
    bool lockless_io;                     // 无锁 I/O
    bool unmergeable;                     // 不可合并
    uint8_t dirty_log_mask;               // 脏页跟踪掩码
    bool is_iommu;                        // 是 IOMMU 区域
    RAMBlock *ram_block;                  // 关联的 RAMBlock
    Object *owner;                        // 所有者（通常是设备）
    DeviceState *dev;                     // 关联设备

    /* 访问配置 */
    const MemoryRegionOps *ops;           // 读/写回调
    void *opaque;                         // 传给 ops 的用户数据

    /* 拓扑关系 */
    MemoryRegion *container;              // 父容器
    int mapped_via_alias;                 // 是否通过别名映射
    Int128 size;                          // 区域大小
    hwaddr addr;                          // 在容器中的偏移
    void (*destructor)(MemoryRegion *mr); // 析构回调
    uint64_t align;                       // 对齐要求
    bool terminates;                      // 是否终止分发（有 ops 的区域）
    bool ram_device;                      // RAM 设备
    bool enabled;                         // 是否启用
    int32_t priority;                     // 优先级（重叠时高优先级胜出）

    /* 别名 */
    MemoryRegion *alias;                  // 别名目标
    hwaddr alias_offset;                  // 别名偏移

    /* 子区域 */
    QTAILQ_HEAD(, MemoryRegion) subregions;       // 子区域链表
    QTAILQ_ENTRY(MemoryRegion) subregions_link;   // 链表节点

    /* 其他 */
    const char *name;                     // 区域名称
    unsigned ioeventfd_nb;                // ioeventfd 数量
    MemoryRegionIoeventfd *ioeventfds;    // ioeventfd 数组
};
```

### 2.2 区域类型

| 类型 | 特征 | 典型用途 |
|------|------|---------|
| **RAM** | `ram=true`，关联 RAMBlock | Guest 物理内存 |
| **MMIO** | `terminates=true`，有 ops | 设备寄存器 |
| **ROM** | `readonly=true`，关联 RAMBlock | BIOS/固件 |
| **ROM Device** | `rom_device=true`，有 ops | 可写ROM设备（如 NOR Flash） |
| **Alias** | `alias != NULL` | 另一个区域的窗口/视图 |
| **Container** | 无 ops，无 RAM | 纯容器，组织子区域 |
| **IOMMU** | `is_iommu=true` | IOMMU 翻译区域 |

## 3. MemoryRegionOps — 设备访问回调

`include/system/memory.h:300-360`:

```c
struct MemoryRegionOps {
    /* 基本回调 */
    uint64_t (*read)(void *opaque, hwaddr addr, unsigned size);
    void (*write)(void *opaque, hwaddr addr, uint64_t data, unsigned size);

    /* 带属性的回调（优先使用） */
    MemTxResult (*read_with_attrs)(void *opaque, hwaddr addr,
                                   uint64_t *data, unsigned size,
                                   MemTxAttrs attrs);
    MemTxResult (*write_with_attrs)(void *opaque, hwaddr addr,
                                    uint64_t data, unsigned size,
                                    MemTxAttrs attrs);

    enum device_endian endianness;        // 设备字节序

    struct {
        unsigned min_access_size;         // 最小有效访问大小
        unsigned max_access_size;         // 最大有效访问大小
        bool unaligned;                   // 是否允许非对齐访问
        bool (*accepts)(void *opaque, hwaddr addr,
                        unsigned size, bool is_write,
                        MemTxAttrs attrs);  // 自定义访问验证
    } valid;

    struct {
        unsigned min_access_size;         // 实现的最小访问大小
        unsigned max_access_size;         // 实现的最大访问大小
        bool unaligned;                   // 实现是否处理非对齐
    } impl;
};
```

**valid vs impl 的区别**：
- `valid` — 定义 Guest 可以发起的合法访问范围
- `impl` — 定义设备实际能处理的访问大小范围

当 Guest 访问大小超出 `impl` 范围时，QEMU 会自动拆分/合并为 `impl` 支持的大小。

> **佐证 commit**: `9f733abb1a` — 对 `MemoryRegionOps` 中 `.unaligned` 组合的合法性增加了断言检查。

## 5. 区域层级与拓扑

### 5.1 子区域管理

```c
// memory.c:2609-2615
memory_region_add_subregion(MemoryRegion *mr, hwaddr offset,
                            MemoryRegion *subregion)
  └─ 将 subregion 插入 mr->subregions，priority = 0

// memory.c:2617-2624
memory_region_add_subregion_overlap(MemoryRegion *mr, hwaddr offset,
                                    MemoryRegion *subregion, int priority)
  └─ 同上，但指定优先级
```

### 5.2 优先级与重叠

`memory_region_update_container_subregions()` (`memory.c:2582-2589`)
按 **优先级降序** 排列子区域。当多个区域覆盖同一地址时：

- **高优先级区域胜出**（遮挡低优先级区域）
- 同优先级时按插入顺序
- `render_memory_region()` (`memory.c:596-686`) 在生成 FlatView 时处理重叠

### 5.3 别名（Alias）

别名是对另一个区域的窗口/视图：

```c
memory_region_init_alias(mr, owner, name, orig, offset, size)
  ├─ mr->alias = orig         // 目标区域
  └─ mr->alias_offset = offset // 在目标区域中的偏移
```

`render_memory_region()` 在渲染时跟随别名链 (`memory.c:629-635`)，
MMIO 分发也递归跟随别名 (`memory.c:1476-1480`)。

### 5.4 启用/禁用

```c
// memory.c:2648-2657
memory_region_set_enabled(MemoryRegion *mr, bool enabled)
  ├─ memory_region_transaction_begin()
  ├─ mr->enabled = enabled
  ├─ memory_region_update_pending = true
  └─ memory_region_transaction_commit()    // 触发 FlatView 重建
```

### 5.5 ARM64 virt 机器典型内存拓扑

```
system_memory (Container, 根)
  ├── ram (RAM, 0x4000_0000, Guest 物理内存)
  ├── pl011@0900_0000 (MMIO, UART 寄存器)
  ├── pl031@0901_0000 (MMIO, RTC 寄存器)
  ├── gic_dist@0800_0000 (MMIO, GIC Distributor)
  ├── gic_redist@080A_0000 (MMIO, GIC Redistributor)
  ├── pcie_ecam (MMIO, PCIe ECAM 配置空间)
  ├── pcie_mmio (Alias → PCIe 设备 MMIO 窗口)
  ├── flash[0] (ROM Device, NOR Flash / UEFI 固件)
  ├── flash[1] (ROM Device, NOR Flash 变量存储)
  ├── virtio_mmio@0a00_xxxx (MMIO, virtio 传输)
  └── smmuv3 (IOMMU, 可选)
```

## 7. FlatView — 扁平化视图

### 7.1 核心概念

FlatView 是将树状 MemoryRegion 层级"压平"成 **无重叠、有序的地址区间数组**，
用于快速地址查找。

### 7.2 结构体

```c
// include/system/memory.h:1194-1202
struct FlatView {
    struct rcu_head rcu;
    unsigned ref;              // 引用计数
    FlatRange *ranges;         // FlatRange 数组
    unsigned nr;               // 有效元素数
    unsigned nr_allocated;     // 已分配数
    struct AddressSpaceDispatch *dispatch;  // 分发表
    MemoryRegion *root;        // 源根区域
};

// memory.c:222-231 (内部结构)
struct FlatRange {
    MemoryRegion *mr;                    // 对应的 MemoryRegion
    hwaddr offset_in_region;             // 在 MR 中的偏移
    AddrRange addr;                      // 在地址空间中的范围 [start, size]
    uint8_t dirty_log_mask;
    bool romd_mode;
    bool readonly;
    bool nonvolatile;
    bool unmergeable;
};
```

### 7.3 生成流程

```
memory_region_transaction_commit()          [memory.c:1144-1170]
  │  当 memory_region_update_pending == true 时
  ▼
flatviews_reset()                           [memory.c:1153-1155]
  │  遍历所有 AddressSpace
  ▼
generate_memory_topology(MemoryRegion *mr)  [memory.c:747-760]
  │
  ├─ 分配空 FlatView
  ├─ render_memory_region(mr, ...)          [memory.c:596-686]
  │   ├─ 递归遍历 MemoryRegion 树
  │   ├─ 跟随 alias 链
  │   ├─ 按优先级处理重叠（高优先级遮挡低优先级）
  │   ├─ 只保留 enabled 的区域
  │   └─ 将每个可见区域生成 FlatRange
  ├─ flatview_simplify()                   # 合并相邻的连续区域
  └─ 设置为 AddressSpace.current_map

address_space_update_topology(as)
  └─ 对比新旧 FlatView → 通知 MemoryListener
```

> **佐证 commit**: `a4e85f89e8` "Optimize flatview_simplify() to eliminate redundant memmove calls"
> — 优化了 FlatView 合并相邻区间的性能。

### 7.4 RCU 保护

FlatView 通过 **RCU（Read-Copy-Update）** 机制实现无锁读访问：
- 读操作（MMIO 分发）在 RCU 读临界区内读取 `current_map`
- 写操作（拓扑变更）创建新 FlatView，通过 `rcu_assign_pointer` 原子替换
- 旧 FlatView 在 RCU grace period 后释放

## 8. MMIO 分发路径

### 8.1 读路径完整调用链

```
Guest 读取设备寄存器（如读 UART 数据寄存器）
  │
  ├─ [KVM 路径]
  │    kvm_cpu_exec()                        [kvm-all.c]
  │    └─ case KVM_EXIT_MMIO:
  │         └─ address_space_rw(&address_space_memory, phys_addr,
  │                             attrs, data, len, is_write=false)
  │
  └─ [TCG 路径]
       do_ld_mmio_beN()                      [cputlb.c:1936-1986]
       └─ io_prepare() → 获取 MemoryRegion
            └─ memory_region_dispatch_read()
                 │
                 ▼
memory_region_dispatch_read(mr, addr, pval, op, attrs)
                                              [memory.c:1467-1488]
  ├─ 跟随 alias 链: while(mr->alias) { addr += mr->alias_offset; mr = mr->alias; }
  ├─ memory_region_access_valid(mr, addr, size, false, attrs)
  │    └─ 检查 valid.min/max_access_size、unaligned、accepts()
  │                                           [memory.c:1402-1442]
  ├─ memory_region_dispatch_read1(mr, addr, pval, op, attrs)
  │    └─ access_with_adjusted_size(addr, pval, size,
  │            mr->ops->impl.min_access_size,
  │            mr->ops->impl.max_access_size,
  │            memory_region_read_accessor / memory_region_read_with_attrs_accessor,
  │            mr, attrs)                     [memory.c:1444-1465]
  │         └─ 如果 size 在 impl 范围内 → 直接调用 ops->read()
  │         └─ 如果 size 超出 → 拆分为多次小访问
  └─ adjust_endianness(mr, pval, op)
       └─ 根据 mr->ops->endianness 进行字节序调整
```

### 8.2 写路径完整调用链

```
memory_region_dispatch_write(mr, addr, data, op, attrs)
                                              [memory.c:1517-1561]
  ├─ 跟随 alias 链
  ├─ memory_region_access_valid(mr, addr, size, true, attrs)
  ├─ adjust_endianness(mr, &data, op)        # 写之前先调整字节序
  ├─ [可选] ioeventfd 快捷路径
  └─ access_with_adjusted_size(...)
       └─ ops->write() 或 ops->write_with_attrs()
```

### 8.3 地址翻译

```c
// include/system/memory.h:2807-2812
address_space_translate(as, addr, xlat, len, is_write, attrs)
  └─ flatview_translate(address_space_to_flatview(as), ...)
       ├─ 在 FlatView.ranges 中二分查找 addr
       ├─ 计算 xlat（在 MemoryRegion 内的偏移）
       └─ 如果是 IOMMU 区域 → 进入 IOMMU 翻译路径
```

### 8.4 访问大小调整

当 Guest 发起的访问大小与设备 `impl` 范围不匹配时：

```
Guest 读取 4 字节，但 ops->impl.max_access_size = 2
  → access_with_adjusted_size 自动拆分为 2 次 2 字节读取
  → 结果合并后返回

Guest 读取 1 字节，但 ops->impl.min_access_size = 4
  → 自动扩展为 4 字节读取
  → 取出对应字节返回
```

### 13.1 核心接口

```c
              void *buf, dma_addr_t len, DMADirection dir,
              MemTxAttrs attrs)
  └─ address_space_rw(as, addr, attrs, buf, len, dir == DMA_DIRECTION_FROM_DEVICE)

dma_memory_write(as, addr, buf, len, attrs)  // 写入设备内存
```

### 13.2 DMA 与 IOMMU 的关系

设备 DMA 经过 `address_space_rw()` → `address_space_translate()` →
如果设备的 AddressSpace 根区域包含 IOMMUMemoryRegion → 自动进入 IOMMU 翻译路径：

```
设备发起 DMA 写入 (IOVA)
  └─ dma_memory_write(dev_as, iova, buf, len, attrs)
       └─ address_space_rw(dev_as, iova, ...)
            └─ address_space_translate(dev_as, iova, ...)
                 └─ [如果有 IOMMU] address_space_translate_iommu()
                      └─ iommu_mr->translate(iova) → 物理地址
                 └─ 最终到达目标 MemoryRegion（RAM 或 MMIO）
```

## 14. KVM vs TCG MMIO 路径对比

### 14.1 KVM MMIO 路径

```
Guest 执行 LDR x0, [设备地址]
  │
  ├─ CPU 执行在 KVM 内核模块中
  ├─ KVM 检测 MMIO 访问 → VM Exit
  ├─ 返回用户态 QEMU
  │
  └─ kvm_cpu_exec(cpu)                        [kvm-all.c]
       └─ case KVM_EXIT_MMIO:
            └─ address_space_rw(&address_space_memory,
                                run->mmio.phys_addr,
                                attrs, run->mmio.data,
                                run->mmio.len, run->mmio.is_write)
                 └─ memory_region_dispatch_read/write()
                      └─ ops->read/write()    ← 设备处理
```

**特点**: 每次 MMIO 访问都需要 VM Exit → 用户态处理 → VM Entry，开销较大。

### 14.2 TCG MMIO 路径

```
Guest 执行 LDR x0, [设备地址]
  │
  ├─ TCG 翻译后的代码执行
  ├─ MMU/TLB 查找 → 未命中 → 慢速路径
  │
  └─ do_ld_mmio_beN()                         [cputlb.c:1936-1986]
       ├─ io_prepare() → 获取 MemoryRegion
       └─ memory_region_dispatch_read(mr, addr, &val, op, attrs)
            └─ ops->read()                    ← 设备处理
```

**特点**: 全部在用户态完成，无内核交互，但 CPU 指令本身是翻译执行的。

### 14.3 对比总结

| 方面 | KVM | TCG |
|------|-----|-----|
| CPU 指令执行 | 硬件直接执行 | 二进制翻译 |
| MMIO 触发 | VM Exit（KVM内核→用户态） | TLB miss → 慢速路径 |
| MMIO 分发 | `address_space_rw()` | `memory_region_dispatch_read/write()` |
| 性能 | CPU 快，MMIO 有 Exit 开销 | CPU 慢（翻译），MMIO 无 Exit |
| 最终到达 | 同一个 `ops->read/write()` | 同一个 `ops->read/write()` |

## 16. 关键设计总结

### 16.1 核心设计模式

| 模式 | 实现 | 说明 |
|------|------|------|
| **树→扁平化** | MR树 → FlatView | 复杂拓扑 → 快速查找 |
| **RCU** | FlatView 的读写分离 | 无锁 MMIO 分发 |
| **观察者** | MemoryListener | 拓扑变更自动同步到 KVM 等后端 |
| **策略** | MemoryRegionOps | 不同设备实现不同的读写行为 |
| **装饰器** | Alias / IOMMU | 在不修改原始区域的情况下变换地址 |
| **事务** | begin/commit | 批量拓扑变更，只触发一次 FlatView 重建 |

### 16.2 关键约束

1. **MMIO 分发必须经过 FlatView** — 保证查找效率 O(log N)
2. **拓扑变更必须在事务中** — `begin()` ... `commit()` 保证原子性
3. **IOMMU 可嵌套** — `address_space_translate_iommu()` 中的 while 循环
4. **设备 ops 线程安全** — 由 BQL（Big QEMU Lock）或设备自己保证
5. **alias 不增加分发开销** — 在 FlatView 生成时已解析

### 16.3 ARM64 特殊考量

- ARM64 主要使用 MMIO（几乎不用 I/O 端口）
- GICv3 的 MMIO 区域（GICD/GICR）是最频繁访问的设备之一
- SMMUv3 为 PCIe 设备提供 IOMMU 翻译
- virt 机器的内存布局在 `hw/arm/virt.c` 中硬编码地址映射
