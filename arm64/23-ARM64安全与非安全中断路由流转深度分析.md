# ARM64 安全/非安全中断路由与流转深度分析

## 1. 概述

本文深度分析 QEMU 11.0.50 中 ARM64 安全中断与非安全中断在不同异常级别和安全状态下的完整流转逻辑。覆盖 GICv3 中断组到 FIQ/IRQ 信号映射、SCR_EL3/HCR_EL2 路由决策、PSTATE.DAIF 屏蔽、虚拟中断注入、以及完整的端到端中断处理路径。

**关键源文件：**
- `hw/intc/arm_gicv3_cpuif.c` — GICv3 CPU 接口（组→FIQ/IRQ 映射、优先级、虚拟接口）
- `hw/intc/arm_gicv3_dist.c` — GICv3 分发器（IGROUPR/IGRPMODR、安全访问控制）
- `target/arm/cpu-irq.c` — CPU 中断处理（arm_cpu_exec_interrupt、arm_excp_unmasked）
- `target/arm/helper.c` — 目标 EL 路由（target_el_table、arm_phys_excp_target_el）
- `hw/intc/gicv3_internal.h` — GIC 内部定义

## 2. GICv3 中断组与安全映射

### 2.1 三个中断组

| 组 | IGROUPR | IGRPMODR | 安全属性 | 默认信号 | 用途 |
|----|---------|----------|----------|----------|------|
| Group 0 | 0 | 0 | Secure | **FIQ** | EL3 固件中断 |
| Group 1 Secure | 0 | 1 | Secure | IRQ（Secure EL1） | Secure OS 中断 |
| Group 1 NS | 1 | （忽略） | Non-Secure | IRQ（NS EL1/EL2） | 普通 OS 中断 |

### 2.2 NS 访问安全过滤

```c
// arm_gicv3_dist.c:59-79 — mask_group_and_nsacr()
static uint32_t mask_group_and_nsacr(GICv3State *s, MemTxAttrs attrs, ...)
{
    if (!attrs.secure && !(s->gicd_ctlr & GICD_CTLR_DS)) {
        // NS 访问：Group 0 和 Secure Group 1 的位为 RAZ/WI
        // 除非 NSACR 明确允许
        mask = *gic_bmp_ptr32(s->group, irq);
        if (maskfn) mask |= maskfn(s, irq);
        return mask;
    }
    return 0xFFFFFFFF;  // Secure 访问：全部可见
}
```

**安全隔离效果：**
- NS 软件看到的 `GICD_IGROUPR` 中，Group 0 和 G1S 的位读为 0（RAZ）
- NS 软件无法修改 Secure 中断的组配置
- `GICD_CTLR.DS=1`（Disable Security）时禁用此过滤

## 3. CPU 接口：组到信号映射

### 3.1 gicv3_cpuif_update() — 核心路由决策

```c
// arm_gicv3_cpuif.c:1046-1102
void gicv3_cpuif_update(GICv3CPUState *cs)
{
    // G1S 发给无 EL3 的 CPU → 降级为 G0
    if (cs->hppi.grp == GICV3_G1 && !arm_feature(env, ARM_FEATURE_EL3))
        cs->hppi.grp = GICV3_G0;

    if (icc_hppi_can_preempt(cs)) {
        bool isfiq;
        switch (cs->hppi.grp) {
        case GICV3_G0:
            isfiq = true;                          // G0 → 始终 FIQ
            break;
        case GICV3_G1:  // Group 1 Secure
            isfiq = (!arm_is_secure(env) ||         // NS 世界 → FIQ
                     (cur_el == 3 && aa64_el3));    // EL3 AArch64 → FIQ
            break;
        case GICV3_G1NS:
            isfiq = arm_is_secure(env);             // Secure 世界 → FIQ
            break;                                  // NS 世界 → IRQ
        }

        if (isfiq) fiqlevel = 1;
        else if (cs->hppi.nmi) nmilevel = 1;       // NMI（FEAT_NMI）
        else irqlevel = 1;
    }

    qemu_set_irq(cs->parent_fiq, fiqlevel);
    qemu_set_irq(cs->parent_irq, irqlevel);
    qemu_set_irq(cs->parent_nmi, nmilevel);
}
```

### 3.2 组→信号映射表

| 中断组 | CPU 在 NS 世界 | CPU 在 Secure 世界 | CPU 在 EL3 (AArch64) |
|--------|---------------|-------------------|---------------------|
| **Group 0** | **FIQ** | **FIQ** | **FIQ** |
| **Group 1 Secure** | **FIQ**（跨世界） | IRQ | **FIQ** |
| **Group 1 NS** | IRQ | **FIQ**（跨世界） | IRQ |

**核心规则：** 跨安全世界的中断始终作为 FIQ 信号，因为 FIQ 通常由 SCR_EL3.FIQ 路由到 EL3。

## 4. CPU 中断路由：target_el_table

### 4.1 路由位提取

```c
// helper.c:8369-8421 — arm_phys_excp_target_el()
uint32_t arm_phys_excp_target_el(CPUState *cs, uint32_t excp_idx,
                                 uint32_t cur_el, bool secure)
{
    switch (excp_idx) {
    case EXCP_IRQ:
    case EXCP_NMI:
        scr = (env->cp15.scr_el3 & SCR_IRQ);   // SCR_EL3.IRQ
        hcr = hcr_el2 & HCR_IMO;                // HCR_EL2.IMO
        break;
    case EXCP_FIQ:
        scr = (env->cp15.scr_el3 & SCR_FIQ);   // SCR_EL3.FIQ
        hcr = hcr_el2 & HCR_FMO;                // HCR_EL2.FMO
        break;
    default: // SError
        scr = (env->cp15.scr_el3 & SCR_EA);    // SCR_EL3.EA
        hcr = hcr_el2 & HCR_AMO;                // HCR_EL2.AMO
    }

    // TGE 强制路由到 EL2
    hcr |= (hcr_el2 & HCR_TGE) != 0;

    // 六维查表
    target_el = target_el_table[is64][scr][rw][hcr][secure][cur_el];
}
```

### 4.2 target_el_table 维度

```c
// helper.c:8309-8340
// target_el_table[is64][scr][rw][hcr][secure][cur_el]
// 维度：
//   is64: 最高 EL 是否 AArch64
//   scr:  SCR_EL3.{IRQ/FIQ/EA} 是否设置
//   rw:   下级 EL 执行状态
//   hcr:  HCR_EL2.{IMO/FMO/AMO/TGE} 是否设置
//   secure: 当前是否 Secure
//   cur_el: 当前 EL (0-3)
// 返回：目标 EL (1-3)
```

### 4.3 路由规则摘要

| SCR_EL3 位 | HCR_EL2 位 | 当前状态 | 目标 EL |
|-----------|-----------|---------|---------|
| IRQ=1 | — | 任何 | **EL3** |
| FIQ=1 | — | 任何 | **EL3** |
| IRQ=0 | IMO=1 | NS EL0/EL1 | **EL2** |
| FIQ=0 | FMO=1 | NS EL0/EL1 | **EL2** |
| IRQ=0 | IMO=0 | EL0 | **EL1** |
| FIQ=0 | FMO=0 | EL0 | **EL1** |
| — | TGE=1 | EL0 | **EL2** |

**关键原则：**
- SCR_EL3 路由优先级最高（EL3 拦截）
- HCR_EL2 次之（EL2 拦截）
- TGE=1 将所有 EL0 异常路由到 EL2
- 中断不能路由到比当前 EL 低的级别

## 5. 中断屏蔽与 NMI

### 5.1 arm_excp_unmasked() — 屏蔽判定

```c
// cpu-irq.c:15-169
static inline bool arm_excp_unmasked(CPUState *cs, unsigned int excp_idx,
                                     unsigned int target_el,
                                     unsigned int cur_el, bool secure, ...)
{
    // 规则1：目标 EL < 当前 EL → 不响应
    if (cur_el > target_el) return false;

    // 规则2：NMI 检查（FEAT_NMI）
    if (aa64_nmi && SCTLR.NMI && cur_el == target_el) {
        allIntMask = PSTATE.ALLINT ||
                     (SCTLR.SPINTMASK && PSTATE.SP);
    }

    // 规则3：按类型检查 DAIF 位
    switch (excp_idx) {
    case EXCP_NMI:   pstate_unmasked = !allIntMask;          break;
    case EXCP_FIQ:   pstate_unmasked = !DAIF.F && !allIntMask; break;
    case EXCP_IRQ:   pstate_unmasked = !DAIF.I && !allIntMask; break;
    case EXCP_VIRQ:  return HCR.IMO && !TGE && !DAIF.I && !allIntMask;
    case EXCP_VFIQ:  return HCR.FMO && !TGE && !DAIF.F && !allIntMask;
    case EXCP_VINMI: return HCR.IMO && !TGE && !allIntMask;
    case EXCP_VFNMI: return HCR.FMO && !TGE && !allIntMask;
    }

    // 规则4：目标 EL > 当前 EL 时的屏蔽覆盖
    if (target_el > cur_el && target_el != 1) {
        // AArch64: 路由到 EL3 的中断不可屏蔽
        if (target_el == 3) unmasked = true;
        // 路由到 EL2：除 E2H+TGE 外不可屏蔽
        if (target_el == 2 && !(E2H && TGE)) unmasked = true;
    }

    return unmasked || pstate_unmasked;
}
```

### 5.2 屏蔽规则总结

| 场景 | DAIF.I/F 能否屏蔽？ | 说明 |
|------|---------------------|------|
| IRQ 路由到 EL3，当前 EL1 | **不能** | 更高 EL 不可屏蔽 |
| FIQ 路由到 EL3，当前 EL1 | **不能** | 更高 EL 不可屏蔽 |
| IRQ 路由到 EL2，当前 EL1 | **不能** | 更高 EL 不可屏蔽（除 E2H+TGE） |
| IRQ 路由到 EL1，当前 EL1 | **能** | 同级可屏蔽 |
| NMI，当前 EL 同级 | 由 ALLINT 控制 | DAIF 无效，仅 ALLINT 可屏蔽 |
| vIRQ/vFIQ | **能** | DAIF.I/F 正常屏蔽 |

## 6. CPU 中断调度

### 6.1 arm_cpu_exec_interrupt() — 优先级调度

```c
// cpu-irq.c:171-265
bool arm_cpu_exec_interrupt(CPUState *cs, int interrupt_request)
{
    // 优先级从高到低：
    // 1. NMI（物理不可屏蔽中断）
    // 2. VINMI（虚拟不可屏蔽 IRQ）
    // 3. VFNMI（虚拟不可屏蔽 FIQ）
    // 4. FIQ（物理快速中断）
    // 5. IRQ（物理普通中断）
    // 6. VIRQ（虚拟 IRQ）
    // 7. VFIQ（虚拟 FIQ）
    // 8. VSERR（虚拟 SError）

    // 每种中断：
    //   1. 计算 target_el = arm_phys_excp_target_el()
    //   2. 检查 arm_excp_unmasked()
    //   3. 如果未屏蔽 → 设置异常并返回
}
```

### 6.2 NMI 降级处理

```c
// cpu-irq.c:208-222
// 如果 FEAT_NMI 未启用，NMI 降级为普通中断：
if (!nmi_enabled) {
    if (NMI)   → 合并到 CPU_INTERRUPT_HARD（IRQ）
    if (VINMI) → 合并到 CPU_INTERRUPT_VIRQ
    if (VFNMI) → 合并到 CPU_INTERRUPT_VFIQ
}
```

### 6.3 虚拟中断目标 EL

```c
// cpu-irq.c:240-255
// 虚拟中断始终 target_el = 1
// 因为虚拟中断只能被 EL1 Guest 看到
if (VIRQ)  → target_el = 1
if (VFIQ)  → target_el = 1
if (VSERR) → target_el = 1
```

## 7. 虚拟中断机制

### 7.1 ICV 访问重定向

```c
// arm_gicv3_cpuif.c:85-106 — icv_access()
static bool icv_access(CPUARMState *env, int hcr_flags)
{
    // NS EL1 + HCR_EL2.{IMO/FMO} → ICC_ 寄存器重定向到 ICV_
    // ICV regs with '0': HCR.FMO 控制（Group 0 相关）
    // ICV regs with '1': HCR.IMO 控制（Group 1 相关）
    return (hcr_el2 & hcr_flags & (HCR_IMO | HCR_FMO))
           && cur_el == 1 && !secure_below_el3;
}
```

**效果：** 当 Hypervisor 设置 `HCR_EL2.IMO=1` 时，Guest EL1 对 `ICC_IAR1_EL1` 的访问被透明重定向到虚拟接口 `ICV_IAR1_EL1`。

### 7.2 虚拟中断来源

虚拟中断通过以下方式注入：

**方式 1：HCR_EL2.VI/VF 位**
```c
// 直接设置 HCR_EL2.VI=1 → CPU 看到虚拟 IRQ pending
// 直接设置 HCR_EL2.VF=1 → CPU 看到虚拟 FIQ pending
```

**方式 2：GICv3 List Registers（ICH_LR*_EL2）**
```c
// gicv3_internal.h:222-251
// ICH_LR_EL2 字段：
//   GROUP (bit 60): 0=Group 0, 1=Group 1
//   NMI (bit 59): 不可屏蔽（FEAT_NMI）
//   STATE (bits 63:62): 00=Invalid, 01=Pending, 10=Active, 11=P+A
//   HW (bit 61): 1=硬件中断（关联物理中断）
//   VINTID (bits 31:0): 虚拟中断 ID
//   PRIORITY (bits 55:48): 虚拟优先级
```

### 7.3 虚拟中断流程

```
Hypervisor (EL2):
  1. 物理中断到达 → EL2 中断处理
  2. 写 ICH_LR<n>_EL2 = {STATE=Pending, VINTID=xxx, PRIORITY=yyy}
  3. ERET 返回 EL1

GICv3 虚拟 CPU 接口:
  4. 扫描 List Registers → 找到最高优先级 pending
  5. 通过 HCR.VI/VF 信号 CPU

CPU (EL1 Guest):
  6. 看到 vIRQ/vFIQ pending
  7. 如果未屏蔽 → 异常入口（VBAR_EL1 + IRQ/FIQ 偏移）
  8. Guest 读 ICV_IAR1_EL1 → 获取 VINTID
  9. Guest 处理中断
  10. Guest 写 ICV_EOIR1_EL1 → 中断完成
```

## 8. 完整中断流转场景

### 8.1 场景 1：NS 中断在 NS EL1（正常路径）

```
1. 设备触发 SPI → GICD 设置 pending
2. GICD: IGROUPR[irq]=1 → Group 1 NS
3. 重分发器: 转发到目标 CPU 接口
4. CPU 接口: G1NS + NS 世界 → IRQ 信号
   gicv3_cpuif_update(): isfiq=false, irqlevel=1
5. qemu_set_irq(parent_irq, 1)
6. CPU: arm_cpu_exec_interrupt()
   - excp_idx = EXCP_IRQ
   - target_el = arm_phys_excp_target_el()
     SCR.IRQ=0, HCR.IMO=0 → target_el = 1
   - arm_excp_unmasked(): !DAIF.I → true
7. 异常入口: VBAR_EL1 + 0x480（低级 AArch64 IRQ）
8. EL1 ISR 读 ICC_IAR1_EL1 → 获取 INTID
9. 处理中断 → 写 ICC_EOIR1_EL1
```

### 8.2 场景 2：Secure FIQ 在 NS EL1（跨世界）

```
1. Secure 设备触发 SPI → GICD 设置 pending
2. GICD: IGROUPR[irq]=0, IGRPMODR[irq]=0 → Group 0
3. CPU 接口: G0 → FIQ 信号（始终 FIQ）
   gicv3_cpuif_update(): isfiq=true, fiqlevel=1
4. qemu_set_irq(parent_fiq, 1)
5. CPU: arm_cpu_exec_interrupt()
   - excp_idx = EXCP_FIQ
   - target_el = arm_phys_excp_target_el()
     SCR.FIQ=1 → target_el = 3
   - arm_excp_unmasked(): target_el(3) > cur_el(1) → 不可屏蔽
6. 异常入口: VBAR_EL3 + 0x500（低级 AArch64 FIQ）
7. EL3 Monitor 保存 NS 上下文
8. 切换到 Secure 世界（SCR.NS=0）
9. 读 ICC_IAR0_EL1 → 获取 Group 0 INTID
10. 分发给 Secure 中断处理
11. ERET 回 NS 世界
```

### 8.3 场景 3：NS IRQ 在 Secure EL1

```
1. NS 设备触发 SPI → Group 1 NS
2. CPU 接口: G1NS + Secure 世界 → FIQ 信号（跨世界→FIQ）
   gicv3_cpuif_update(): isfiq = arm_is_secure(env) = true
3. qemu_set_irq(parent_fiq, 1)
4. CPU: excp_idx = EXCP_FIQ
   - SCR.FIQ=1 → target_el = 3
   - 不可屏蔽（目标 EL3 > 当前 EL1）
5. 异常入口: VBAR_EL3 + 0x200（同级 FIQ，SP_ELx）
6. EL3 Monitor 保存 Secure 上下文
7. 切换到 NS 世界（SCR.NS=1）
8. ERET 到 NS EL1 → NS 中断处理器
9. 读 ICC_IAR1_EL1 → 获取 NS INTID
10. 处理完成后 ERET 回 Secure
```

### 8.4 场景 4：虚拟化环境（NS EL1 Guest + EL2 Hypervisor）

```
1. 设备触发 SPI → Group 1 NS → IRQ 信号
2. HCR_EL2.IMO=1 → IRQ 路由到 EL2
3. CPU: target_el = 2（HCR.IMO 强制）
4. 异常入口: VBAR_EL2 + 0x480
5. Hypervisor 读 ICC_IAR1_EL1 → 获取 INTID
6. Hypervisor 确定目标 VM
7. 写 ICH_LR<n>_EL2 = {Pending, VINTID, Priority, Group=1}
8. ERET 回 EL1 Guest
9. 虚拟 CPU 接口: vIRQ pending → CPU_INTERRUPT_VIRQ
10. Guest: target_el=1, arm_excp_unmasked(!DAIF.I) → 异常入口
11. VBAR_EL1 + 0x280（同级 IRQ，SP_ELx）
12. Guest 读 ICV_IAR1_EL1 → 获取 VINTID
13. Guest 处理 → 写 ICV_EOIR1_EL1
```

### 8.5 场景 5：Secure G1S 中断在 NS EL2

```
1. Secure 设备触发 → Group 1 Secure
2. CPU 接口: G1S + NS 世界 → FIQ（跨世界）
   gicv3_cpuif_update(): GICV3_G1, !secure → isfiq=true
3. SCR.FIQ=1 → target_el = 3
4. 异常入口: VBAR_EL3 + 0x500（低级 FIQ）
5. EL3 切换到 Secure，ERET 到 S-EL1
6. S-EL1 读 ICC_IAR1_EL1 → G1S INTID
```

## 9. GICv3 优先级与安全状态

### 9.1 优先级空间分离

```c
// arm_gicv3_cpuif.c:1113-1155
// NS 访问 ICC_PMR_EL1 时，优先级值被移位：
// Secure 优先级使用全 8 位范围 [0x00 - 0xFF]
// NS 优先级只能使用上半 [0x80 - 0xFF]
// NS 读 PMR 时，高位自动移位使 NS 看到 [0x00-0xFF] 的假象
```

**效果：** Secure 中断天然比 NS 中断优先级高（数值更小），确保 Secure 中断能抢占 NS 处理。

### 9.2 ICC_HPPIR 安全可见性

```c
// arm_gicv3_cpuif.c:1189-1259
// ICC_HPPIR0_EL1（Group 0）：
//   Secure 可见所有 Group 0 pending
//   NS 只看到 INTID_SPURIOUS（1023）
//
// ICC_HPPIR1_EL1（Group 1）：
//   Secure 看到 G1S pending
//   NS 看到 G1NS pending
//   跨组看到 INTID_SPURIOUS
```

## 10. 中断异常入口细节

### 10.1 AArch64 中断向量偏移

```c
// helper.c:9322-9338
case EXCP_IRQ:
case EXCP_VIRQ:
case EXCP_NMI:
case EXCP_VINMI:
    addr += 0x80;     // IRQ 类偏移
    break;
case EXCP_FIQ:
case EXCP_VFIQ:
case EXCP_VFNMI:
    addr += 0x100;    // FIQ 类偏移
    break;
case EXCP_VSERR:
    addr += 0x180;    // SError 偏移
    break;
```

### 10.2 中断 vs 同步异常的入口差异

| 特性 | 同步异常（SVC/Abort） | 中断（IRQ/FIQ） |
|------|---------------------|----------------|
| ESR_ELx | 设置 syndrome | **不设置** |
| FAR_ELx | 设置（Abort 时） | 不设置 |
| ELR_ELx | 异常指令地址 | **下一条**待执行指令 |
| 向量偏移 | +0x000（Sync） | +0x080/+0x100 |
| 可预测性 | 确定（由指令触发） | 异步（任意时刻） |

## 11. 小结

| 组件 | 实现位置 | 核心功能 |
|------|----------|----------|
| **组→信号映射** | cpuif.c:1073-1083 | G0→FIQ, G1S 跨世界→FIQ, G1NS 跨世界→FIQ |
| **NS 访问过滤** | dist.c:59-79 | mask_group_and_nsacr RAZ/WI |
| **目标 EL 路由** | helper.c:8369-8421 | SCR.IRQ/FIQ + HCR.IMO/FMO + target_el_table |
| **屏蔽判定** | cpu-irq.c:15-169 | DAIF + 高 EL 不可屏蔽 + NMI/ALLINT |
| **中断调度** | cpu-irq.c:171-265 | NMI>VINMI>VFNMI>FIQ>IRQ>VIRQ>VFIQ>VSERR |
| **虚拟接口** | cpuif.c:85-106 | HCR.IMO/FMO 触发 ICC→ICV 重定向 |
| **优先级隔离** | cpuif.c:1113-1155 | NS 只看到 [0x80-0xFF] 优先级空间 |

**关键设计原则：**
1. 跨安全世界的中断始终作为 FIQ 信号，确保能被 SCR_EL3.FIQ 路由到 EL3
2. 路由到更高 EL 的中断不受当前 EL 的 DAIF 屏蔽
3. 虚拟中断通过 ICV 重定向对 Guest 完全透明
4. Secure 中断优先级天然高于 NS（优先级空间分离）
5. target_el_table 六维查表避免了复杂的条件判断链
