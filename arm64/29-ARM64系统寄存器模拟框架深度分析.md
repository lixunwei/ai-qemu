# ARM64 系统寄存器模拟框架深度分析

## 1. 概述

ARM64 架构拥有数百个系统寄存器，通过 MSR/MRS 指令访问。QEMU 实现了一套完整的系统寄存器模拟框架，包括：寄存器定义与注册、编码与哈希查找、TCG 翻译时分发、运行时访问控制与陷阱、写副作用处理、迁移保存恢复。本文深入分析这套框架的完整实现。

**关键源文件：**
- `target/arm/cpregs.h` — ARMCPRegInfo 结构体、编码宏、访问权限定义（~1100行）
- `target/arm/helper.c` — 寄存器表定义、注册逻辑、读写处理函数（~8500行）
- `target/arm/tcg/translate-a64.c` — MSR/MRS 指令翻译 `handle_sys()`
- `target/arm/tcg/op_helper.c` — 运行时读写 Helper、访问检查
- `target/arm/machine.c` — 寄存器迁移 vmstate

## 2. ARMCPRegInfo 核心结构体

每个系统寄存器用一个 `ARMCPRegInfo` 描述：

```c
// cpregs.h:921-1049
struct ARMCPRegInfo {
    const char *name;          // 寄存器名（调试用）
    
    // === 编码字段 ===
    uint8_t cp;                // 协处理器号（AA64 固定 0x13）
    uint8_t crn, crm;         // CRn, CRm 字段
    uint8_t opc0, opc1, opc2; // op0, op1, op2 字段
    CPState state;             // AA32 / AA64 / BOTH
    
    // === 属性 ===
    int type;                  // ARM_CP_CONST / ARM_CP_IO / ARM_CP_NZCV 等
    CPAccessRights access;     // PL0_R, PL1_RW, PL2_RW, PL3_RW 等
    CPSecureState secure;      // S / NS / 无限制
    FGTBit fgt;                // 细粒度陷阱位（Fine-Grained Trap）
    
    // === VHE/NV2 重定向 ===
    uint32_t nv2_redirect_offset;  // FEAT_NV2 内存重定向偏移
    uint32_t vhe_redir_to_el2;     // VHE 下 EL1 寄存器重定向到 EL2
    uint32_t vhe_redir_to_el01;    // VHE 下 EL02/EL12 回指
    
    // === 值与存储 ===
    uint64_t resetvalue;       // 复位值（或 ARM_CP_CONST 的常量值）
    ptrdiff_t fieldoffset;     // CPUARMState 中的偏移
    ptrdiff_t bank_fieldoffsets[2]; // Secure/NonSecure 分 bank 偏移
    
    // === 回调函数 ===
    CPAccessFn *accessfn;      // 额外访问检查（运行时）
    CPReadFn   *readfn;        // 自定义读处理
    CPWriteFn  *writefn;       // 自定义写处理（副作用）
    CPReadFn   *raw_readfn;    // KVM/迁移 原始读（无副作用）
    CPWriteFn  *raw_writefn;   // KVM/迁移 原始写
    CPResetFn  *resetfn;       // 自定义复位函数
};
```

### 2.1 关键设计

| 特性 | 说明 |
|------|------|
| **fieldoffset** | 大多数寄存器直接映射到 `CPUARMState.cp15.xxx`，无需自定义 readfn/writefn |
| **writefn** | 有副作用的寄存器必须提供（如 SCTLR 刷 TLB、HCR 更新虚拟中断） |
| **raw_writefn** | 仅用于 KVM 同步和迁移，跳过副作用 |
| **bank_fieldoffsets** | Secure/NonSecure 分两个存储位置（如 SCTLR_S / SCTLR_NS） |
| **ARM_CP_IO** | 标记需要持有 BQL 锁的寄存器（如 HCR_EL2） |

## 3. 寄存器编码与哈希查找

### 3.1 AArch64 编码

```c
// cpregs.h:203-209
#define ENCODE_AA64_CP_REG(op0, op1, crn, crm, op2) \
    (CP_REG_AA64_MASK | CP_REG_ARM64_SYSREG |       \
     ((op0) << CP_REG_ARM64_SYSREG_OP0_SHIFT) |     \
     ((op1) << CP_REG_ARM64_SYSREG_OP1_SHIFT) |     \
     ((crn) << CP_REG_ARM64_SYSREG_CRN_SHIFT) |     \
     ((crm) << CP_REG_ARM64_SYSREG_CRM_SHIFT) |     \
     ((op2) << CP_REG_ARM64_SYSREG_OP2_SHIFT))

// 示例: SCTLR_EL1 = {op0=3, op1=0, crn=1, crm=0, op2=0}
// HCR_EL2    = {op0=3, op1=4, crn=1, crm=1, op2=0}
// DAIF       = {op0=3, op1=3, crn=4, crm=2, op2=1}
```

### 3.2 AArch32 编码

```c
// cpregs.h:198-201
#define ENCODE_CP_REG(cp, is64, ns, crn, crm, opc1, opc2) \
    (((ns) << 22) | ((is64) << 21) |                       \
     ((cp) << 16) | ((crn) << 11) | ((crm) << 7) | ((opc1) << 3) | (opc2))
```

## 5. MSR/MRS 翻译路径

### 5.1 handle_sys() — TCG 翻译入口

```c
// translate-a64.c:2764-3145 — handle_sys()
static void handle_sys(DisasContext *s, bool isread,
                       unsigned int op0, op1, op2, crn, crm, rt)
{
    // 1. 编码哈希键
    uint32_t key = ENCODE_AA64_CP_REG(op0, op1, crn, crm, op2);
    
    // 2. 查找寄存器信息
    const ARMCPRegInfo *ri = get_arm_cp_reginfo(s->cp_regs, key);
    
    // 3. 未知寄存器 → UNDEF
    if (!ri) {
        gen_sysreg_undef(s, ...);
        return;
    }
    
    // 4. NV2 内存重定向检查
    // 5. 翻译时权限检查 cp_access_ok()
    // 6. 生成运行时访问检查
    //    gen_helper_access_check_cp_reg(...)    [2883-2892]
    
    // 7. 读路径:
    if (isread) {
        if (ri->type & ARM_CP_CONST) {
            tcg_rt = resetvalue;            // 常量直接返回
        } else if (ri->readfn) {
            gen_helper_get_cp_reg64(...)     // 调用自定义读函数
        } else {
            tcg_gen_ld_i64(fieldoffset)      // 直接从 CPUARMState 读
        }
    }
    // 8. 写路径:
    else {
        if (ri->writefn) {
            gen_helper_set_cp_reg64(...)     // 调用自定义写函数
        } else {
            tcg_gen_st_i64(fieldoffset)      // 直接写 CPUARMState
        }
        if (need_exit_tb) {
            s->base.is_jmp = DISAS_UPDATE_EXIT; // 可能需要结束 TB
        }
    }
}
```

### 5.2 Helper 分发

```c
// op_helper.c:1042-1069
void HELPER(set_cp_reg64)(CPUARMState *env, const void *rip, uint64_t value)
{
    const ARMCPRegInfo *ri = rip;
    if (ri->type & ARM_CP_IO) {
        bql_lock();               // I/O 类型需要全局锁
        ri->writefn(env, ri, value);
        bql_unlock();
    } else {
        ri->writefn(env, ri, value);
    }
}

uint64_t HELPER(get_cp_reg64)(CPUARMState *env, const void *rip)
{
    const ARMCPRegInfo *ri = rip;
    if (ri->type & ARM_CP_IO) {
        bql_lock();
        res = ri->readfn(env, ri);
        bql_unlock();
    } else {
        res = ri->readfn(env, ri);
    }
    return res;
}
```

## 6. 访问权限与陷阱

### 6.1 权限层级

```c
// cpregs.h:307-333 — 与 EL 层级对齐
PL3_R = 0x80,  PL3_W = 0x40,   // EL3（Secure Monitor）
PL2_R = 0x20 | PL3_R,          // EL2（Hypervisor）
PL1_R = 0x08 | PL2_R,          // EL1（OS Kernel）
PL0_R = 0x02 | PL1_R,          // EL0（User）
// 高层级自动继承低层级权限
// PL1_RW = PL1_R | PL1_W = 0xCC（EL1 及以上可读写）
```

### 6.2 访问检查结果

```c
// cpregs.h:335-375
CP_ACCESS_OK          = 0,       // 允许访问
CP_ACCESS_TRAP_EL1    = 5,       // 陷入 EL1（syndrome 分类异常）
CP_ACCESS_TRAP_EL2    = 6,       // 陷入 EL2（虚拟化陷阱）
CP_ACCESS_TRAP_EL3    = 7,       // 陷入 EL3（安全陷阱）
CP_ACCESS_UNDEFINED   = 8,       // UNDEF（syndrome 0x0）
```

### 6.3 运行时访问检查

```c
// op_helper.c:840-957 — HELPER(access_check_cp_reg)
// 检查顺序（优先级从高到低）:
// 1. 基本 EL 权限检查 (cp_access_ok)
// 2. HSTR_EL2 陷阱 (AArch32 协处理器位图)
// 3. Fine-Grained Trap (FGT) 位检查
//    - fgt_read[] / fgt_write[] / fgt_exec[]
// 4. 寄存器自身的 accessfn() 回调
// 5. 结果为 CP_ACCESS_TRAP_ELx → raise_exception() 到目标 EL
```

### 6.4 HCR_EL2 陷阱路由

许多 accessfn 检查 HCR_EL2 的陷阱位：

```c
// 典型模式 — 检查 HCR 位决定是否陷入 EL2:
static CPAccessResult access_tvm_trvm(CPUARMState *env, ...)
{
    if (arm_current_el(env) == 1) {
        uint64_t hcr = arm_hcr_el2_eff(env);
        if (isread && (hcr & HCR_TRVM))  return CP_ACCESS_TRAP_EL2;
        if (!isread && (hcr & HCR_TVM))  return CP_ACCESS_TRAP_EL2;
    }
    return CP_ACCESS_OK;
}
// SCTLR_EL1, TCR_EL1, TTBR0/1_EL1 等均使用此模式
```

## 7. 关键寄存器写副作用

### 7.1 SCTLR_EL1 写

```c
// helper.c:3265-3298 — sctlr_write()
// 寄存器定义: helper.c:7336-7347
// 编码: {op0=3, op1=0, crn=1, crm=0, op2=0}, PL1_RW
// bank: cp15.sctlr_s / cp15.sctlr_ns
//
// 副作用:
// 1. MTE 位过滤（无 MTE 时清除 TCF/ATA 等位）
// 2. 值未变 → 跳过 TLB 刷新（优化：Linux 经常做无效写）
// 3. raw_write() 存储值
// 4. tlb_flush() — MMU 开关可能变化，必须刷新 TLB
//
// 影响: M(MMU), C(Cache), I(ICache), A(Alignment), E(Endian) 等位
```

### 7.2 HCR_EL2 写

```c
// helper.c:3669-3784 — do_hcr_write()
// 寄存器定义: helper.c:4067-4074
// 编码: {op0=3, op1=4, crn=1, crm=1, op2=0}, PL2_RW, ARM_CP_IO
//
// 副作用:
// 1. 构建 valid_mask（按 CPU 特性动态调整允许位）
//    - ARMv8.0 基础: bits[33:0]
//    - VHE: +E2H, RAS: +TERR/TEA, MTE: +ATA/DCT/TID5
//    - NV: +NV/NV1/NV2/AT, RME: +GPF
// 2. MMU 相关位变化 → tlb_flush()
//    - HCR_VM | HCR_PTW | HCR_DC | HCR_DCT | HCR_FWB | HCR_NV | HCR_NV1
// 3. 虚拟中断更新（需要 BQL）:
//    arm_cpu_update_virq()   — VI 位 → vIRQ
//    arm_cpu_update_vfiq()   — VF 位 → vFIQ
//    arm_cpu_update_vserr()  — VSE 位 → vSError
//    arm_cpu_update_vinmi()  — VINMI 位（NMI 扩展）
//    arm_cpu_update_vfnmi()  — VFNMI 位（NMI 扩展）
```

## 10. 迁移与状态保存

### 10.1 VMState 结构

```c
// machine.c:1229-1277 — vmstate_arm_cpu
// 固定字段直接序列化:
//   VMSTATE_UINT64_ARRAY(env.xregs, 32)    — 通用寄存器
//   VMSTATE_UINT64(env.pc)                  — 程序计数器
//   cpsr / pstate                           — 状态寄存器
//   VMSTATE_UINT64_ARRAY(env.elr_el, 4)     — ELR_EL1/2/3
//   VMSTATE_UINT64_ARRAY(env.sp_el, 4)      — SP_EL0/1/2/3

// 系统寄存器通过变长数组迁移:
//   cpreg_vmstate_array_len                 — 寄存器数量
//   cpreg_vmstate_indexes[]                 — 寄存器编码键（KVM ID）
//   cpreg_vmstate_values[]                  — 寄存器值
```

### 10.2 保存/恢复流程

```
发送端:
  cpu_pre_save()
    → 遍历 cpu->cp_regs 哈希表
    → 对每个寄存器: cpreg_to_kvm_id(key) → indexes[], readfn() → values[]
    → 填充 cpreg_vmstate_indexes/values

接收端:
  cpu_post_load()
    → 遍历 cpreg_vmstate_indexes[]
    → kvm_to_cpreg_id() 查找寄存器
    → raw_writefn() 恢复值（跳过副作用）
    → 最后 arm_rebuild_hflags() 重建状态
```

## 11. Fine-Grained Trap (FGT)

```c
// cpregs.h:377+ — FGT 索引
// HFGRTR / HFGWTR — 读/写功能陷阱
// HDFGRTR / HDFGWTR — 调试功能陷阱
// HFGITR — 指令陷阱

// 每个 ARMCPRegInfo 的 .fgt 字段编码:
//   IDX: 哪个 FGT 寄存器
//   BITPOS: 哪一位
//   REV: 是否反向（1=允许而非陷阱）
//   NXS: 是否也适用于 NXS TLB 操作

// op_helper.c:858-890 — FGT 检查逻辑
if (arm_fgt_active(env, current_el)) {
    trapword = env->cp15.fgt_read[idx];  // 或 fgt_write/fgt_exec
    trapbit = extract64(trapword, bitpos, 1);
    if (rev) trapbit = !trapbit;
    if (trapbit) → CP_ACCESS_TRAP_EL2;
}
```

## 13. 完整 MSR 执行流程

```
Guest: MSR SCTLR_EL1, X0
  │
  ├── [TCG 翻译时] handle_sys()              [translate-a64.c:2764]
  │     ├── key = ENCODE_AA64_CP_REG(3,0,1,0,0)
  │     ├── ri = get_arm_cp_reginfo(key)     → 找到 SCTLR_EL1
  │     ├── cp_access_ok(PL1_RW, current_el) → 权限检查
  │     ├── gen_helper_access_check_cp_reg() → 运行时陷阱检查
  │     └── gen_helper_set_cp_reg64(ri, X0)  → 生成写 Helper 调用
  │
  ├── [运行时] HELPER(access_check_cp_reg)   [op_helper.c:840]
  │     ├── HSTR_EL2 位图检查
  │     ├── FGT_SCTLR_EL1 位检查
  │     ├── access_tvm_trvm() → HCR_EL2.TVM 陷阱检查
  │     └── CP_ACCESS_OK → 继续
  │         (若 TRAP → raise_exception → 异常入口)
  │
  └── [运行时] HELPER(set_cp_reg64)          [op_helper.c:1042]
        └── sctlr_write(env, ri, value)      [helper.c:3265]
              ├── MTE 位过滤
              ├── 值未变 → return（跳过 TLB 刷新）
              ├── raw_write() → cp15.sctlr_ns = value
              └── tlb_flush() → 清除所有 TLB 条目
```

## 14. 小结

| 组件 | 实现 |
|------|------|
| **ARMCPRegInfo** | 统一的寄存器描述结构，包含编码、权限、回调、存储偏移 |
| **哈希表** | ARMCPU->cp_regs，32位编码键 O(1) 查找 |
| **翻译分发** | handle_sys() 查表 → 编译时权限 → 运行时 Helper |
| **Helper** | set/get_cp_reg64 调用 writefn/readfn，ARM_CP_IO 自动加 BQL |
| **访问控制** | PLx 层级 + accessfn + FGT + HSTR 四级检查，支持 TRAP_ELx |
| **写副作用** | SCTLR→TLB 刷新，HCR→虚拟中断+TLB，TCR/TTBR→条件 TLB 刷新 |
| **迁移** | cpreg_vmstate_indexes/values 变长数组，raw_writefn 恢复 |
| **复位** | resetvalue + resetfn，CPU 型号决定初始值 |
