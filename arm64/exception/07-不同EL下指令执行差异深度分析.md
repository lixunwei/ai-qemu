## 1. 概述

ARM64 架构定义了四个异常级别 (EL0-EL3)，不同 EL 下 CPU 可执行的指令集存在显著差异。这些差异不仅包括某些指令仅在特权级别可用（如 ERET 仅限 EL1+），还包括通过控制寄存器的 Trap 位，将低 EL 的指令执行强制路由到高 EL 处理（如 Hypervisor 拦截 Guest 的 WFI 指令）。

QEMU 在 TCG 翻译阶段（编译时）和辅助函数（运行时）两个层面实现了完整的 EL 指令差异模拟：

```
指令差异的三个维度：

1. 静态可用性  —— 指令在某 EL 不存在（UNDEF）
   例：ERET 在 EL0 → unallocated_encoding

2. 静态 Trap   —— 编译时已知的 Trap（嵌入 TB flags）
   例：FP 指令在 fp_excp_el != 0 时 → EXCP_UDEF

3. 动态 Trap   —— 运行时检查控制寄存器
   例：MSR 写 SCTLR_EL1 在 HCR_EL2.TVM=1 时 → CP_ACCESS_TRAP_EL2
```

## 2. 指令 Trap 总体框架

QEMU 将指令的 EL 差异分为**翻译时检查**和**运行时检查**两类：

### 2.1 翻译时检查（DisasContext）

在 `translate-a64.c` 的翻译函数中，通过 `DisasContext` 的字段直接判断：

| 字段 | 来源 | 用途 |
|------|------|------|
| `s->current_el` | TB flags | 当前 EL，决定指令是否可用 |
| `s->fp_excp_el` | `FPEXC_EL` TB flag | FP/SIMD 指令 trap 目标 EL（0=允许） |
| `s->sve_excp_el` | `SVEEXC_EL` TB flag | SVE 指令 trap 目标 EL |
| `s->sme_excp_el` | `SMEEXC_EL` TB flag | SME 指令 trap 目标 EL |
| `s->trap_eret` | TB flag | ERET 是否被 FGT trap |
| `s->fgt_svc` | TB flag | SVC 是否被 FGT trap |

这些值在 TB 构建时从 `hflags.c` 中的 `rebuild_hflags_a64()` 预计算。

### 2.2 运行时检查（Helper 函数）

对于依赖动态控制寄存器状态的检查，在翻译时生成对 helper 函数的调用：

```
translate-a64.c:
  handle_sys() → gen_helper_access_check_cp_reg()
                           ↓
op_helper.c:
  HELPER(access_check_cp_reg)() → ri->accessfn() → CPAccessResult
                                          ↓
                              CP_ACCESS_TRAP_EL2 → raise_exception()
```

源码位置：`translate-a64.c:2883-2892`、`op_helper.c:802-957`

## 3. WFI/WFE 指令三层 Trap 机制

WFI（Wait For Interrupt）和 WFE（Wait For Event）指令在不同 EL 下可能被 trap 到更高级别。QEMU 实现了三层优先级检查。

### 3.1 检查函数

```c
// op_helper.c:322-366
static inline int check_wfx_trap(CPUARMState *env, bool is_wfe, uint32_t *excp)
{
    int cur_el = arm_current_el(env);
    uint64_t mask;

    *excp = EXCP_UDEF;

    // M-profile 永不 trap
    if (arm_feature(env, ARM_FEATURE_M)) {
        return 0;
    }

    // 第一层：EL0 → EL1 trap（仅 v8+）
    // SCTLR_EL1.nTWI = 0 trap WFI，SCTLR_EL1.nTWE = 0 trap WFE
    if (cur_el < 1 && arm_feature(env, ARM_FEATURE_V8)) {
        mask = is_wfe ? SCTLR_nTWE : SCTLR_nTWI;
        if (!(arm_sctlr(env, cur_el) & mask)) {
            return exception_target_el(env);  // 通常为 EL1
        }
    }

    // 第二层：EL0/EL1 → EL2 trap
    // HCR_EL2.TWI/TWE 控制
    if (cur_el < 2) {
        mask = is_wfe ? HCR_TWE : HCR_TWI;
        if (arm_hcr_el2_eff(env) & mask) {
            return 2;
        }
    }

    // 第三层：EL0/EL1/EL2 → EL3 trap
    // SCR_EL3.TWI/TWE 控制
    if (arm_feature(env, ARM_FEATURE_V8) && !arm_is_el3_or_mon(env)) {
        mask = (is_wfe) ? SCR_TWE : SCR_TWI;
        if (env->cp15.scr_el3 & mask) {
            if (!arm_el_is_aa64(env, 3)) {
                *excp = EXCP_MON_TRAP;  // AArch32 EL3 使用 Monitor Trap
            }
            return 3;
        }
    }

    return 0;  // 不 trap
}
```

### 3.2 Trap 控制位对照表

| 控制寄存器 | WFI Trap 位 | WFE Trap 位 | 生效条件 | Trap 目标 |
|-----------|------------|------------|---------|----------|
| SCTLR_EL1 | nTWI=0 | nTWE=0 | cur_el=0, v8+ | EL1 |
| HCR_EL2 | TWI | TWE | cur_el < 2 | EL2 |
| SCR_EL3 | TWI | TWE | cur_el < 3, v8+ | EL3 |

**异常综合征 (EC)**: `EC_WFX_TRAP` = 0x01，通过 `syn_wfx()` 生成。

### 3.3 典型使用场景

- **Hypervisor 拦截 Guest WFI**：设置 `HCR_EL2.TWI=1`，Guest 执行 WFI 时 trap 到 EL2，Hypervisor 可以调度其他 vCPU
- **Secure Monitor 拦截 WFE**：设置 `SCR_EL3.TWE=1`，防止非安全世界的 WFE 影响安全状态

## 4. SVC/HVC/SMC 异常调用指令

这三条指令是 ARM64 中跨 EL 调用的核心机制，各自有不同的 EL 限制和路由规则。

### 4.1 翻译实现

```c
// translate-a64.c:3155-3205

// SVC：系统调用，所有 EL 可执行
static bool trans_SVC(DisasContext *s, arg_i *a)
{
    uint32_t syndrome = syn_aa64_svc(a->imm);
    if (s->fgt_svc) {
        // FEAT_FGT：SVC 可被 trap 到 EL2
        gen_exception_insn_el(s, 0, EXCP_UDEF, syndrome, 2);
        return true;
    }
    gen_ss_advance(s);
    gen_exception_insn(s, 4, EXCP_SWI, syndrome);
    return true;
}

// HVC：Hypervisor 调用，EL1+ 可执行
static bool trans_HVC(DisasContext *s, arg_i *a)
{
    int target_el = s->current_el == 3 ? 3 : 2;
    if (s->current_el == 0) {
        unallocated_encoding(s);  // EL0 不可用
        return true;
    }
    gen_a64_update_pc(s, 0);
    gen_helper_pre_hvc(tcg_env);  // 运行时检查 HCR_EL2.HCD
    gen_ss_advance(s);
    gen_exception_insn_el(s, 4, EXCP_HVC, syn_aa64_hvc(a->imm), target_el);
    return true;
}

// SMC：安全监控调用，EL1+ 可执行
static bool trans_SMC(DisasContext *s, arg_i *a)
{
    if (s->current_el == 0) {
        unallocated_encoding(s);  // EL0 不可用
        return true;
    }
    gen_a64_update_pc(s, 0);
    gen_helper_pre_smc(tcg_env, ...);  // 运行时检查 SCR_EL3.SMD
    gen_ss_advance(s);
    gen_exception_insn_el(s, 4, EXCP_SMC, syn_aa64_smc(a->imm), 3);
    return true;
}
```

### 4.2 路由规则对照表

| 指令 | EL0 | EL1 | EL2 | EL3 | Trap 控制 |
|-----|-----|-----|-----|-----|----------|
| SVC | → EL1 | → EL1 | → EL2 | → EL3 | FGT: fgt_svc → EL2 |
| HVC | UNDEF | → EL2 | → EL2 | → EL3 | HCR_EL2.HCD → UNDEF |
| SMC | UNDEF | → EL3 | → EL3 | → EL3 | SCR_EL3.SMD → UNDEF |

### 4.3 EC 编码

| 指令 | EC (Exception Class) | 值 |
|-----|---------------------|-----|
| SVC | EC_AA64_SVC | 0x15 |
| HVC | EC_AA64_HVC | 0x16 |
| SMC | EC_AA64_SMC | 0x17 |

源码：`syndrome.h:138-159`

## 5. FP/SIMD 指令 Trap 机制

浮点和 SIMD 指令可以通过 CPACR_EL1、CPTR_EL2、CPTR_EL3 三级控制寄存器进行 Trap。

### 5.1 fp_exception_el() — Trap 目标 EL 计算

```c
// helper.c:9844-9948
int fp_exception_el(CPUARMState *env, int cur_el)
{
    // 第一层：CPACR_EL1.FPEN 控制 EL0/EL1 的 FP 访问
    // （仅当 E2H+TGE 未同时设置时生效）
    if ((hcr_el2 & (HCR_E2H | HCR_TGE)) != (HCR_E2H | HCR_TGE)) {
        int fpen = FIELD_EX64(env->cp15.cpacr_el1, CPACR_EL1, FPEN);
        switch (fpen) {
        case 0: case 2:  // trap EL0 和 EL1
            if (cur_el <= 1) return 1;
            break;
        case 1:           // 仅 trap EL0
            if (cur_el == 0) return 1;
            break;
        case 3:           // 不 trap
            break;
        }
    }

    // 第二层：CPTR_EL2 控制 EL0/EL1/EL2 的 FP 访问
    if (cur_el <= 2) {
        if (hcr_el2 & HCR_E2H) {
            // VHE 格式：CPTR_EL2.FPEN 字段（类似 CPACR）
            switch (FIELD_EX64(env->cp15.cptr_el[2], CPTR_EL2, FPEN)) {
            case 0: case 2: return 2;
            case 1: if (cur_el == 0 && (hcr_el2 & HCR_TGE)) return 2;
            }
        } else {
            // 非 VHE：CPTR_EL2.TFP 位
            if (FIELD_EX64(env->cp15.cptr_el[2], CPTR_EL2, TFP))
                return 2;
        }
    }

    // 第三层：CPTR_EL3.TFP 控制所有 EL
    if (FIELD_EX64(env->cp15.cptr_el[3], CPTR_EL3, TFP))
        return 3;

    return 0;  // FP 可用
}
```

### 5.2 翻译时 Trap 检查

```c
// translate-a64.c:1430-1458
static bool fp_access_check_only(DisasContext *s)
{
    if (s->fp_excp_el) {
        // fp_excp_el 已在 TB flags 中预计算
        gen_exception_insn_el(s, 0, EXCP_UDEF,
                              syn_fp_access_trap(1, 0xe, false, 0),
                              s->fp_excp_el);
        return false;  // 指令不翻译
    }
    s->fp_access_checked = 1;
    return true;
}

static bool fp_access_check(DisasContext *s)
{
    return fp_access_check_only(s) && nonstreaming_check(s);
}
```

**EC**: `EC_FPIDTRAP` = 0x08，通过 `syn_fp_access_trap()` 生成。

### 5.3 Trap 控制位对照表

| 控制寄存器 | 字段 | 值 | 效果 |
|-----------|------|-----|------|
| CPACR_EL1 | FPEN | 0/2 | trap EL0+EL1 到 EL1 |
| CPACR_EL1 | FPEN | 1 | 仅 trap EL0 到 EL1 |
| CPACR_EL1 | FPEN | 3 | 不 trap |
| CPTR_EL2 | TFP (非 VHE) | 1 | trap EL0/EL1/EL2 到 EL2 |
| CPTR_EL2 | FPEN (VHE) | 0/2 | trap EL0/EL1/EL2 到 EL2 |
| CPTR_EL3 | TFP | 1 | trap 所有 EL 到 EL3 |

## 6. SVE 指令 Trap 机制

SVE (Scalable Vector Extension) 指令有独立于 FP/SIMD 的 Trap 控制。

### 6.1 sve_exception_el() — SVE Trap 目标计算

```c
// helper.c:4598-4641
int sve_exception_el(CPUARMState *env, int el)
{
    // 第一层：CPACR_EL1.ZEN 控制 EL0/EL1
    if (el <= 1 && !el_is_in_host(env, el)) {
        switch (FIELD_EX64(env->cp15.cpacr_el1, CPACR_EL1, ZEN)) {
        case 0: case 2: return 1;     // trap EL0+EL1 到 EL1
        case 1: if (el == 0) return 1; // 仅 trap EL0
        }
    }

    // 第二层：CPTR_EL2 控制
    if (el <= 2 && arm_is_el2_enabled(env)) {
        if (env->cp15.hcr_el2 & HCR_E2H) {
            // VHE 格式：CPTR_EL2.ZEN 字段
            switch (FIELD_EX64(env->cp15.cptr_el[2], CPTR_EL2, ZEN)) {
            case 0: case 2: return 2;
            case 1: if (el == 0 && (hcr & HCR_TGE)) return 2;
            }
        } else {
            // 非 VHE：CPTR_EL2.TZ 位
            if (FIELD_EX64(env->cp15.cptr_el[2], CPTR_EL2, TZ))
                return 2;
        }
    }

    // 第三层：CPTR_EL3.EZ 控制（注意 EZ 是负逻辑）
    if (arm_feature(env, ARM_FEATURE_EL3)
        && !FIELD_EX64(env->cp15.cptr_el[3], CPTR_EL3, EZ))
        return 3;

    return 0;
}
```

### 6.3 SVE 与 FP 的优先级关系

```
如果 fp_excp_el != 0 且 sve_excp_el > fp_excp_el：
  → FP 异常优先，sve_excp_el 被强制置 0
  → 因为 FP 异常会先触发，无需生成 SVE trap

逻辑在 hflags.c:273-276：
  if (fp_el != 0) {
      if (sve_el > fp_el) {
          sve_el = 0;  // FP trap 优先
      }
  }
```

## 8. ERET 指令的 EL 限制

ERET（Exception Return）仅在 EL1+ 可执行。

### 8.1 翻译实现

```c
// translate-a64.c:1951-1975
static bool trans_ERET(DisasContext *s, arg_ERET *a)
{
    if (s->current_el == 0) {
        return false;  // EL0 → unallocated encoding
    }
    if (s->trap_eret) {
        // FEAT_FGT：ERET 被 trap 到 EL2
        gen_exception_insn_el(s, 0, EXCP_UDEF, syn_erettrap(0), 2);
        return true;
    }
    // 加载 ELR_ELx 作为返回地址
    tcg_gen_ld_i64(dst, tcg_env,
                   offsetof(CPUARMState, elr_el[s->current_el]));
    gen_helper_exception_return(tcg_env, dst);
    s->base.is_jmp = DISAS_EXIT;
    return true;
}
```

### 8.2 ERETAA/ERETAB（指针认证变体）

```c
// translate-a64.c:1978-2007
static bool trans_ERETA(DisasContext *s, arg_reta *a)
{
    if (!dc_isar_feature(aa64_pauth, s)) return false;
    if (s->current_el == 0) return false;
    if (s->trap_eret) {
        gen_exception_insn_el(s, 0, EXCP_UDEF,
                              syn_erettrap(a->m ? 3 : 2), 2);
        return true;
    }
    // 先加载 ELR，再进行指针认证
    dst = auth_branch_target(s, dst, cpu_X[31], !a->m);
    gen_helper_exception_return(tcg_env, dst);
    ...
}
```

**关键差异**：
- `ERET`：EC = `syn_erettrap(0)` → syndrome = 0
- `ERETAA`：EC = `syn_erettrap(2)` → PACIASP 认证
- `ERETAB`：EC = `syn_erettrap(3)` → PACIBSP 认证

## 10. CPAccessRights 权限位矩阵

```c
// cpregs.h:307-333
typedef enum {
    PL3_R = 0x80,                    // 仅 EL3 可读
    PL3_W = 0x40,                    // 仅 EL3 可写
    PL2_R = 0x20 | PL3_R,           // EL2+ 可读 (0xA0)
    PL2_W = 0x10 | PL3_W,           // EL2+ 可写 (0x50)
    PL1_R = 0x08 | PL2_R,           // EL1+ 可读 (0xA8)
    PL1_W = 0x04 | PL2_W,           // EL1+ 可写 (0x54)
    PL0_R = 0x02 | PL1_R,           // EL0+ 可读 (0xAA)
    PL0_W = 0x01 | PL1_W,           // EL0+ 可写 (0x55)

    PL3_RW = PL3_R | PL3_W,         // 0xC0
    PL2_RW = PL2_R | PL2_W,         // 0xF0
    PL1_RW = PL1_R | PL1_W,         // 0xFC
    PL0_RW = PL0_R | PL0_W,         // 0xFF
} CPAccessRights;
```

位布局设计使得 **高 EL 自动包含低 EL 的所有权限位**：

```
位 [7:0] 对应:
  bit 7: PL3 read     bit 6: PL3 write
  bit 5: PL2 read     bit 4: PL2 write
  bit 3: PL1 read     bit 2: PL1 write
  bit 1: PL0 read     bit 0: PL0 write

索引计算: (current_el * 2) + isread
  EL0 read  = bit 1    EL0 write = bit 0
  EL1 read  = bit 3    EL1 write = bit 2
  EL2 read  = bit 5    EL2 write = bit 4
  EL3 read  = bit 7    EL3 write = bit 6
```

## 11. cp_access_ok() 静态权限检查

```c
// cpregs.h:1122-1126
static inline bool cp_access_ok(int current_el,
                                const ARMCPRegInfo *ri, int isread)
{
    return (ri->access >> ((current_el * 2) + isread)) & 1;
}
```

这是整个系统寄存器访问控制的**第一道门**。极其简洁 —— 仅一次位移和位测试。

**示例**：
- `SCTLR_EL1` 的 `.access = PL1_RW` (0xFC)
  - EL0 read: `(0xFC >> 1) & 1 = 0` → **拒绝**
  - EL1 write: `(0xFC >> 2) & 1 = 1` → **允许**
  - EL3 read: `(0xFC >> 7) & 1 = 1` → **允许**

- `CTR_EL0` 的 `.access = PL0_R` (0xAA)
  - EL0 read: `(0xAA >> 1) & 1 = 1` → **允许**
  - EL0 write: `(0xAA >> 0) & 1 = 0` → **拒绝**

## 13. CPAccessResult 结果与异常路由

```c
// cpregs.h:335-375
typedef enum CPAccessResult {
    CP_ACCESS_OK = 0,           // 允许访问

    CP_ACCESS_EL_MASK = 3,      // 低 2 位编码目标 EL

    // 带 syndrome 的 Trap（直接指定目标 EL）
    CP_ACCESS_TRAP_BIT = (1 << 2),
    CP_ACCESS_TRAP_EL1 = CP_ACCESS_TRAP_BIT | 1,  // 0x05
    CP_ACCESS_TRAP_EL2 = CP_ACCESS_TRAP_BIT | 2,  // 0x06
    CP_ACCESS_TRAP_EL3 = CP_ACCESS_TRAP_BIT | 3,  // 0x07

    // UNDEF（无 syndrome，路由到默认目标 EL）
    CP_ACCESS_UNDEFINED = (2 << 2),  // 0x08

    // GCS EXLOCK 异常
    CP_ACCESS_EXLOCK = (3 << 2),     // 0x0C
} CPAccessResult;
```

### 13.1 异常路由处理

```c
// op_helper.c:895-957
// 处理 accessfn 返回的 CPAccessResult

fail:
    excp = EXCP_UDEF;
    switch (res) {
    case CP_ACCESS_TRAP_EL3:
        // AArch32 EL3 无 syndrome → 使用 EXCP_MON_TRAP
        if (!arm_el_is_aa64(env, 3))
            excp = EXCP_MON_TRAP;
        break;

    case CP_ACCESS_TRAP_EL2:
    case CP_ACCESS_TRAP_EL1:
        break;  // 使用默认 EXCP_UDEF + syndrome

    case CP_ACCESS_UNDEFINED:
        // FEAT_IDST：ID 空间寄存器使用 EC_SYSTEMREGISTERTRAP
        if (cpu_isar_feature(aa64_ids, cpu) && isread
            && arm_cpreg_in_idspace(ri)) {
            break;  // 保留原始 syndrome
        }
        syndrome = syn_uncategorized();  // EC = 0x00
        break;

    case CP_ACCESS_EXLOCK:
        syndrome = syn_gcs_exlock();
        break;
    }

    // 从结果中提取目标 EL
    target_el = res & CP_ACCESS_EL_MASK;
    if (target_el == 0) {
        target_el = exception_target_el(env);  // 默认目标
    }

    raise_exception(env, excp, syndrome, target_el);
```

## 15. VHE 寄存器重定向

VHE (Virtualization Host Extensions) 通过 `HCR_EL2.E2H=1` 使 Host OS 可以直接运行在 EL2，此时 EL1 寄存器访问被重定向到 EL2 版本。

### 15.1 重定向逻辑

```c

    // 从 EL2 访问 FOO_EL1 → 重定向到 FOO_EL2
    key = ri->vhe_redir_to_el2;
    ri = redirect_cpreg(s, key, isread);
} else if (ri->vhe_redir_to_el01 && s->current_el >= 2) {
    // 从 EL2/EL3 访问 FOO_EL12 → 重定向到 FOO_EL1
    if (!s->e2h) {
        gen_sysreg_undef(s, ...);  // 无 E2H 时 UNDEF
        return;
    }
    key = ri->vhe_redir_to_el01;
    ri = redirect_cpreg(s, key, isread);
}
```

**示例**：
- EL2 + E2H=1 访问 `SCTLR_EL1` → 实际访问 `SCTLR_EL2`
- EL2 + E2H=1 访问 `SCTLR_EL12` → 实际访问 `SCTLR_EL1`（绕过重定向）

## 17. Cache 维护指令 Trap 机制

Cache 维护指令（DC CIVAC、DC CVAC、IC IVAU 等）有两层 Trap 控制。

### 17.1 Point of Coherency 操作

```c
// helper.c:3145-3165
static CPAccessResult aa64_cacheop_poc_access(CPUARMState *env,
                                              const ARMCPRegInfo *ri,
                                              bool isread)
{
    switch (arm_current_el(env)) {
    case 0:
        // EL0：SCTLR_EL1.UCI=0 时 trap 到 EL1
        if (!(arm_sctlr(env, 0) & SCTLR_UCI))
            return CP_ACCESS_TRAP_EL1;
        /* fall through */
    case 1:
        // EL1：HCR_EL2.TPCP=1 时 trap 到 EL2
        if (arm_hcr_el2_eff(env) & HCR_TPCP)
            return CP_ACCESS_TRAP_EL2;
        break;
    }
    return CP_ACCESS_OK;
}
```

### 17.2 Point of Unification 操作

```c
// helper.c:3167-3197

                                            uint64_t hcrflags)
{

    case 0:

            return CP_ACCESS_TRAP_EL1;

    case 1:

            return CP_ACCESS_TRAP_EL2;

}
```

## 18. DC ZVA 指令的 EL 访问控制

DC ZVA（Data Cache Zero by VA）指令有独立的访问控制，因为它可以用于快速清零内存。

```c
// helper.c:3199-3225
static CPAccessResult aa64_zva_access(CPUARMState *env,
                                      const ARMCPRegInfo *ri,
                                      bool isread)
{
    int cur_el = arm_current_el(env);

    if (cur_el < 2) {
        uint64_t hcr = arm_hcr_el2_eff(env);

        if (cur_el == 0) {
            if ((hcr & (HCR_E2H | HCR_TGE)) == (HCR_E2H | HCR_TGE)) {
                // VHE host EL0：检查 SCTLR_EL2.DZE
                if (!(env->cp15.sctlr_el[2] & SCTLR_DZE))
                    return CP_ACCESS_TRAP_EL2;
            } else {
                // 普通 EL0：检查 SCTLR_EL1.DZE
                if (!(env->cp15.sctlr_el[1] & SCTLR_DZE))
                    return CP_ACCESS_TRAP_EL1;
                // 然后检查 HCR_EL2.TDZ
                if (hcr & HCR_TDZ)
                    return CP_ACCESS_TRAP_EL2;
            }
        } else {
            // EL1：HCR_EL2.TDZ 控制
            if (hcr & HCR_TDZ)
                return CP_ACCESS_TRAP_EL2;
        }
    }
    return CP_ACCESS_OK;
}
```

DC ZVA 的 `.access = PL0_W`，即所有 EL 可执行写操作，但通过 `accessfn` 在运行时限制。

## 21. 调试寄存器 Trap 机制

调试寄存器通过 MDCR_EL2 和 MDCR_EL3 控制 Trap，分为四类访问函数。

### 21.1 四类调试访问检查

```c
// debug_helper.c:18-121

// ① TDOSA：调试 OS 相关寄存器（OSLAR_EL1 等）
static CPAccessResult access_tdosa(...)
{
    // EL2 trap：MDCR_TDOSA || MDCR_TDE || HCR_TGE
    if (el < 2 && mdcr_el2_tdosa) return CP_ACCESS_TRAP_EL2;
    // EL3 trap：MDCR_EL3.TDOSA
    if (el < 3 && (mdcr_el3 & MDCR_TDOSA)) return CP_ACCESS_TRAP_EL3;
}

// ② TDRA：调试 ROM 寄存器
static CPAccessResult access_tdra(...)
{
    // EL2 trap：MDCR_TDRA || MDCR_TDE || HCR_TGE
    if (el < 2 && mdcr_el2_tdra) return CP_ACCESS_TRAP_EL2;
    // EL3 trap：MDCR_EL3.TDA
    if (el < 3 && (mdcr_el3 & MDCR_TDA)) return CP_ACCESS_TRAP_EL3;
}

// ③ TDA：通用调试寄存器（DBGBVR、DBGWVR 等）
static CPAccessResult access_tda(...)
{
    // EL2 trap：MDCR_TDA || MDCR_TDE || HCR_TGE
    if (el < 2 && mdcr_el2_tda) return CP_ACCESS_TRAP_EL2;
    // EL3 trap：MDCR_EL3.TDA
    if (el < 3 && (mdcr_el3 & MDCR_TDA)) return CP_ACCESS_TRAP_EL3;
}

// ④ TDCC：调试通信通道（DBGDTR/DBGDCC）
static CPAccessResult access_tdcc(...)
{
    // EL0 → EL1：MDSCR_EL1.TDCC
    if (el < 1 && mdscr_el1_tdcc) return CP_ACCESS_TRAP_EL1;
    // EL1 → EL2：MDCR_EL2.TDA || TDE || TGE || TDCC
    if (el < 2 && (mdcr_el2_tda || mdcr_el2_tdcc))
        return CP_ACCESS_TRAP_EL2;
    // → EL3：MDCR_EL3.TDA || TDCC
    if (!arm_is_el3_or_mon(env) && (mdcr_el3_tda || mdcr_el3_tdcc))
        return CP_ACCESS_TRAP_EL3;
}
```

### 21.2 Trap 控制位汇总

| MDCR 字段 | 控制范围 | Trap 目标 |
|-----------|---------|----------|
| MDCR_EL2.TDE | 所有调试访问 | EL2 |
| MDCR_EL2.TDA | 通用调试寄存器 | EL2 |
| MDCR_EL2.TDRA | 调试 ROM 寄存器 | EL2 |
| MDCR_EL2.TDOSA | 调试 OS 寄存器 | EL2 |
| MDCR_EL2.TDCC | 调试通信通道 | EL2 |
| MDCR_EL3.TDA | 通用调试寄存器 | EL3 |
| MDCR_EL3.TDOSA | 调试 OS 寄存器 | EL3 |
| MDCR_EL3.TDCC | 调试通信通道 | EL3 |
| MDSCR_EL1.TDCC | 调试通信通道 (EL0) | EL1 |
| HCR_EL2.TGE | 全局 trap 增强 | EL2 |

注意：`MDCR_EL2.TDE` 和 `HCR_EL2.TGE` 是"总开关"，它们会激活所有 EL2 调试 trap。

## 25. 总结

### 25.1 核心设计原则

ARM64 异常级别的指令执行差异遵循三个原则：

1. **分层控制**：每层 EL 可通过控制寄存器 trap 低 EL 的操作
   - EL1 通过 SCTLR_EL1 控制 EL0
   - EL2 通过 HCR_EL2/CPTR_EL2/MDCR_EL2 控制 EL0/EL1
   - EL3 通过 SCR_EL3/CPTR_EL3/MDCR_EL3 控制所有 EL

2. **优先级递增**：低 EL 的 trap 检查先于高 EL
   - SCTLR → HCR → SCR 顺序检查，第一个匹配即生效

3. **静态与动态分离**：可在编译时确定的 trap 嵌入 TB flags，动态 trap 推迟到运行时

### 25.2 QEMU 实现的两层架构

