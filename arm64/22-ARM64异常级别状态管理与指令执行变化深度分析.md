# ARM64 异常级别状态管理与指令执行变化深度分析

## 1. 概述

本文深度分析 QEMU 11.0.50 中 ARM64 异常级别（EL0-EL3）切换时 CPU 指令执行行为的变化机制。重点覆盖 TB Flags 中 EL 编码、翻译时特权检查、异常入口/返回的完整状态转换、系统寄存器访问门控、HCR_EL2 陷阱效应。

**关键源文件：**
- `target/arm/tcg/hflags.c` — TB Flags 构建（EL 相关标志）
- `target/arm/tcg/translate-a64.c` — 翻译时 EL 检查、特权指令门控
- `target/arm/tcg/translate.h` — DisasContext（current_el 等字段）
- `target/arm/tcg/helper-a64.c` — ERET 实现
- `target/arm/helper.c` — 异常入口、系统寄存器访问、HCR 陷阱
- `target/arm/cpregs.h` — 访问权限位图
- `target/arm/ptw.c` — EL 相关 MMU regime

## 2. TB Flags 中的 EL 编码

### 2.1 EL 不直接编码

QEMU 的 Translation Block (TB) flags 中，**EL 不作为独立字段存储**。相反，EL 通过以下方式间接编码：

- `MMUIDX` — 当前 MMU 索引（包含 EL 和安全状态信息）
- `FPEXC_EL` — FP 异常陷阱级别
- `SVEEXC_EL` / `SMEEXC_EL` — SVE/SME 异常陷阱级别
- `UNPRIV` — 是否使用 AccType_UNPRIV（LDTR 等）
- `TRAP_ERET` — ERET 是否被陷阱
- `NV/NV1/NV2` — 嵌套虚拟化标志
- `E2H` — VHE 使能

翻译时通过 `arm_mmu_idx_to_el(dc->mmu_idx)` 从 MMUIDX 恢复 EL：
```c
// translate-a64.c:10662
dc->current_el = arm_mmu_idx_to_el(dc->mmu_idx);
```

### 2.2 rebuild_hflags_common()

```c
// hflags.c:77-89
static CPUARMTBFlags rebuild_hflags_common(CPUARMState *env, int fp_el,
                                           ARMMMUIdx mmu_idx, ...)
{
    DP_TBFLAG_ANY(flags, FPEXC_EL, fp_el);    // FP 异常级别
    DP_TBFLAG_ANY(flags, MMUIDX, ...);         // MMU 索引（含 EL）
    if (arm_singlestep_active(env))
        DP_TBFLAG_ANY(flags, SS_ACTIVE, 1);    // 单步状态
}
```

### 2.3 rebuild_hflags_a64() — EL 相关标志

```c

static CPUARMTBFlags rebuild_hflags_a64(CPUARMState *env, int el, ...)
```

按功能分组的 EL 相关标志：

**基础标志（所有 EL）：**
- `AARCH64_STATE` — AArch64 执行状态
- `TBII/TBID` — Tagged address 控制
- `ALIGN_MEM` — 对齐检查
- `BE_DATA` — 大端数据

**特性陷阱级别（由 EL 决定是否陷阱）：**
```c

int sme_el = sme_exception_el(env, el);   // SME 在哪个 EL 陷阱
DP_TBFLAG_A64(flags, SVEEXC_EL, sve_el);
DP_TBFLAG_A64(flags, SMEEXC_EL, sme_el);
```

**EL1 特定标志：**
```c
// hflags.c:345-368 — LDTR UNPRIV 判定
if (mmu_idx == ARMMMUIdx_E10_1 || ARMMMUIdx_E10_1_PAN)
    DP_TBFLAG_A64(flags, UNPRIV, 1);  // EL1 下 LDTR 用 EL0 权限

// hflags.c:388-400 — NV 陷阱（仅 EL1）

```

**ERET 陷阱（FGT 或 NV）：**
```c
// hflags.c:374-378 — FGT 控制 ERET 陷阱
if (arm_fgt_active(env, el)) {
    if (FIELD_EX64(env->cp15.fgt_exec[FGTREG_HFGITR], HFGITR_EL2, ERET))
        DP_TBFLAG_A64(flags, TRAP_ERET, 1);

```

**安全特性（EL 依赖的 SCTLR 字段）：**
```c
// hflags.c:320-337
// PAuth：由 SCTLR.EnIA/EnIB/EnDA/EnDB 控制
if (sctlr & (SCTLR_EnIA | SCTLR_EnIB | SCTLR_EnDA | SCTLR_EnDB))
    DP_TBFLAG_A64(flags, PAUTH_ACTIVE, 1);

// BTI：由 SCTLR.BT0(EL0) / SCTLR.BT1(EL1+) 控制
if (sctlr & (el == 0 ? SCTLR_BT0 : SCTLR_BT1))
```

## 5. 每个 EL 的指令可用性

### 5.1 EL0（用户态）

**可用指令：**
- 所有用户态数据处理、分支、SIMD/FP 指令
- SVC（系统调用，陷阱到 EL1）
- MRS/MSR 对 `PL0_R/PL0_W` 寄存器（NZCV, FPCR, FPSR, TPIDR_EL0 等）
- WFI/WFE（可能被 HCR/SCTLR 陷阱）

**不可用/受限：**
- 所有 PL1+ 系统寄存器 → UNDEF
- DC/IC/TLBI 操作 — 受 SCTLR.UCI、HCR_EL2 陷阱控制
- AT 指令 → UNDEF
- SMC/HVC → UNDEF

### 5.2 EL1（内核态）

**新增可用：**
- MSR/MRS 对 PL1 寄存器（SCTLR_EL1, TCR_EL1, TTBR0/1_EL1, ESR_EL1, FAR_EL1, MAIR_EL1, VBAR_EL1 等）
- DC/IC/TLBI 操作（受 HCR 陷阱控制）
- AT 地址翻译指令
- WFI 不再默认陷阱

**受 HCR_EL2 控制：**
```c
// 以下操作在 EL1 可能被陷阱到 EL2：
HCR.TVM  → 写 SCTLR/TCR/TTBR/MAIR/CONTEXTIDR 陷阱
HCR.TRVM → 读上述寄存器陷阱
HCR.TSW  → 缓存维护（DC ISW/CSW/CISW）陷阱
HCR.TACR → 辅助控制寄存器陷阱
HCR.TTLB → TLB 维护操作陷阱
HCR.TID* → ID 寄存器读取陷阱
HCR.TSC  → SMC 执行陷阱到 EL2
HCR.TWI  → WFI 陷阱到 EL2
HCR.TWE  → WFE 陷阱到 EL2
```

**HVC 指令：**
```c
// translate-a64.c:3173-3189
// HVC 从 EL1 陷阱到 EL2（需要 EL2 存在且 SCR_EL3.HCE=1）
```

### 5.3 EL2（Hypervisor）

**新增可用：**
- MSR/MRS 对 PL2 寄存器（HCR_EL2, VTTBR_EL2, VTCR_EL2, VMPIDR_EL2 等）
- Stage-2 页表管理
- 虚拟中断注入
- VHE 下直接运行 EL0 用户态应用

**VHE（E2H=1）效果：**
- EL1 寄存器名重定向到 EL2 实现
- EL2 可以直接使用 EL1&0 翻译 regime
- LDTR 使用 EL0 权限（`UNPRIV` 标志）

### 5.4 EL3（Secure Monitor / Root）

**新增可用：**
- MSR/MRS 对 PL3 寄存器（SCR_EL3, SCTLR_EL3, VBAR_EL3, TTBR0_EL3 等）
- SMC 处理入口
- 安全世界切换（SCR_EL3.NS/NSE）
- RME：GPCCR_EL3, GPTBR_EL3, MFAR_EL3
- 所有低级别操作均可执行

**SMC 处理：**
```c
// translate-a64.c:3193-3203
// SMC 始终陷阱到 EL3（如果 EL3 存在）
```

## 6. 异常入口（EL 切换）

### 6.1 AArch64 异常入口核心

```c
// helper.c:9198-9420 — arm_cpu_do_interrupt_aarch64()
```

**完整流程：**

**Step 1：确定向量偏移**
```c
// helper.c:9203
addr = env->cp15.vbar_el[new_el];  // VBAR_ELx 基地址

// 向量偏移取决于来源 EL 和执行状态：
if (cur_el < new_el) {
    if (lower_el_is_aa64) addr += 0x400;  // 低级 AArch64
    else                  addr += 0x600;  // 低级 AArch32
} else {
    // 同级异常
    if (pstate & PSTATE_SP)  addr += 0x200;  // 使用 SP_ELx
    // else addr += 0x000                     // 使用 SP_EL0
}
// 再加异常类型偏移：
// Sync: +0x000, IRQ: +0x080, FIQ: +0x100, SError: +0x180
```

**VBAR 向量表布局：**

| 偏移 | SP_EL0 同级 | SP_ELx 同级 | 低级 AArch64 | 低级 AArch32 |
|------|------------|------------|-------------|-------------|
| Sync | 0x000 | 0x200 | 0x400 | 0x600 |
| IRQ | 0x080 | 0x280 | 0x480 | 0x680 |
| FIQ | 0x100 | 0x300 | 0x500 | 0x700 |
| SError | 0x180 | 0x380 | 0x580 | 0x780 |

**Step 2：保存状态**
```c
// helper.c:9343-9369
aarch64_save_sp(env, cur_el);              // 保存当前 SP
env->elr_el[new_el] = env->pc;            // PC → ELR_ELx
old_mode = pstate_read(env);               // 读取完整 PSTATE
env->banked_spsr[spsr_idx] = old_mode;     // PSTATE → SPSR_ELx
```

**Step 3：设置异常综合信息**
```c
// helper.c:9257-9338
// Sync 异常：ESR_ELx = syndrome
env->cp15.esr_el[new_el] = env->exception.syndrome;
// Data/Prefetch Abort：FAR_ELx = fault address
env->cp15.far_el[new_el] = env->exception.vaddress;
```

**Step 4：构造新 PSTATE**
```c
// helper.c:9375-9417
new_mode |= PSTATE_DAIF;  // 屏蔽所有异步异常（D, A, I, F）

// PAN 处理（EL1/EL2）：
if (SCTLR.SPAN == 0) new_mode |= PSTATE_PAN;  // 强制设置 PAN

// MTE：设置 TCO（Tag Check Override）
if (aa64_mte) new_mode |= PSTATE_TCO;

// SSBS：由 SCTLR.DSSBS 决定
if (SCTLR.DSSBS) new_mode |= PSTATE_SSBS;

// NMI：ALLINT 由 SCTLR.SPINTMASK 决定

// 最终写入
pstate_write(env, PSTATE_DAIF | new_mode);
env->aarch64 = true;
aarch64_restore_sp(env, new_el);  // 切换到 SP_ELx
```

### 6.2 典型 EL 转换

**EL0→EL1（SVC/页错误）：**
```
1. PC → ELR_EL1
2. PSTATE → SPSR_EL1
3. ESR_EL1 = syndrome
4. 新 PSTATE = DAIF 全屏蔽 + PAN（如配置）
5. PC = VBAR_EL1 + 0x400（低级 AArch64 同步）
6. SP 切换到 SP_EL1
7. TB Flags 重建：MMUIDX 变为 EL1, FPEXC_EL 可能变化
```

**EL1→EL2（HVC/陷阱）：**
```
1. PC → ELR_EL2
2. PSTATE → SPSR_EL2
3. ESR_EL2 = syndrome（含陷阱原因）
4. 新 PSTATE = DAIF 全屏蔽
5. PC = VBAR_EL2 + 0x400
6. SP 切换到 SP_EL2
7. TB Flags：MMUIDX→EL2, NV/NV1/NV2 标志清除
```

**EL1→EL3（SMC）：**
```
1. PC → ELR_EL3
2. PSTATE → SPSR_EL3
3. ESR_EL3 = SMC syndrome
4. 新 PSTATE = DAIF 全屏蔽
5. PC = VBAR_EL3 + 0x400
6. SP 切换到 SP_EL3
7. 安全空间变为 Root（RME）或 Secure
8. 地址空间可能切换
```

### 7.2 ERET Helper 实现

```c
// helper-a64.c:622-785 — HELPER(exception_return)
```

**完整流程：**

**Step 1：读取 SPSR**
```c
uint64_t spsr = env->banked_spsr[aarch64_banked_spsr_index(cur_el)];
int new_el = el_from_spsr(spsr);  // 从 SPSR.M[3:0] 提取目标 EL
```

**Step 2：合法性检查**
```c
// helper-a64.c:647-680 — 非法返回条件：
if (new_el == -1) goto illegal_return;           // 无效模式编码
if (new_el > cur_el) goto illegal_return;        // 返回更高 EL
if (new_el == 2 && !el2_enabled) goto illegal;   // EL2 未实现
if (cur_el == 3 && SCR_NSE && !SCR_NS) goto illegal; // RME 保留状态
if (arm_el_is_aa64(new_el) != return_to_aa64) goto illegal; // 宽度不匹配
if (new_el == 1 && HCR.TGE) goto illegal_return; // TGE 禁止返回 EL1
```

**Step 3：状态恢复**
```c
// 返回 AArch64：
pstate_write(env, spsr);           // SPSR → PSTATE
aarch64_restore_sp(env, new_el);   // 恢复 SP_ELx
env->pc = new_pc;                  // ELR → PC（含 TBI 处理）
helper_rebuild_hflags_a64(env, new_el);  // 重建 TB Flags

// 返回 AArch32：
cpsr_write_from_spsr_elx(env, spsr);   // SPSR → CPSR
aarch64_sync_64_to_32(env);            // 64→32 寄存器映射
env->regs[15] = new_pc;               // ELR → R15
```

**Step 4：SVE 状态调整**
```c
// helper-a64.c:758
aarch64_sve_change_el(env, cur_el, new_el, return_to_aa64);
// EL 变化可能需要截断/扩展 SVE 寄存器（不同 EL 可能有不同 VL）
```

**Step 5：非法返回处理**
```c
// helper-a64.c:766-785
illegal_return:
    env->pstate |= PSTATE_IL;  // 设置 Illegal 位
    env->pc = new_pc;           // PC 仍然更新
    // 仅恢复 NZCV + DAIF + ALLINT，其余保持
    // EL 不变、SP 不变、执行状态不变
```

## 8. MMU Regime 与 EL

### 8.1 EL 到 MMU Regime 映射

| 当前 EL | MMU Regime | SCTLR | TCR | TTBR0/1 |
|---------|------------|-------|-----|---------|
| EL0 (无 VHE) | EL1&0 | SCTLR_EL1 | TCR_EL1 | TTBR0_EL1 / TTBR1_EL1 |
| EL0 (VHE+TGE) | EL2&0 | SCTLR_EL2 | TCR_EL2 | TTBR0_EL2 / TTBR1_EL2 |
| EL1 | EL1&0 | SCTLR_EL1 | TCR_EL1 | TTBR0_EL1 / TTBR1_EL1 |
| EL2 (无 VHE) | EL2 | SCTLR_EL2 | TCR_EL2 | TTBR0_EL2（仅一个） |
| EL2 (VHE) | EL2&0 | SCTLR_EL2 | TCR_EL2 | TTBR0_EL2 / TTBR1_EL2 |
| EL3 | EL3 | SCTLR_EL3 | TCR_EL3 | TTBR0_EL3（仅一个） |

### 8.2 翻译禁用条件

```c
// ptw.c:282-304
// HCR.TGE 效果：EL0/EL1 的 Stage-1 行为改变
if (HCR_TGE && (EL0 || EL1))
    → Stage-1 如同 SCTLR_EL1.M=0（禁用翻译）

// HCR.DC 效果：
if (HCR_DC && Stage-1 for EL1&0)
    → Stage-1 禁用（直接通过，使用 Normal WB 属性）

// Stage-2：由 HCR.VM 或 HCR.DC 控制
```

### 8.3 SP 选择

每个 EL 可选择使用 `SP_EL0` 或 `SP_ELx`，由 `PSTATE.SP` 位控制：

```c
// PSTATE.SP = 0 → 使用 SP_EL0（所有 EL 共享）
// PSTATE.SP = 1 → 使用 SP_ELx（当前 EL 的专用 SP）
// EL0 始终使用 SP_EL0

// 异常入口时默认选择 SP_ELx（PSTATE.SP=1）
// ERET 恢复 SPSR 中保存的 SP 选择
```

## 9. HCR_EL2 对 EL1 指令行为的影响

### 9.1 HCR_EL2 陷阱位汇总

| HCR 位 | 效果 | 影响的 EL1 操作 |
|--------|------|----------------|
| TVM | 写陷阱 | SCTLR, TCR, TTBR0/1, MAIR, CONTEXTIDR, AMAIR |
| TRVM | 读陷阱 | 同上（读操作） |
| TSW | 陷阱 | DC ISW/CSW/CISW（缓存维护） |
| TACR | 陷阱 | ACTLR_EL1 |
| TTLB | 陷阱 | 所有 TLB 维护操作 |
| TID0-3 | 陷阱 | ID 寄存器读取 |
| TSC | 陷阱 | SMC 指令 |
| TWI | 陷阱 | WFI 指令 |
| TWE | 陷阱 | WFE 指令 |
| TGE | 路由 | EL0 异常全部路由到 EL2 |
| VM | 使能 | Stage-2 翻译 |
| DC | 使能 | 默认缓存（禁用 Stage-1） |
| NV/NV1/NV2 | 嵌套虚拟化 | EL1 的 EL2 寄存器访问被重定向 |
| E2H | VHE | EL2 使用 EL1&0 翻译 regime |

## 10. EL 切换对指令执行的完整影响

### 10.1 状态变化总结

| 变化项 | EL0→EL1 | EL1→EL2 | EL1→EL3 |
|--------|---------|---------|---------|
| **PSTATE.DAIF** | 全屏蔽 | 全屏蔽 | 全屏蔽 |
| **PSTATE.SP** | →SP_EL1 | →SP_EL2 | →SP_EL3 |
| **PSTATE.PAN** | SCTLR.SPAN 控制 | SCTLR.SPAN | 保持 |
| **PSTATE.TCO** | 设置（MTE） | 设置 | 设置 |
| **MMUIDX** | EL0→EL1&0 | EL1→EL2 | EL1→EL3 |
| **可访问寄存器** | +PL1 全部 | +PL2 全部 | +PL3 全部 |
| **MMU regime** | 不变（EL1&0） | 切换到 EL2 | 切换到 EL3 |
| **Stage-2** | 受控 | 控制者 | 不适用 |
| **安全空间** | 不变 | 不变 | →Root/Secure |
| **地址空间** | 不变 | 可能变化 | 可能切换 |
| **SVE VL** | 可能变化 | 可能变化 | 可能变化 |
| **TB Flags** | 完全重建 | 完全重建 | 完全重建 |

### 10.2 TB Flags 重建触发

每次 EL 变化后，`arm_rebuild_hflags()` 被调用：
```c
// helper.c:9419-9420（异常入口后）
arm_rebuild_hflags(env);

// helper-a64.c:728（ERET 后）
helper_rebuild_hflags_a64(env, new_el);
```

这确保了新的 Translation Block 使用正确的 EL 相关标志生成代码。

## 11. 小结

| 机制 | 实现位置 | 核心功能 |
|------|----------|----------|
| **TB Flags EL 编码** | hflags.c:240-430 | MMUIDX 间接编码 EL，缓存陷阱/特性状态 |
| **DisasContext** | translate.h:85-160 | current_el + fp/sve/sme_excp_el + trap_eret |
| **寄存器访问权限** | cpregs.h:307-333 | PL0-PL3 位图 + accessfn 动态检查 |
| **异常入口** | helper.c:9198-9420 | VBAR+偏移、SPSR/ELR 保存、PSTATE 重构 |
| **异常返回** | helper-a64.c:622-785 | SPSR→PSTATE、ELR→PC、非法返回检测 |
| **HCR 陷阱** | helper.c:333-363 | TVM/TRVM/TSW/TACR → EL1 操作陷阱到 EL2 |
| **MMU Regime** | ptw.c:163-304 | EL→regime 映射、TGE/DC 翻译禁用 |

**关键设计原则：**
1. EL 通过 MMUIDX 间接编码到 TB Flags，避免直接暴露 EL 字段
2. 陷阱状态（TRAP_ERET, NV, FGT）缓存到 TB Flags，加速翻译
3. 异常入口始终屏蔽 DAIF 并切换到 SP_ELx
4. ERET 有 7 种非法返回条件检查，非法返回设置 PSTATE.IL
5. HCR_EL2 的陷阱位可全面改变 EL1 的指令行为，是虚拟化的核心
6. 每次 EL 变化后必须重建 TB Flags，确保后续翻译正确
