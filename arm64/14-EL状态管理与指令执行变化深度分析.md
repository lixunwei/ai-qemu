# ARM64 EL 状态管理与指令执行变化深度分析

## 1. 概述

ARM64 架构定义了四个异常级别（Exception Level, EL0-EL3），不同 EL 下 CPU 的指令执行行为有本质区别。QEMU 通过 `CPUARMState` 中的 `pstate`、`aarch64`、`hflags` 等字段精确模拟了这一行为，并在异常进入/返回时完整实现了 EL 切换的所有副作用。

**关键源文件：**
| 文件 | 职责 |
|------|------|
| `cpu.h:270-284,1546-1581` | PSTATE 定义、模式常量 |
| `internals.h:451-515` | `arm_el_is_aa64()` / `arm_current_el()` |
| `helper.c:9198-9428` | 异常进入主函数 `arm_cpu_do_interrupt_aarch64()` |
| `helper-a64.c:584-785` | 异常返回 `HELPER(exception_return)` |
| `hflags.c:240-524` | TB flags 重建（EL 敏感） |
| `op_helper.c:802-957` | 系统寄存器访问检查 |
| `op_helper.c:1111-1200` | SMC 预处理 |
| `cpu-irq.c:15-260` | 中断路由与屏蔽 |
| `mmuidx.h:1-170` | MMU 索引定义（22 种） |
| `helper.c:10131-10187` | 安全状态判定 |

## 2. EL 状态在 CPU 中的表示

### 2.1 PSTATE 与 EL 提取

```c
// cpu.h:283-284
uint64_t pstate;    // 存储 AArch64 PSTATE（SPSR 格式）
bool aarch64;       // True = AArch64 状态; PSTATE.nRW 的反转

// internals.h:489-498 — arm_current_el()
if (is_a64(env)) {
    return extract32(env->pstate, 2, 2);  // PSTATE.M[3:2] = EL
}
```

**AArch64 PSTATE.M 编码：**
| 值 | 常量 | 含义 |
|----|------|------|
| 0  | `PSTATE_MODE_EL0t` | EL0 (SP_EL0) |
| 4  | `PSTATE_MODE_EL1t` | EL1 使用 SP_EL0 |
| 5  | `PSTATE_MODE_EL1h` | EL1 使用 SP_EL1 |
| 8  | `PSTATE_MODE_EL2t` | EL2 使用 SP_EL0 |
| 9  | `PSTATE_MODE_EL2h` | EL2 使用 SP_EL2 |
| 12 | `PSTATE_MODE_EL3t` | EL3 使用 SP_EL0 |
| 13 | `PSTATE_MODE_EL3h` | EL3 使用 SP_EL3 |

### 2.2 PSTATE 位域分布

```c
// cpu.h:1550-1573
#define PSTATE_SP       (1U)        // bit 0: SP 选择（0=SP_EL0, 1=SP_ELx）
#define PSTATE_M        (0xFU)      // bits [3:0]: 模式域
#define PSTATE_nRW      (1U << 4)   // bit 4: 执行状态（0=AArch64,1=AArch32）
#define PSTATE_F        (1U << 6)   // FIQ 屏蔽
#define PSTATE_I        (1U << 7)   // IRQ 屏蔽
#define PSTATE_A        (1U << 8)   // SError 屏蔽
#define PSTATE_D        (1U << 9)   // Debug 屏蔽
#define PSTATE_SSBS     (1U << 12)  // 推测存储旁路安全
#define PSTATE_ALLINT   (1U << 13)  // 全中断屏蔽（FEAT_NMI）
#define PSTATE_IL       (1U << 20)  // 非法执行状态
#define PSTATE_SS       (1U << 21)  // 软件单步
#define PSTATE_PAN      (1U << 22)  // 特权访问永不（FEAT_PAN）
#define PSTATE_UAO      (1U << 23)  // 用户访问覆盖（FEAT_UAO）
#define PSTATE_DIT      (1U << 24)  // 数据无关时序
#define PSTATE_TCO      (1U << 25)  // Tag Check 覆盖（FEAT_MTE）
#define PSTATE_EXLOCK   (1ULL<<34)  // 执行锁（FEAT_GCS）
#define PSTATE_DAIF     (D|A|I|F)   // 合并的异常屏蔽
```

### 2.3 PSTATE 字段分散存储

QEMU 并非将所有 PSTATE 位集中存储，而是分散到多个字段以提高访问效率：

| PSTATE 位 | 实际存储位置 | 说明 |
|-----------|------------|------|
| NZCV | `env->CF/VF/NF/ZF` | 条件标志位分散存储 |
| nRW (M[4]) | `env->aarch64`（取反） | 执行状态 |
| DAIF | `env->daif` | 异常屏蔽 |
| BTYPE | `env->btype` | BTI 分支类型 |
| SM, ZA | `env->svcr` | SME 状态 |
| 其余位 | `env->pstate` | 原位存储 |

读取完整 PSTATE 需要调用 `pstate_read(env)` 将分散字段合并。

### 2.4 AArch64/AArch32 判定

```c
// internals.h:452-483 — arm_el_is_aa64()
static inline bool arm_el_is_aa64(CPUARMState *env, int el)
{
    bool aa64 = arm_feature(env, ARM_FEATURE_AARCH64);
    if (el == 3) return aa64;           // EL3 宽度 = CPU 最高支持
    if (arm_feature(env, ARM_FEATURE_EL3))
        aa64 = aa64 && arm_scr_rw_eff(env);  // SCR_EL3.RW 控制 EL2
    if (el == 2) return aa64;
    if (arm_is_el2_enabled(env))
        aa64 = aa64 && (env->cp15.hcr_el2 & HCR_RW);  // HCR_EL2.RW 控制 EL1
    return aa64;
}
```

**层级控制模型：**
```
EL3 宽度 = ARM_FEATURE_AARCH64（CPU 固有属性）
  └─ SCR_EL3.RW → EL2 宽度
       └─ HCR_EL2.RW → EL1 宽度
            └─ EL0 宽度 = 当前指令集状态（动态切换）
```

### 2.5 安全状态与 EL 的交互

```c
// helper.c:10131-10161 — arm_security_space()
if (is_a64(env)) {
    if (extract32(env->pstate, 2, 2) == 3) {  // 在 EL3
        if (cpu_isar_feature(aa64_rme, ...))
            return ARMSS_Root;      // RME: EL3 = Root
        else
            return ARMSS_Secure;    // 传统: EL3 = Secure
    }
}
return arm_security_space_below_el3(env);  // SCR_EL3.{NS,NSE} 决定

// helper.c:10163-10187 — arm_security_space_below_el3()

if (scr_el3 & SCR_NSE)    return ARMSS_Realm;    // FEAT_RME
else                       return ARMSS_NonSecure;
```

**安全状态 × EL 矩阵：**
| 安全状态 | 可用 EL | 控制寄存器 |
|---------|--------|-----------|
| Root | EL3 | FEAT_RME |
| Secure | EL0/EL1/EL2(SEL2)/EL3 | SCR_EL3.NS=0 |
| NonSecure | EL0/EL1/EL2 | SCR_EL3.NS=1, NSE=0 |
| Realm | EL0/EL1/EL2 | SCR_EL3.NS=1, NSE=1 (FEAT_RME) |

## 3. 异常进入：EL 提升的完整流程

### 3.1 目标 EL 确定

```c
// op_helper.c:32-45 — 基本规则
target_el = max(1, current_EL);  // EL0 异常最低到 EL1
```

目标 EL 的精确确定涉及多个因素：
- **同步异常**：由指令触发，目标 EL 由指令类型和路由配置决定
  - SVC → EL1（或 EL2 如果 HCR_TGE）
  - HVC → EL2
  - SMC → EL3
- **异步异常（中断）**：由 SCR_EL3 和 HCR_EL2 路由位决定
  - IRQ: SCR_EL3.IRQ=1 → EL3; HCR_EL2.IMO=1 → EL2; 否则 → EL1
  - FIQ: SCR_EL3.FIQ=1 → EL3; HCR_EL2.FMO=1 → EL2; 否则 → EL1

### 3.2 向量地址计算

```c
// helper.c:9198-9255
vaddr addr = env->cp15.vbar_el[new_el];  // 向量基址

if (cur_el < new_el) {
    // 从低 EL 进入高 EL
    if (lower_el_is_aarch64)
        addr += 0x400;   // 低 EL 是 AArch64
    else
        addr += 0x600;   // 低 EL 是 AArch32
} else {
    // 同 EL 内的异常
    if (pstate_read(env) & PSTATE_SP)
        addr += 0x200;   // 使用 SP_ELx
    // else addr += 0x000 — 使用 SP_EL0
}

// 异常类型偏移（在上述基础上叠加）
switch (exception_type) {
    case Synchronous:  addr += 0x000; break;
    case IRQ/VIRQ:     addr += 0x080; break;
    case FIQ/VFIQ:     addr += 0x100; break;
    case SError/VSerr: addr += 0x180; break;
}
```

**向量表布局（每个 VBAR_ELx）：**
```
偏移      同EL SP_EL0  同EL SP_ELx  低EL AArch64  低EL AArch32
+0x000    Sync         -           -             -
+0x080    IRQ          -           -             -
+0x100    FIQ          -           -             -
+0x180    SError       -           -             -
+0x200    -            Sync        -             -
+0x280    -            IRQ         -             -
+0x300    -            FIQ         -             -
+0x380    -            SError      -             -
+0x400    -            -           Sync          -
+0x480    -            -           IRQ           -
+0x500    -            -           FIQ           -
+0x580    -            -           SError        -
+0x600    -            -           -             Sync
+0x680    -            -           -             IRQ
+0x700    -            -           -             FIQ
+0x780    -            -           -             SError
```

### 3.3 状态保存

```c
// helper.c:9343-9369
if (is_a64(env)) {
    old_mode = pstate_read(env);            // 完整 PSTATE
    aarch64_save_sp(env, arm_current_el(env));  // 保存当前 SP
    env->elr_el[new_el] = env->pc;          // 返回地址
} else {
    old_mode = cpsr_read_for_spsr_elx(env); // AArch32 CPSR
    env->elr_el[new_el] = env->regs[15];   // R15/PC
    aarch64_sync_32_to_64(env);             // 寄存器组映射到 64 位
}
env->banked_spsr[aarch64_banked_spsr_index(new_el)] = old_mode;
```

**保存的关键状态：**
- `SPSR_ELx` ← 完整 PSTATE/CPSR（包含 NZCV、DAIF、EL、SP 选择等）
- `ELR_ELx` ← 异常返回地址（被中断指令的 PC）
- `ESR_ELx` ← 异常综合信息（syndrome）

### 3.4 PSTATE 修改（异常进入时）

```c
// helper.c:9375-9417
uint64_t new_mode = aarch64_pstate_mode(new_el, true);  // ELxh 模式

// PAN 处理
new_mode |= old_mode & PSTATE_PAN;  // 默认保留
if (new_el == 1 || (new_el == 2 && VHE)) {
    if (!(sctlr_el[new_el] & SCTLR_SPAN))
        new_mode |= PSTATE_PAN;     // SPAN=0 → 强制设置 PAN
}

// MTE: TCO=1 (禁止 Tag 检查)
if (aa64_mte) new_mode |= PSTATE_TCO;

// SSBS: 由 SCTLR.DSSBS 控制
if (sctlr & SCTLR_DSSBS_64)  new_mode |= PSTATE_SSBS;
else                          new_mode &= ~PSTATE_SSBS;

// NMI/ALLINT
if (!(sctlr & SCTLR_SPINTMASK))  new_mode |= PSTATE_ALLINT;

// 最终写入：设置 DAIF 全屏蔽
pstate_write(env, PSTATE_DAIF | new_mode);
env->aarch64 = true;               // 进入 AArch64
aarch64_restore_sp(env, new_el);   // 切换到 SP_ELx
arm_rebuild_hflags(env);           // 重建 TB flags
env->pc = addr;                    // 跳转到向量入口
```

**异常进入时 PSTATE 变化总结：**
| 位域 | 变化 | 说明 |
|------|------|------|
| M[3:0] | → new_el + SP_ELx | 设置目标 EL，使用 SP_ELx |
| nRW | → 0 | 进入 AArch64 |
| DAIF | → 全1 (0xF) | 屏蔽所有异步异常 |
| PAN | 保留或设置 | SCTLR.SPAN=0 时强制设置 |
| TCO | → 1 | 禁止 MTE 检查 |
| SSBS | ← SCTLR.DSSBS | 按配置设置 |
| ALLINT | ← SCTLR.SPINTMASK | 按配置设置 |
| IL | → 0 | 清除非法状态 |
| SS | → 0 | 清除单步 |
| BTYPE | → 0 | 清除 BTI 类型 |

## 4. 异常返回：EL 降低的完整流程

### 4.1 ERET 实现

```c

int cur_el = arm_current_el(env);
uint64_t spsr = env->banked_spsr[aarch64_banked_spsr_index(cur_el)];
int new_el = el_from_spsr(spsr);         // 从 SPSR 提取目标 EL
bool return_to_aa64 = (spsr & PSTATE_nRW) == 0;
```

### 4.2 目标 EL 验证

```c
// helper-a64.c:584-620 — el_from_spsr()
if (spsr & PSTATE_nRW) {
    // AArch32 返回：mode → EL 映射
    USR → EL0; HYP → EL2; FIQ/IRQ/SVC/ABT/UND/SYS → EL1
    MON → -1 (非法)
} else {
    // AArch64 返回：SPSR.M[3:2] = EL
    return extract32(spsr, 2, 2);
}

// 合法性检查 (helper-a64.c:646-691):
if (new_el > cur_el) → illegal_return       // 不能返回到更高 EL
if (new_el == 2 && !EL2_enabled) → illegal  // EL2 未使能
if (width_mismatch) → illegal               // AArch64/32 配置不匹配
if (new_el == 1 && HCR_TGE) → illegal       // TGE 下 EL1 不存在
```

### 4.3 状态恢复

```c
// 返回到 AArch64 (helper-a64.c:718-751):
env->aarch64 = true;
pstate_write(env, spsr & valid_mask);   // 恢复 PSTATE
aarch64_restore_sp(env, new_el);        // 切换到目标 EL 的 SP
helper_rebuild_hflags_a64(env, new_el); // 重建 hflags
// TBI 处理后设置 PC
env->pc = new_pc;

// 返回到 AArch32 (helper-a64.c:697-717):
env->aarch64 = false;
cpsr_write_from_spsr_elx(env, spsr);    // 恢复 CPSR
aarch64_sync_64_to_32(env);             // 64→32 寄存器映射
env->regs[15] = new_pc & ~0x1/~0x3;    // PC 对齐
helper_rebuild_hflags_a32(env, new_el);
```

### 4.4 非法返回处理

```c
// helper-a64.c:766-785
illegal_return:
    env->pstate |= PSTATE_IL;                    // 设置非法状态位
    env->pc = new_pc;                            // 仍然使用 ELR
    // 仅恢复 NZCV + DAIF + ALLINT，其余不变
    spsr &= PSTATE_NZCV | PSTATE_DAIF | PSTATE_ALLINT;
    spsr |= pstate_read(env) & ~(PSTATE_NZCV | PSTATE_DAIF | PSTATE_ALLINT);
    pstate_write(env, spsr);
    // 不改变 EL、执行状态、SP
```

## 5. 不同 EL 下的指令执行差异

### 5.1 翻译体制与 MMU 索引

QEMU 为不同 EL 分配独立的 MMU 索引，共 22 种 `ARMMMUIdx`：

```c
// mmuidx.h:137-170
ARMMMUIdx_E10_0      // EL0 在 EL1&0 体制下（用户态）
ARMMMUIdx_E10_1      // EL1 在 EL1&0 体制下（内核态）
ARMMMUIdx_E10_1_PAN  // EL1 + PAN 启用
ARMMMUIdx_E20_0      // EL0 在 EL2&0 体制下（VHE 用户态）
ARMMMUIdx_E20_2      // EL2 在 EL2&0 体制下（VHE 内核态）
ARMMMUIdx_E20_2_PAN  // EL2 + PAN（VHE）
ARMMMUIdx_E2         // EL2 独立体制（非 VHE）
ARMMMUIdx_E3         // EL3 体制
ARMMMUIdx_E30_0      // AArch32 Secure EL0
```

**EL → 翻译体制映射：**
| 当前 EL | HCR 配置 | 翻译体制 | Stage-1 | Stage-2 |
|---------|---------|---------|---------|---------|
| EL0 | 无 VHE | EL1&0 | TTBR0_EL1 | VTTBR_EL2 |
| EL0 | VHE (E2H+TGE) | EL2&0 | TTBR0_EL2 | 无 |
| EL1 | - | EL1&0 | TTBR0/1_EL1 | VTTBR_EL2 |
| EL2 | 无 VHE | EL2 | TTBR0_EL2 | 无 |
| EL2 | VHE | EL2&0 | TTBR0/1_EL2 | 无 |
| EL3 | - | EL3 | TTBR0_EL3 | 无 |

### 5.2 TB Flags 与翻译块缓存

```c
// hflags.c:506-524 — rebuild_hflags_internal()
int el = arm_current_el(env);
ARMMMUIdx mmu_idx = arm_mmu_idx_el(env, el);  // EL → MMU 索引

// hflags.c:240-503 — rebuild_hflags_a64()

DP_TBFLAG_A64(flags, UNPRIV, ...);   // LDTR 行为
DP_TBFLAG_A64(flags, TRAP_ERET, ..); // ERET 是否陷入
DP_TBFLAG_A64(flags, NV/NV1/NV2,..); // 嵌套虚拟化
```

**关键影响**：不同 EL 产生不同的 hflags，导致 QEMU 为每个 EL/配置组合维护独立的翻译块缓存。EL 切换后必须调用 `arm_rebuild_hflags()` 使新的 TB 可以被正确查找。

### 5.3 系统寄存器访问控制

```c
// op_helper.c:802-957 — HELPER(access_check_cp_reg)
// 三层检查机制：

// 第一层：accessfn（寄存器自定义访问函数）
res = ri->accessfn(env, ri, isread);
// 典型返回: CP_ACCESS_OK / CP_ACCESS_TRAP_EL2 / CP_ACCESS_UNDEFINED

// 第二层：HSTR_EL2（EL0 的 CP15 寄存器访问陷入 EL2）
if (arm_current_el(env) == 0 && ri->cp == 15) {
    if (env->cp15.hstr_el2 & (1 << ri->crn))
        res = CP_ACCESS_TRAP_EL2;
}

// 第三层：Fine-Grained Traps（细粒度陷入到 EL2）
if (arm_fgt_active(env, el)) {
    trapword = env->cp15.fgt_exec/read/write[idx];
    if (extract64(trapword, bitpos, 1) != rev)
        res = CP_ACCESS_TRAP_EL2;
}
```

**访问结果处理：**
| 结果 | 行为 |
|------|------|
| `CP_ACCESS_OK` | 正常访问 |
| `CP_ACCESS_TRAP_EL1` | 陷入到 EL1（UDEF） |
| `CP_ACCESS_TRAP_EL2` | 陷入到 EL2（HYP_TRAP） |
| `CP_ACCESS_TRAP_EL3` | 陷入到 EL3 |
| `CP_ACCESS_UNDEFINED` | UNDEF 异常 |

**EL 对系统寄存器访问的影响：**
- EL0 不能访问 EL1 及以上的系统寄存器（除非 PMUSERENR 等明确允许）
- EL1 不能访问 EL2/EL3 寄存器（尝试访问 → UNDEF）
- EL2 可以陷入 EL1 的寄存器访问（通过 HSTR_EL2、HCR、FGT）
- EL3 可以陷入任何低 EL 的寄存器访问（通过 MDCR_EL3.TPM 等）

#### 5.4.3 SMC（→ EL3）

```c
// op_helper.c:1111-1200 — HELPER(pre_smc)
// 路由决策树:
// 1. !EL3 && !HCR_NV && !PSCI_SMC → UNDEF
// 2. EL1 && HCR_TSC → 陷入 EL2（优先级最高）
// 3. !PSCI && (SMD || !EL3) → UNDEF
// 4. 其余 → 到达 EL3（异常处理阶段完成）
```

#### 5.4.4 WFI / WFE

```c
// translate-a64.c:2030-2048
// WFI/WFE 在翻译阶段标记为 DISAS_WFI/DISAS_WFE
// 实际陷入由运行时决定:
// - SCTLR_ELx.nTWI = 0 → EL0 的 WFI 陷入 EL1
// - HCR_EL2.TWI = 1    → EL0/EL1 的 WFI 陷入 EL2
// - SCR_EL3.TWI = 1    → EL0/EL1/EL2 的 WFI 陷入 EL3
// WFE 类似（nTWE/TWE 位）
```

### 5.5 内存访问权限

#### 5.5.1 PAN（特权访问永不）

当 PSTATE.PAN=1 时，EL1/EL2 的特权加载/存储指令不能访问用户页面：
```c
// hflags.c:345-368 — UNPRIV 计算
// LDTR/STTR（非特权加载存储）在 PAN 模式下使用 EL0 权限
if (!(env->pstate & PSTATE_UAO)) {
    switch (mmu_idx) {
    case ARMMMUIdx_E10_1:
    case ARMMMUIdx_E10_1_PAN:
        DP_TBFLAG_A64(flags, UNPRIV, 1);  // LDTR 使用 EL0 权限
        break;
    }
}
```

#### 5.5.2 UAO（用户访问覆盖）

当 PSTATE.UAO=1 时，LDTR/STTR 在 EL1/EL2 使用特权权限（而非 EL0 权限），有效地"覆盖"了 PAN 对这些指令的影响。

#### 5.5.3 页表权限与 EL

页表描述符中的 AP[2:1] 位根据当前 EL 确定读写权限：
| AP[2:1] | EL0 | EL1+ |
|---------|-----|------|
| 00 | 无访问 | 读写 |
| 01 | 读写 | 读写 |
| 10 | 无访问 | 只读 |
| 11 | 只读 | 只读 |

### 5.6 中断路由与屏蔽

```c
// cpu-irq.c:15-168 — arm_excp_unmasked()

// 规则 1: 中断不能路由到比当前 EL 更低的 EL
if (cur_el > target_el) return false;

// 规则 2: 路由到更高 EL（且非 EL1）的中断通常不可屏蔽
if (target_el > cur_el && target_el != 1) {
    if (target_el == 3)
        unmasked = true;   // 到 EL3 的中断永远不可屏蔽
    if (target_el == 2 && !(E2H && TGE))
        unmasked = true;   // 到 EL2 的中断不可屏蔽（非 VHE host）
}

// 规则 3: 同 EL 或 EL1 目标的中断受 PSTATE.DAIF 屏蔽
pstate_unmasked = !(env->daif & PSTATE_I);  // IRQ
pstate_unmasked = !(env->daif & PSTATE_F);  // FIQ
```

**中断路由配置（cpu-irq.c:171-260）：**
```c
// 物理中断路由:
// arm_phys_excp_target_el() 根据 SCR_EL3/HCR_EL2 确定 target_el
//   IRQ: SCR.IRQ→EL3, HCR.IMO→EL2, otherwise→EL1
//   FIQ: SCR.FIQ→EL3, HCR.FMO→EL2, otherwise→EL1

// 虚拟中断（VIRQ/VFIQ/VSerr）:
//   总是 target_el = 1（虚拟中断只能注入到 EL0/EL1）
//   需要 HCR.IMO/FMO/AMO = 1 才生效
//   HCR.TGE = 1 时虚拟中断被禁止
```

**NMI 处理（FEAT_NMI，cpu-irq.c:34-57）：**
```c
if (aa64_nmi && SCTLR.NMI && cur_el == target_el) {
    allIntMask = PSTATE.ALLINT ||
                 (SCTLR.SPINTMASK && PSTATE.SP);
}
// NMI 仅受 ALLINT 屏蔽，不受 PSTATE.I/F 影响
```

## 6. HVC / SMC 调用机制

### 6.1 HVC（EL1 → EL2）

```
执行流程:
  EL1 执行 HVC #imm16
    → trans_HVC() 翻译为 gen_exception_insn_el(EXCP_HVC, target_el)
    → arm_cpu_do_interrupt_aarch64()
       - target_el = 2
       - addr = VBAR_EL2 + 0x400 + 0x000 (同步,低EL AArch64)
       - ESR_EL2 = syn_aa64_hvc(imm16)  [EC=0x16]
       - SPSR_EL2 = old_PSTATE
       - ELR_EL2 = PC of HVC insn
    → 跳转到 EL2 异常向量
```

### 6.2 SMC（→ EL3）

```
执行流程:
  EL1 执行 SMC #imm16
    → HELPER(pre_smc) 检查:
       - HCR.TSC=1? → raise_exception(EXCP_HYP_TRAP, 2)  [陷入EL2]
       - SMD=1 || !EL3? → raise_exception(EXCP_UDEF)
       - PSCI call? → 特殊处理
    → 通过检查后: arm_cpu_do_interrupt_aarch64()
       - target_el = 3
       - addr = VBAR_EL3 + 0x400 + 0x000
       - ESR_EL3 = syn_aa64_smc(imm16)  [EC=0x17]
       - SPSR_EL3 = old_PSTATE
       - ELR_EL3 = PC of SMC + 4  (注: SMC 返回地址是下一条指令)
    → 跳转到 EL3 异常向量
```

## 8. EL 转换的完整状态机

```
                    ┌───────────────────────────────────┐
                    │            EL3 (Secure Monitor)   │
                    │  VBAR_EL3, SCTLR_EL3, TTBR0_EL3 │
                    └──────────┬────────────────────────┘
                               │ SMC / FIQ(SCR.FIQ)
                               │ ERET
                    ┌──────────▼────────────────────────┐
                    │            EL2 (Hypervisor)       │
                    │  VBAR_EL2, HCR_EL2, TTBR0_EL2   │
                    │  VHE: TTBR0/1_EL2                │
                    └──────────┬────────────────────────┘
                               │ HVC / IRQ(HCR.IMO)
                               │ ERET
                    ┌──────────▼────────────────────────┐
                    │            EL1 (OS Kernel)        │
                    │  VBAR_EL1, SCTLR_EL1, TTBR0/1_EL1│
                    └──────────┬────────────────────────┘
                               │ SVC / Data Abort / etc
                               │ ERET
                    ┌──────────▼────────────────────────┐
                    │            EL0 (User App)         │
                    │  使用 EL1 体制的 TTBR0_EL1       │
                    │  受限的系统寄存器访问             │
                    └───────────────────────────────────┘
```

**EL 转换规则：**
1. 异常只能升 EL 或保持不变，不能降 EL
2. ERET 只能降 EL 或保持不变，不能升 EL
3. EL0 的异常最低到 EL1（除非 HCR.TGE 将其重定向到 EL2）
4. 可以从任何 EL 直接到 EL3（通过 SMC 或 SCR 路由的中断）

## 9. 各 EL 的执行环境对比

| 特性 | EL0 | EL1 | EL2 | EL3 |
|------|-----|-----|-----|-----|
| 翻译体制 | EL1&0 Stage1+2 | EL1&0 Stage1+2 | EL2 或 EL2&0 | EL3 (单Stage) |
| 系统寄存器 | 极少（CTR, TPIDR等） | EL1 级寄存器 | EL2 级寄存器 | 所有寄存器 |
| 特权指令 | 仅 SVC | SVC/HVC/DC/AT | HVC/SMC/TLBI | 全部 |
| 内存权限 | AP[2:1] 用户位 | AP[2:1] 特权位 | Stage-2 控制 | 独立体制 |
| 中断屏蔽 | PSTATE.DAIF（可能不可屏蔽） | PSTATE.DAIF | PSTATE.DAIF | PSTATE.DAIF（最高优先级） |
| 可被陷入 | → EL1 (SCTLR) | → EL2 (HCR/FGT) | → EL3 (SCR) | 不可陷入 |
| PAN 影响 | - | 不能访问 EL0 页 | 不能访问 EL0 页(VHE) | - |
| Stage-2 | 受控 | 受控 | 不受 Stage-2 | 不受 Stage-2 |

## 11. 典型 EL 切换场景分析

### 11.1 系统调用（EL0 → EL1 → EL0）

```
1. EL0 执行 SVC #imm
2. arm_cpu_do_interrupt_aarch64():
   - new_el = 1
   - addr = VBAR_EL1 + 0x400 (从低 EL AArch64)
   - 保存: SPSR_EL1=PSTATE, ELR_EL1=PC
   - 设置: PSTATE.DAIF=全屏蔽, M=EL1h, PAN 按配置
3. 跳转到内核 SVC handler
4. 内核处理完毕执行 ERET:
   - 读 SPSR_EL1, 提取 EL=0
   - pstate_write(SPSR_EL1) → 恢复用户 PSTATE
   - aarch64_restore_sp(0) → 使用 SP_EL0
   - PC = ELR_EL1 → 返回用户代码
```

### 11.2 虚拟机退出（EL1 → EL2 → EL1）

```
1. Guest EL1 访问被陷入的寄存器(如 HCR 配置的陷入)
2. access_check_cp_reg() 返回 CP_ACCESS_TRAP_EL2
3. raise_exception(EXCP_HYP_TRAP, syndrome, target_el=2)
4. arm_cpu_do_interrupt_aarch64():
   - new_el = 2
   - addr = VBAR_EL2 + 0x400
   - 保存: SPSR_EL2, ELR_EL2, ESR_EL2
5. Hypervisor 处理完毕执行 ERET:
   - 恢复 Guest EL1 状态
   - PC = ELR_EL2 (可能是下一条指令或重试)
```

### 11.3 安全监控调用（EL1 → EL3 → EL1）

```
1. NS EL1 执行 SMC #0
2. HELPER(pre_smc):
   - 检查 HCR.TSC (如果=1, 陷入 EL2 而非继续到 EL3)
   - 检查 SCR.SMD (如果=1 且非 PSCI, UNDEF)
3. arm_cpu_do_interrupt_aarch64():
   - new_el = 3
   - addr = VBAR_EL3 + 0x400
   - ESR_EL3 = syn_aa64_smc(0) [EC=0x17]
4. Secure Monitor 处理, 可能切换安全状态:
   - 修改 SCR_EL3.NS 位
   - ERET 回到目标世界
```

## 13. 总结

QEMU 的 ARM64 EL 状态管理核心机制：

1. **状态表示**：`pstate[3:2]` 直接编码当前 EL，`aarch64` 标记执行状态
2. **异常进入**：确定目标 EL → 计算向量地址 → 保存状态 → 修改 PSTATE → 重建 hflags → 跳转
3. **异常返回**：从 SPSR 提取目标 EL → 验证合法性 → 恢复状态 → 重建 hflags → 跳转
4. **执行差异**：通过 MMU 索引、TB flags、访问检查、陷入配置实现各 EL 独立的执行环境
5. **副作用管理**：EL 变化钩子确保 PMU、Timer、SVE 等子系统感知 EL 切换
